# Excel 内嵌图片题库导入专项设计

> 2026-11-06 · 已确认设计 v2，取代第一版方案“填写图片引用列”的建议。已完成本机POI解析器/持久化预览/原子确认与50题76图片文件实测，未部署。[实际实现与兼容边界](choice-question-images-development-verification-20261106.md)。
> 2026-11-09 · v3 本机追加：在原文字列右侧新增7个图片专用列，旧模板继续兼容；图片专用列按左上角锚点所在列归属并检查跨题行。该改动未发布，正式1.30.82仍为v2实现。
> 以下保留设计阶段的研究依据与方案；真实教师Excel/WPS多版本文件仍待验证，生成样本通过不等于所有图片格式都已兼容。

## 1. 教师操作与支持承诺

**目标路径：上传一个 Excel → 系统识别文字与图片并显示预览 → 确认导入。** 无异常时只需选择一次文件和确认一次。50 道题可以作为一个批次处理，不要求逐张传图、填图片地址/ID/图注，也不额外上传图片包。后台读表与上传图片自动完成，不增加人工“开始识别”按钮。

保留原模板的题目类型、题目内容、年级、学期、第几课、选项A/B/C/D、标准答案、解析、公开等列名和顺序；不要求用户改成只有六列的新表。允许受控别名“题干/A/B/C/D/答案”，映射后仍以原字段为准，同一语义两列同时出现须提示选择，不按列序号猜。v2曾计划只优化列宽/行高、不新增图片技术列；v3已改为在原列右侧新增7个图片专用列，旧模板继续兼容。

### 1.1 v3 图片专用列决策

原文字列继续保存题型、题干、选项文字、答案、解析等信息；右侧新增 `题干图片1`、`题干图片2`、`题干图片3`、`选项A图片`、`选项B图片`、`选项C图片`、`选项D图片`。图片放进对应列后，不再占用题干/选项文字格，避免插入图片把文字顶掉。

归属规则：图片专用列只看图片左上角锚点落在哪一列，再检查图片垂直方向是否主要落在本题行内。跨到下一题行、合并数据行或无法判断时不自动猜，进入“待确认图片”，由教师在预览中选择题目和槽位。旧模板没有这些列时，仍按原文字格和浮动图覆盖面积识别；新导出统一写回图片专用列，保证导出再导入不丢图。

题干和选项的文字与图片分别读取再合并，同格可文字+图片；题干最多3张、每选项1张为首期建议。纯图片选项直接有效。题干全是图片时也应接收：系统按稳定规则生成“图片选择题”检索摘要，界面可显示题号/缩略图，**不强迫教师补标题或图注**，摘要不进入评分。原纯文字文件及既有A/B必填、C/D可选的导入习惯保持；正确答案所指选项必须有内容。

必须区分：

- 常见 Excel/WPS 浮动图片，文件内含真实图像且锚点明确：首期重点支持自动识别。
- 跨格、合并、组合对象或图片位置模糊：能提取则保留到待分配区，预览中点选归属；不能静默丢弃或给高置信度假象。
- WPS单元格内图、DISPIMG、Microsoft新式单元格内图：**列入首期格式检测与样本验证**，不能声称现有POI 4.1.2天然全支持。能可靠解包关联的格式才宣布自动支持，否则给原位补图/点选图片方式；不阻止其余49题保留在预览中。
- 网络IMAGE公式、链接图片：不能把一个URL当内嵌图片，不服务器抓外网。定位到具体行列，允许粘贴本地截图替换。

上述差异来自真实存储格式，不是给教师增加配置项。实际 Excel/WPS 版本样本是正式开发的第一道门禁。

## 3. 图片定位与图文合并算法

### 3.1 先建立表格语义，再读取图片实例

1. 校验扩展名/文件签名、加密/宏/外链特征、大小、压缩包限制。只开放 `.xlsx/.xls`，不启用宏，不执行公式。
2. 从实际工作表读表头，识别业务列和数据行；保存原sheet、原Excel行号、列号，不能过滤空行后重新编号。
3. 不用getAllPictures()的顺序推断位置。按sheet关系遍历每一个**图片出现实例**，保存drawing/shape标识、关系目标、锚点类型、from/to/偏移、可见裁剪/旋转/翻转属性和原始图字节索引。
4. 文字单独读取：字符串/数值按模板约定转文字，显示格式需DataFormatter验证；保存多行与原有中文，不执行用户公式。IMAGE/DISPIMG等图片公式先专门识别，不能作为普通题干显示或评分内容；其他公式默认提示改为值/在线修正，不依赖有可能过时的缓存值推断正确性。
5. 用规范化 `RowDraft` 合并文字+图片；题干全图也不跳行。其他题型沿原规则校验，选择题媒体只在本期适配；不可因导入器升级为判断/打字等偷偷加入新的含图业务。

### 3.2 归属依据与异常处理

| 情况 | 建议算法 | 教师看到什么 |
| --- | --- | --- |
| twoCell/oneCell普通浮动图片 | 读实际client anchor/底层CT锚点；按sheet列宽、行高、offset算显示矩形和相交业务格 | 明确落一格则自动归属，正常预览 |
| 调整大小但仍在同格 | 原图字节保持，显示大小只用于定位；不按显示缩小重采样保存 | 图片仍可放大看原清晰度 |
| 图片越过格线一点 | 结合左上锚点与主要可见面积。首轮建议主要格覆盖≥85%、且与次候选差距足够时才自动认定；阈值需样本校准，属建议不是实测值 | 无歧义自动；其余标“请确认图片位置”，不显示技术置信度 |
| 跨题行或跨选项列 | 不强制按左上角猜，不把一图复制到多个答案项；保留候选格与原表局部示意 | 点原图→选择“第12题/选项D”，一次修正 |
| 合并单元格 | 顶部说明/表头与数据区分开。若合并跨不同题目行或不同业务列，视为归属歧义；不把一题复制成多题，也不填充到所有行 | 在线指定题/字段；大量歧义可建议调整行高后重新保存，但不是唯一补救 |
| 同一格多张图 | 收集所有实例，按显示y→x→drawing序稳定排序；题干可在预览拖动排序 | 展示1/2/3图，可重排/删除；超过上限明确定位 |
| 多个shape指同一个图片数据 | 每个实例分别定位，字节可按批次SHA256复用 | 不丢重复出现实例，也不重复复制同一文件 |
| 纯图片选项/题干无文本 | 以图实例使单元格/行“非空”，与文字合并后校验 | 预览完整图片，不显示“未配置” |
| 组合图形中的照片 | 如可用POI/底层XML可靠递归坐标变换则提取；组合矢量图/SmartArt不假装是普通位图 | 提示本题图暂不支持，可直接截图粘贴替换 |
| absoluteAnchor | 可利用绝对坐标与sheet几何反算候选，不把缺失row1默认成A1；字体/列宽异常需降级 | 能可靠定位则归属，不能则在线指派 |
| 裁剪/旋转/翻转图 | 必须保留教师可见内容，不能仅拿包内未裁剪原图直接展示（可能露出被裁掉的答案）。首期能安全生成派生PNG并核对时处理，否则标记并让截图替换 | 显示原表可见效果或明确异常，不悄悄改变题意 |
| 背景图/页眉页脚/隐藏sheet图片 | 不按题目图片导入；统计“未作为题目处理的图片”，出现题目区未归属图时阻止确认并要求核对 | 不凭全包图片数量自动生成题目 |

XSSF偏移以EMU等单位计，HSSF锚点偏移比例不同，不能共用同一数值公式。0基索引仅用于程序，用户错误显示1基Excel坐标，例如“题库 / 第13行 / 选项D”。几何归属只是确定性辅助，不引入AI/OCR出题。v3图片专用列不以面积或中心点猜列；只有旧模板同格浮动图继续使用主要覆盖面积比例。

### 3.3 新式单元格内图片和WPS

现有代码只确认绘图层提取，下面必须用真实版本文件验证后再公布兼容列表：

- WPS内嵌图常见DISPIMG/cellimages关系、Microsoft新式in-cell/richData等应检测包部件与引用。**这些只是候选格式特征，不是本轮已验证解析规则**，不能凭文件扩展名推断全部可用。
- 若文件中确有位图且能安全解析“单元格→图片关系”，可新增受限OPC/XML适配器，无需全量升级POI；使用现有安全XML能力、禁外部实体/外部关系，白名单解析结构。
- 若能提取位图但缺少可靠cell映射，将图放在本批“待放置图片”，教师点选题目/选项即可，后台不自动猜。
- 若连位图都不在文件里（外链/受保护对象），保留该行文字，显示具体问题，让教师在该行预览直接粘贴截图；无需重新制作50题Excel。
- 最简统一制表建议：“在对应格附近直接粘贴截图，图片左上角放在该格内，调整行高让图不要跨题；保存为xlsx。”优先引导普通浮动图片，不让教师处理解压包、公式编码或ID。只在遇到不兼容文件时展示这条帮助。

首期门禁样本：学校常用Excel版本/WPS版本分别验证浮动、粘贴截图、嵌入单元格、xlsx/xls、同格多图、跨格和裁剪。没有样本不能承诺某版本“100%支持”，但异常必须可见且可在线补救。

## 4. 预览、在线纠错与进度

### 4.1 页面状态

`未选择 → 上传中 → 识别中 → 待核对（正常/异常） → 确认中 → 完成`；失败是可重试状态，不把已识别题目清空。

- 上传进度取真实字节比例；解析阶段显示“正在读取第x张工作表/已检查y题/已处理z张图”，不知道总量时用阶段文字，不造百分比。
- 预览显示题号、原Excel位置、题干摘要、图片数、答案、状态；默认展开一道题显示完整图文。正常/待修正有文字标识和颜色，提供“只看待修正”。
- 点“修正”在旁边打开当前题，不叠多层弹窗。可改题干/选项文字、答案，重分配/排序/粘贴/删除图。图注/ID均不要求填。
- 未确认且不能判断归属的图片保留在待放置区；不可一键静默忽略。若用户明确删除无关装饰图，记录修正并重新校验。
- 只有所有拟导入行通过校验才允许整批确认。允许明确“本次不导入这题”，重新显示49/50题和排除原因；不默认偷偷跳过异常行。
- 每次修正递增batchRevision，局部重新校验后更新总数；确认提交revision，避免教师两窗口修正互相覆盖。
- 断网、刷新或返回后从同一批次恢复预览；批次过期告知“预览已过期，请重新选择文件”，不把预览当正式题库。

### 4.2 完成与回访

显示“已导入50题/其中含图x题”，主操作“查看本次题目”。服务端返回批次及新questionId列表，题库支持该批次结果筛选并高亮首题；关闭提示后仍能从最近导入记录重新进入。批次结果权限限本人/管理员，不把其他教师导入目录公开。

## 5. 建议后端契约与数据

下述全部为待实现设计，不是现有接口：

| 操作 | 契约 |
| --- | --- |
| `POST /business/question/import-batches` | 上传文件+clientRequestId，返回batchId及处理中/预览状态；同一请求重试不重复创建 |
| `GET /business/question/import-batches/{id}` | 返回状态、revision、数量、分页行摘要、错误及处理阶段，不返回磁盘路径/Token |
| `GET /business/question/import-batches/{id}/items/{itemId}` | 完整图文草稿与可修正问题；图片读取复用上传元数据但必须验证批次归属 |
| `PATCH /business/question/import-batches/{id}/items/{itemId}` | expectedRevision + 文本/图片位置调整，事务校验后返回新revision和统计 |
| `POST /business/question/import-batches/{id}/confirm` | expectedRevision + confirmRequestId，锁定批次、再校验全部行；事务插题、绑定图片、落结果后返回真实结果 |
| `GET /business/question/import-batches/{id}/result` | 恢复提交结果；网络丢响应时查这里，不再次导入 |

建议新增两张小型持久化表，避免只靠浏览器内存/Redis短TTL丢失50题预览：

- `biz_question_import_batch`：batchId、ownerId、fileSha256、clientRequestId、状态、revision、原始文件受控路径、数量/阶段、确认请求/内容摘要、开始/完成/过期时间、失败原因；唯一(ownerId,clientRequestId)。
- `biz_question_import_item`：itemId、batchId、sourceSheet/sourceRow/sourceKey、draftJson、validationJson、是否选入、resultQuestionId、顺序/审计时间；唯一(batchId,sourceKey)。一行一个题，不用“过滤后序号”做身份。
- `biz_question_image`、题库/抽测media_json沿增强A方案；原表单仍不见这些字段。图片归属记录包括本批暂存关系，草稿图不可只凭imageId被其他教师读到。

导入行draftJson包含文本、slot→图片ID、有序列表、原始定位证据；解析错误JSON仅服务端/管理日志需的部分不直接甩给教师。

建议状态：`PARSING/REVIEW/COMMITTING/COMMITTED/FAILED/EXPIRED`。小批次可以同请求解析，较大批次沿用已有受限线程池，仍持久化阶段并提供轮询；不引入新任务队列服务。进程中断后的PARSING可按同一文件和批次幂等重建预览，不能假定线程一定完成。

## 6. 原子性、防重复与文件治理

1. 上传文件与所有提取位图先保存在本功能独立目录，注册TEMP图片元数据，禁止未验证图片被公开访问；原图唯一命名、不可覆盖。
2. 校验完整类型/MIME/签名、实际宽高/像素/文件总量；记录SHA256。在同一批次按“原字节/安全变换版本”去重存储，保留每个引用实例；不跨教师全站去重导致权限混淆。
3. 解析完成只写草稿，不插正式题库。预览修正也只改草稿；异常不影响现有题库。
4. 确认时按固定锁顺序锁定batch、items、待绑定图片；复查revision、归属、图片存在/合法、全部业务字段，再调用可在同事务内执行的题库写入能力。
5. **插入全部题目、图片TEMP→RETAINED、每行resultQuestionId、批次COMMITTED及结果映射必须同一数据库事务。** 任一行失败全部回滚，不把半批“正常题”提交给教师。
6. 文件在确认前已经存到稳定不可变路径，确认只绑定记录，不把一半文件移动到正式目录造成跨文件系统事务。失败回滚后TEMP可继续修正，孤立文件由受控补偿清理。
7. 同confirmRequestId重复提交：已COMMITTED直接返回原结果；同键不同内容拒绝。两窗口同时确认只会产生一套题；响应超时通过result恢复，不再新建。
8. 同文件再次上传：同owner+同请求复用批次；新请求但相同fileSha可提示“该文件已导入，可查看本次题目”，确实要再次导入需明确动作。只做题干相同不够判重，不能自动吞掉教师有意复用的相似题。
9. 暂存清理只针对超期、未提交的本批文件和TEMP，扫描隔离目录，锁定复核再标记并提交后删文件；COMMITTED结果映射需长期或明确保留，不能随预览TTL一起删掉防重证据。已绑定原图不自动物理删除。

## 7. 异常、安全与建议容量

以下数值为开发起点，必须用样本与本机内存测量校准：

| 限制 | 建议值/处理 |
| --- | --- |
| 上传Excel | ≤50MiB，低于当前application单文件55MB与请求60MB；目标Nginx另查，不为本功能全局调大 |
| 单批题数/图片实例 | 最多200题、1000图片实例；50题在此范围内，不承诺无限文件 |
| 单图 | ≤5MiB、最大边8192、2000万像素；题干3张/每选项1张 |
| 解压/图片累计 | 显式解包部件和累计解压字节预算，例如128MiB；图片逐个校验，不一次把全部高清图解码进内存 |
| 解析并发 | 初期每教师1个活跃解析、全局2个受限任务，超出排队；数值结合现有主机负载确认 |
| 超时/失败 | 阶段超时可重试，草稿保留；异常文件/压缩炸弹在解析前或预算达到时停止，保留错误原因而不是部分正式题 |

文件包检查拒绝目录穿越、外部关系任意读取、宏执行、外部实体、加密或不支持结构；不因异常文件全局放宽POI的ZipSecureFile压缩比/安全设置。客户端可伪造扩展名和MIME，服务器仍需实际校验。读取图片尺寸应先用metadata判限，再决定是否解码，防止小压缩包解出巨量像素。

来源Excel的公式/HTML仅作为受控文字，不用v-html渲染。导出时对可能触发公式的文字使用安全的文本单元格；不能把教师题干送入图表HTML字符串而不转义。返回错误保留sheet/行/字段，但不返回SQL堆栈、服务器绝对路径或凭据。

50题×7图×5MiB会远超50MiB上限，因此回答“50题一次传”必须带“文件在体积/数量上限内”的条件，不能拿题目数量代替容量边界。默认不要求教师压缩图片包；普通截图可系统生成轻量展示副本，清晰原图保留。超过上限时显示文件实际大小和最简单的分批建议。

## 8. 导出与原模板兼容

首期导入是必做，**导出也不能丢图**：v3使用POI把图片写入对应的题干图片1-3、选项A-D图片专用列，文字保留原列，按题目内容调整行高，以同一套左上角锚点规则实现本站导出→再导入。避免新式in-cell格式作为唯一导出，以降低旧Excel/WPS差异。

复用现有POI，不直接套 `@Excel(IMAGE)` 替换原文字值；题库专用writer只读取已授权的本地图片，不取任意远程URL。每批导出总字节/行高/原图数量设限；缺图明确失败或说明不完整，不能产出看似完整的无图卷。原纯文字导出结构维持，操作题原过滤规则保持。

不要求教师操作ZIP包、图片ID或路径配置。可提供系统自动下载的错误清单，但在线修正是主要补救路径。

## 10. 官方资料与结论可信度

- [Apache POI 4.1 XSSFClientAnchor](https://poi.apache.org/apidocs/4.1/org/apache/poi/xssf/usermodel/XSSFClientAnchor.html)：说明fixed/one-cell/two-cell等锚定方式；本项目要按实际锚定处理，不能只看左上角。
- [Apache POI 4.1 XSSFPicture](https://poi.apache.org/apidocs/4.1/org/apache/poi/xssf/usermodel/XSSFPicture.html)：提供getClientAnchor/getPictureData；getPreferredSize是尺寸计算能力，非完整图片归属算法。
- [Microsoft：Excel单元格内图片](https://support.microsoft.com/en-gb/excel/insert-picture-in-cell-in-excel)：区分Place in Cell和Place over Cells，常规Ctrl+V粘贴为浮动于单元格之上的图。不同Excel版本/命令需样本验证。
- [Microsoft：IMAGE函数](https://support.microsoft.com/en-us/excel/functions/image-function)：基于来源地址的图片与文件内真实内嵌图应区分，不能当作可离线提取的同一种对象。
- [WPS：插入和设置图片](https://www.wps.com/academy/how-to-add-a-watermark/1861729/)：明确Floating Picture与Embed to Cell为不同方式；不据此推定二者的包格式都已被POI 4.1.2支持。

检索日期2026-11-06。官方资料确认格式/接口差异；项目实际兼容性、精确识别率、解析耗时和资源上限尚未实测，不给100%或精确工时承诺。
