# ADR-001：版本化课堂任务状态与事务后推送

- 状态：已接受，本地核心实现完成，数据库未迁移，未发布
- 日期：2026-09-03

## 背景

答案表只能可靠表达“已有答案/已有成绩”，不能表达学生已经打开题目、正在作答或被教师退回。旧实现直接在提交、批改接口中广播简单消息，既没有统一状态，也可能在数据库事务回滚前让页面先看到成功。

## 备选方案

1. 只推“刷新提示”，页面收到后重新查答案。改动小，但无法表达六种状态，也无法处理乱序消息。
2. 以 Redis 作为任务状态事实。实时性好，但重启/过期会丢失课堂过程状态，历史提交也难回填。
3. 以 MySQL 状态表作为权威事实，事务提交后通过现有课堂 WebSocket 推送版本事件，页面周期性 REST 校准。

## 决策

采用方案 3：

- `biz_student_task_state` 以 `lesson_id + question_id + student_id` 唯一，保存六态之一、`state_version` 和最后变化时间。
- 学生只允许上报本人当前课程题目的 `ENTERED/WORKING`；正式提交、批改、退回必须由对应服务端业务接口写入。
- 低阶段事件不得把 `WORKING/SUBMITTED/GRADED` 降级；`RETURNED` 后重新作答可进入 `WORKING`，再次提交进入 `SUBMITTED`。
- 状态属于答案/作品/批改主业务的展示旁路：主事务存在时，先在其 `afterCommit` 中启动独立状态事务；状态表失败只告警，不能使主业务回滚或向学生返回失败。状态事务提交后才广播；没有活动主事务时立即以独立事务写入。事件为 `TASK_STATE_UPDATE`，客户端按 `stateVersion` 丢弃旧消息。
- 保留旧课堂 WebSocket 三段路径，新增可显式携带 `lessonId` 的四段路径。学生只能订阅当前课程；教师订阅历史课程必须同时通过课程班级关系与教师管理范围校验。
- 推送只负责加速，REST 全班查询是校准事实；无状态行返回 `NOT_ENTERED`、版本 0。

## 后果

- 新后端依赖 `sql/student_task_state_v1.sql`，发布顺序必须是备份、执行迁移和后检，再切换后端；旧后端可忽略新增表。
- 状态表或推送失败不会回滚已提交的业务数据，页面可由周期校准恢复。
- 任务状态与学生终端 Presence 分离；该表不能用来判断在线或考勤。
- 当前只完成批改页和教师首页的校准接入；成绩页共享 store 与学生桌面仍需后续实施。

## 验证与回滚

- 自动测试覆盖状态流转、低阶段防降级、状态写入器广播、跨班/历史课程 WebSocket 授权；`mvn -pl ruoyi-business -am test` 生成的 94 份 Surefire 报告均无失败或错误标记。真实库验证仍待完成。
- 发布前仍需执行迁移前检/后检、本机真实库接口验证和教师/学生浏览器冒烟。
- 应用回滚时先切回旧版本；新增表可兼容保留。确认没有新版本依赖后，才可按 `sql/student_task_state_v1_rollback.sql` 删除表。
