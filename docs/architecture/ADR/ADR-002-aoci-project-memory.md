# ADR-002：本机AOCI项目记忆与当前事实分工

- 日期：2026-10-06（首次决策2026-10-05）
- 状态：用户已授权；本机安装及MCP接入通过，代码索引建立中，十二批累计237条正式写入，尚未全仓对齐。

## 背景与备选方案

### 2026-10-07 决策更新：日常任务不自动进入 AOCI

用户反馈生成近期功能自查提示词时，完整索引分块读取耗时过长，要求减少每次任务等待。现场核对 `aoci_rules`：当前合同确实要求新 Run 完整 Overview，分块参数只影响传输大小，不能免除全量读取。本次采用项目层面的按需启用：日常任务先读核心资料、相关 Git 改动和源码；只有明确的 AOCI 专项任务进入完整合同。详细边界以 `AGENTS.md` 的“AOCI 调用策略”为准。

保留工具、索引、Baseline 和原托管区块，不修改引擎、不宣称已支持轻量 API。日常任务不自动补齐或维护索引，代价是索引可能滞后，必须以当前源码为准并在必要时注明未同步；正式索引维护仍遵守工具安全与验证规则。此次仅修改项目使用规则及说明，无业务 SQL、部署或重启要求，也不产生产品更新版本。文档核对不能代替新会话效果验证；下一次日常任务应确认不再自动调用全量 Overview。回退时仅撤销此次调用策略及配套说明，保留既有业务修改和索引资产。

项目已有AGENTS、核心上下文、架构和专题资料，但核心文档已累积大量发布历史。只整理文档成本低、没有自动索引漂移检测；直接全仓接入可能把历史、生成文件和私密配置纳入范围；先整理再配置受管范围，便于保持业务事实和索引一致。

## 决策

按用户要求先完整归档旧文档，压缩核心事实和架构入口，再安装官方AOCI-CODE并接入当前项目Codex。保留同日其他开发任务的新事实和全部既有业务修改。

AOCI只辅助文件职责、接口和关系定位，不改变平台架构、认证或部署。现有操作规范和用户授权继续优先；核心上下文管理已验证当前状态，历史记录按需追溯。初次不安装Hooks、不连接数据库、不新增模型端点；在受管范围中排除旧Vue2、业务上传、私密配置、产物和历史归档。

## 后果与验证

安装会增加本机二进制、项目MCP配置、AGENTS托管区块、索引骨架与状态；首次语义生成和日常维护消耗现有宿主模型额度。已安装不等于已生成完整索引，aligned不等于业务正确。

文档归档逐字节验证、包校验、版本、扫描、协议、分卷创作与恢复证据统一记录在 [AOCI_CODE.md](../AOCI_CODE.md)。本次恢复时199条概览交付已验证、Challenge 10/10且严格认知校验通过，但治理未对齐；第十二批成功后仍有1692项待处理，不能称完整全仓索引、完整系统认知可靠或治理aligned。本轮不生成产品更新版本，不需业务SQL或重启。

## 回退影响

可移除本轮新增工具条目和托管资产；按差异恢复规则及配置，保留其他会话写入，不回灌业务数据库、不回退平台功能。
