## 一、背景与目标

VForm3 是第三方可视化表单设计器，内置了一批字段（单选、多选、输入框等）。当业务需要非内置控件时，需制作「类原生」自定义组件，使其：

1. 出现在设计器左侧「自定义扩展字段」面板，可拖拽/双击添加；
2. 被选中时高亮，支持上移/下移/删除等原生操作；
3. 属性面板能渲染该组件的属性编辑器；
4. 运行时（学生端）能正常渲染并回填数据。

「类原生」即尽量复用 VForm3 内部约定（type 映射、props 注入、样式 class），避免重造轮子。

## 二、核心机制原理

### 2.1 type 命名约定

VForm3 通过 `type` 字段解析组件名：

```
type: 'image-add' → 组件名 image-add-widget
```

惯例：`getWidgetName(type) = type + '-widget'`。因此 `type` 为 `image-add` 的自定义组件，须全局注册为 `image-add-widget`。

### 2.2 面板渲染机制（关键）

VForm3 的 FieldPanel（左侧面板）在 `created()` 生命周期通过**模块级 `customFields` 闭包数组**一次性构建面板列表：

```js
// designer.umd.js（预构建包，模块内部闭包）
customFields = []                    // 模块级数组
function addCustomWidgetSchema(i) { customFields.push(i) }   // 闭包私有，未导出

// FieldPanel created() → loadWidgets()
this.customFields = customFields.map(i => enrich(i)).filter(...)
```

**后果**：`addCustomWidgetSchema` 和模块级 `customFields` 都是 UMD 闭包私有变量/函数，外部无法访问。所以无法在组件挂载后往模块级数组里 push，只能通过运行时补丁 FieldPanel 实例的 `loadWidgets()` 来注入（见第五节）。

### 2.3 渲染列表的响应性

左侧面板用 vuedraggable 渲染，其 `list` 绑定 `customFields`。要让它对新注入的组件产生响应，必须**产生新的数组引用**（整体重建），单纯 `push` 到旧数组或对已有数组重新赋值都不会被 vuedraggable 感知。

## 三、开发组件本体

组件本体是「类原生」的关键，参考 `src/components/ImageAddWidget/index.vue`。

### 3.1 接收的 props（VForm3 注入）

VForm3 设计器渲染自定义字段时，会注入以下 props：

```javascript
const props = defineProps({
  field: { type: Object, default: () => ({}) },     // 当前字段的完整定义（含 options）
  designer: { type: Object, default: null },        // 设计器实例（仅设计态存在）
  parentList: { type: Array, default: null },       // 父级 widgetList 数组
  indexOfParentList: { type: Number, default: -1 }, // 在父级数组中的索引
  parentWidget: { type: Object, default: null },    // 父级 widget 对象
  designState: { type: Boolean, default: false },   // 是否设计态
  subFormRowIndex: { type: Number, default: -1 },   // 子表单相关（可忽略）
  subFormColIndex: { type: Number, default: -1 },
  subFormRowId: { type: String, default: '' }
})
```

### 3.2 设计态 / 运行态 / 选中态判断

```javascript
// 设计态：有 designer 或 designState 为 true
const isDesignMode = computed(() => !!(props.designState || props.designer))

// 选中态：设计器中当前选中字段 id 等于 field.id
const isSelected = computed(() =>
  !!(props.designer && props.field && props.field.id === props.designer.selectedId)
)
```

### 3.3 原生操作（选中 / 移动 / 删除）

复用 designer 实例提供的方法：

```javascript
function selectField() {
  props.designer?.setSelected(props.field)          // 选中当前
  props.designer?.emitEvent('field-selected', props.parentWidget)
}
function selectParentWidget() {
  props.parentWidget
    ? props.designer?.setSelected(props.parentWidget)
    : props.designer?.clearSelected()
}
function moveUpWidget() {
  if (props.designer && props.parentList && props.indexOfParentList > 0) {
    props.designer.moveUpWidget(props.parentList, props.indexOfParentList)
    props.designer.emitHistoryChange()              // 记录历史，支持撤销
  }
}
function removeFieldWidget() {
  // splice 移除自身，并处理选中态切换
  props.parentList?.splice(props.indexOfParentList, 1)
  props.designer?.emitHistoryChange()
}
```

### 3.4 读写 field.options（业务配置）

组件配置统一存在 `field.options` 中，通过 computed getter/setter 读写，并在赋值时做范围约束：

```javascript
const imageUrl = computed({
  get: () => props.field.options?.imageUrl || '',
  set: v => { (props.field.options || (props.field.options = {})).imageUrl = v }
})
const imageWidth = computed({
  get: () => props.field.options?.imageWidth || 200,
  set: v => { props.field.options.imageWidth = Math.max(30, Math.min(2000, v)) }
})
```

### 3.5 样式对齐原生

复用 VForm3 原生字段的 class 约定，保证观感一致：

- 外层包裹 `field-wrapper`（position: relative + margin-bottom）
- 选中态加 `image-selected` 或直接 `outline: 2px solid #409eff`
- 操作按钮栏 `.field-action`（底部蓝色背景，含上移/下移/删除图标）
- 拖拽手柄 `.drag-handler`（顶部蓝色背景）

## 四、全局注册

组件本体 + 全局注册（`src/main.js`）：

```javascript
import ImageAddWidget from '@/components/ImageAddWidget/index.vue'

app.component('image-add-widget', ImageAddWidget)   // 名称 = type + '-widget'
app.use(VForm3)                                     // 注册 v-form-designer 等
```

> 组件名必须严格等于 `type + '-widget'`，否则 VForm3 无法按 type 解析到组件。

## 五、注入设计器面板

这是让组件出现在左侧面板的核心步骤。在 `designer.vue` 中完成。

### 5.1 定义 widget schema

```javascript
const IMAGE_ADD_WIDGET_SCHEMA = {
  type: 'image-add',
  icon: 'picture-upload-field',      // 面板图标（VForm3 内置图标名）
  formItemFlag: true,
  options: {
    name: '', label: '图片展示',
    labelAlign: '', defaultValue: null,
    columnWidth: '200px', size: '', labelWidth: null,
    labelHidden: false, disabled: false, hidden: false,
    required: false, requiredHint: '', validation: '', validationHint: '',
    imageWidth: 200, imageHeight: 200, imageUrl: '',
    customClass: '', onCreated: '', onMounted: '', onChange: '', onValidate: ''
  }
}
```

### 5.2 定位当前可见的 FieldPanel 实例（作用域限定）

```javascript
function findFieldPanelInstanceByDom() {
  // 优先在当前可见的 VForm3 设计器根节点 $el 内查找，避免命中 keep-alive/HMR 遗留陈旧实例
  const scopeRoot = (designerRef.value && designerRef.value.$el) || document
  const el = scopeRoot.querySelector('.panel-container')
    || scopeRoot.querySelector('.field-widget-item')
    || scopeRoot.querySelector('.widget-panel')
  if (!el) return null
  let inst = el.__vueParentComponent
  let depth = 0
  while (inst && depth < 40) {
    const name = inst.type && (inst.type.name || inst.type.__name)
    if (name === 'FieldPanel' || name === 'WidgetPanel' || name === 'widget-panel') {
      return inst
    }
    inst = inst.parent
    depth++
  }
  return null
}
```

### 5.3 补丁 loadWidgets + 注入（核心）

```javascript
function injectImageAddIntoArray(arr) {
  if (!Array.isArray(arr)) return false
  if (arr.some(f => f.type === 'image-add')) return false
  arr.push({ key: 'image_add', ...IMAGE_ADD_WIDGET_SCHEMA, displayName: '图片展示' })
  return true
}

function registerCustomImageWidget() {
  const fieldPanel = findFieldPanelInstanceByDom()
  if (!fieldPanel) return
  const proxy = fieldPanel.proxy

  // 1) 显示文字补丁（见第六节）
  // 2) 属性面板补丁（见第六节）

  // 3) 核心：补丁 loadWidgets，让每次重建都追加自定义字段
  if (!fieldPanel._imageAddLoadPatched) {
    fieldPanel._imageAddLoadPatched = true
    const origLoadWidgets = proxy.loadWidgets
    proxy.loadWidgets = function() {
      if (typeof origLoadWidgets === 'function') origLoadWidgets()
      injectImageAddIntoArray(this.customFields)
    }
  }

  // 4) 若尚未进入渲染列表，触发一次重建 + 强制重渲染
  if (!Array.isArray(proxy.customFields) || !proxy.customFields.some(f => f.type === 'image-add')) {
    if (typeof proxy.loadWidgets === 'function') proxy.loadWidgets()
    else injectImageAddIntoArray(proxy.customFields)
    nextTick(() => { proxy.$forceUpdate?.() })
  }
}
```

**为什么这样写**：
- 模块级 `customFields` 闭包无法访问，只能补丁实例方法 `loadWidgets()`。
- 原始 `loadWidgets()` 会整体重赋 `this.customFields`（产生新数组引用）→ 追加字段后触发 vuedraggable 重渲染。
- 用 `_imageAddLoadPatched` 标记防止重复补丁；用 `some(f => f.type === ...)` 保证幂等，避免每秒轮询重复刷新。

### 5.4 注册时机（多层保障）

```javascript
onMounted(() => {
  nextTick(startDomObserver)           // MutationObserver 监听 .panel-container 出现
  // ...
  pollingTimer = setInterval(() => {   // 1 秒兜底轮询
    processFormState()
    registerCustomImageWidget()
  }, 1000)
})

onActivated(() => {
  nextTick(() => registerCustomImageWidget())  // keep-alive 激活后重新注册
})
```

## 六、属性面板与显示文字

### 6.1 显示文字（i18n2t 补丁）

左侧面板每个 item 的可视文字由渲染期 `i18n2t('designer.widgetLabel.${type}')` 生成。自定义 type 不在内置 locale 中，会返回空，必须补丁 `proxy.i18n2t`（Vue3 render 通过 proxy 取方法）：

```javascript
if (!fieldPanel._i18nPatched) {
  fieldPanel._i18nPatched = true
  const originalI18n2t = proxy.i18n2t
  proxy.i18n2t = function(d, e) {
    if (d === 'designer.widgetLabel.image-add') return '图片展示'
    return originalI18n2t.call(this, d, e)
  }
}
```

### 6.2 属性面板（getFieldWidgetByType 补丁）

VForm3 的 `hasConfig → getFieldWidgetByType` 需在数组中找到 widget schema，否则属性面板无法渲染编辑器。补丁 designer 实例：

```javascript
const designer = fieldPanel.props.designer
if (designer && designer.getFieldWidgetByType && !designer._imageAddPatched) {
  designer._imageAddPatched = true
  const original = designer.getFieldWidgetByType
  designer.getFieldWidgetByType = function(type) {
    if (type === 'image-add') {
      return { key: 'image_add', ...IMAGE_ADD_WIDGET_SCHEMA, displayName: '图片展示' }
    }
    return original.call(this, type)
  }
}
```

## 七、完整实现流程汇总

1. **写组件本体**：新建 `src/components/XxxWidget/index.vue`，接收 field/designer/parentList 等 props，实现设计/运行态、选中态、原生操作、field.options 读写。
2. **全局注册**：`main.js` 中 `app.component('xxx-widget', XxxWidget)`（名称 = type + '-widget'）。
3. **定义 schema**：在 designer.vue 中定义 `XXX_WIDGET_SCHEMA`（type、icon、formItemFlag、options）。
4. **定位 FieldPanel**：`findFieldPanelInstanceByDom()` 作用域限定在当前设计器 `$el`。
5. **注入面板**：补丁 `loadWidgets()` 追加字段并触发重建。
6. **补丁 i18n2t**：使面板显示自定义字段中文名。
7. **补丁 getFieldWidgetByType**：使属性面板可渲染编辑器。
8. **注册时机**：onMounted + MutationObserver + 1 秒轮询 + onActivated 多层保障。
9. **验证**：硬刷新设计页（Ctrl+Shift+R），确认左侧「自定义扩展字段」出现组件，可添加、选中、删除、配置属性。

## 八、注意事项与常见坑

| 坑 | 原因 | 对策 |
|----|------|------|
| 面板不显示组件 | FieldPanel 用模块级 customFields 闭包一次性构建，addCustomWidgetSchema 未导出 | 补丁实例 loadWidgets() 注入 |
| 数据注入了但仍不渲染 | vuedraggable 不响应旧数组 push/重赋值 | 产生新数组引用（整体重赋）+ $forceUpdate |
| 命中陈旧实例 | keep-alive/HMR 遗留多个 FieldPanel | 通过 designerRef.$el 作用域限定 DOM 查询 |
| 面板文字为空 | i18n2t 无自定义 type 的 locale | 补丁 proxy.i18n2t |
| 属性面板空白 | getFieldWidgetByType 找不到 schema | 补丁 designer.getFieldWidgetByType |
| 组件名不匹配 | type 与组件注册名不一致 | 组件名 = type + '-widget' |
| 选中/操作失效 | 未调用 designer API | 用 setSelected/moveUpWidget/emitHistoryChange |
| 配置丢失 | 自定义属性未写入 field.options | 业务配置都存 field.options |
| 重复注入/重复刷新 | 轮询每次触发 | 用标记位 + some() 幂等判断 |
