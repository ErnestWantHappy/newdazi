# Python 刷题功能实施提示词

> 状态：**历史实施提示词，已过时**。Python 刷题已完成开发、正式迁移与发布；当前准确状态见 `contexts/PROJECT_CORE.md`。
> 使用时机：仅用于追溯原始实施约束。后续 AI 不得按本文判断功能未开发，也不应把它作为默认入口；若需继续该专题，先读 `AGENTS.md`、`contexts/PROJECT_CORE.md` 和本专题最新任务文档。

## 角色与目标

你是本项目的高级全栈开发代理。请在现有 RuoYi-Vue3 + Spring Boot/RuoYi + MySQL + Judge0 CE 项目中，新增一个简化版 OJ 风格的 Python 刷题功能。目标用户是小学高年级、初中阶段的 Python 零基础学生；目标不是建设复杂竞赛 OJ，而是提供教师可配置、学生可持续练习、教师可查看学情的教学训练工具。

本功能暂不开发课程设计器改造，不把刷题成绩写入课程总分，不改变当前课程内 Python 操作题的既有行为。

## 已确定的产品边界

1. 教师端只增加一个一级菜单：`Python 刷题`。
2. 该菜单首屏复用教师首页的工作流：`年级分组 → 年级 Python 练习卡 → 配置题目或查看班级`。教师不需要先填写复杂筛选条件，也不需要先进入报表页。
3. 不再把“年级题单、学情分析、题库”并排做成首屏页签或独立一级菜单。题单配置从年级练习卡的“配置题目”进入；班级学情从“查看班级情况”进入；Python 题库仅在配置题目时作为选择工具打开。
4. 学生端顶部导航增加一个入口：`Python 练习`；点击进入独立刷题页。
5. 刷题是课程外的长期练习，学生练习记录和课程作答记录分开保存；不影响课程总分、课程推进和课程成绩。
6. 复用现有 Python 题目、测试点、CodeMirror 6 编辑器、Judge0 判题客户端、异步判题、取消、轮询和脱敏规则，不复制一套判题引擎。
7. 默认提供系统题单模板，第一批 80 道题由项目方导入；教师可以复制模板后为年级配置题单。
8. 同一个学校、学期、年级使用一套当前发布的“年级基础题单”，它对该年级全部班级生效；班级既是统计维度，也可通过“班级加练包”获得追加练习。完整版本、题目快照和重复题规则以总架构提示词为准。
9. 加练包可选择一个或多个班级，支持不同班级使用不同加练包；加练只能追加题目，不能替换、删除或隐藏年级基础题。
10. 学生一次只练习一道题，可以自由选择题目；支持未完成、已完成、错题筛选和题目切换。
11. 每题通过得 100 分，记录最高得分、是否通过、提交次数、首次通过时间和最近练习时间；刷题分数不进入课程成绩。

## 推荐的简化 OJ 体验

### 教师端统一工作台

首屏按教师首页既有方式显示当前年级与历史年级。每个年级只显示一张“Python 练习”卡片，卡片明确告诉教师：是否已发布、覆盖几个班、题目数、本周练习人数、完成率和一个最需要关注的薄弱知识点。每张卡最多提供两个主操作：`配置题目`、`查看班级情况`。

### 配置题目（由年级练习卡进入）

- 年级和学期从被点击的练习卡自动带入。
- 新手教师先看到“使用系统推荐题单”作为默认推荐，推荐题单按输出、输入、条件、循环等阶段组织；可直接发布，也可点击“调整题目”。
- 调整题目时才打开题库选择抽屉，支持选择、取消选择、顺序调整以及按知识点筛选。
- 支持保存草稿、发布、撤回、复制上一版；发布前清晰显示题目数量和覆盖知识点。
- 在基础题配置下方提供“为部分班级加练”。加练页先选择一个或多个班级，再选题并发布；页面必须提示“基础题仍对全年级生效，加练只追加”。
- 第一阶段不设置复杂截止时间，不引入训练单、排行榜和闯关解锁。

### 班级学习情况（由年级练习卡进入）

- 点击“查看班级情况”先沿用现有课程的班级选择方式；选中一个班后才进入班级学习情况。
- 班级页首屏只显示学生数、完成率、正确率、未开始人数和薄弱知识点，避免首屏报表化。
- 学生名单显示完成题数、通过题数、正确率、最近练习时间；点击学生后看其题目列表。
- 题目分析和知识点分析收在“查看薄弱题目”入口后，不与学生名单同时抢占注意力。

### Python 题库（仅作为配置工具）

- 由“调整题目”或工作台右上角“管理 Python 题目”打开，默认筛选 Python 题目。
- 复用现有题库的新增、编辑、复制、预览和测试点配置能力。
- 增加或复用难度、知识点、适用阶段字段。
- 系统模板题不能被普通教师直接删除；教师复制后可以调整题面和题单关系。
- 题目配置必须保留公开测试点和隐藏测试点；保存前做服务端校验。

## 学生端体验

- 顶部导航显示 `Python 练习`，不把刷题卡片塞进课程作答页。
- 进入后显示当前年级已发布的基础题单，以及本人班级命中的加练包；两类题目分区显示。
- 顶部显示完成率、已通过题数和当前阶段。
- 左侧或顶部为题目列表，支持全部、未完成、已完成、错题。
- 中间一次显示一道题，复用现有 Python 编辑器。
- 操作按钮包括：保存草稿、运行示例、提交判题、上一题、下一题。
- 显示公开样例、判题结果、历史提交和当前题完成状态。
- 不显示隐藏测试数据、服务端地址、Token 或其他内部信息。
- 学生只能访问自己所属年级当前发布的基础题，以及本人班级命中的当前加练包。

## 推荐数据模型

请先核对现有表命名和主键，再决定最终表名。原则上新增以下业务对象，不修改课程成绩表语义：

- 年级基础题单：学校、学期、年级、名称、版本、状态、发布人、发布时间。
- 基础题关系：题单、题目、顺序、阶段、是否必做和题目版本标识。
- 班级加练包、加练包班级关系、加练题关系：加练包关联基础题单，目标班级支持多选；加练题只能追加。
- 学生刷题汇总：学生、题单、完成题数、通过题数、最高总分、最近练习时间。
- 学生刷题提交：学生、题单、题目、代码、提交类型、状态、通过数、总数、得分、Judge0 结果摘要、幂等键。

如果现有 `programming_submission` 可以通过增加明确的业务来源字段安全复用，优先评估复用；如果会影响课程查询、学生成绩或历史数据，则新增刷题提交表。不得凭感觉直接改生产表，必须先给出影响分析和迁移方案。

## 权限边界

- 管理员、教研员：可查看和维护所有年级题单及学情。
- 教师：只能维护自己有权限学校/年级范围内的基础题单，只能给自己可管理的班级发布加练，能查看对应班级和学生学情。
- 学生：只能查看本人年级已发布题单和本人练习记录。
- 学生不能查看其他学生代码、详细错误答案或隐藏测试数据。
- 所有列表、详情、统计接口都必须在服务端再次校验学校、年级、班级和学生身份，不能只依赖前端筛选。

## 80 道题库要求

第一批按以下比例设计：

- 入门启蒙 20 题：输出、变量、输入、整数和小数、简单计算。
- 基础语法 30 题：条件、循环、字符串、列表、简单统计。
- 进阶应用 20 题：函数、字典、嵌套结构、简单模拟。
- 综合挑战 10 题：排序、计数、综合模拟和基础算法。

每题必须具备：适用阶段、难度、知识点、题面、输入说明、输出说明、约束条件、公开样例、至少一个隐藏测试点、起始代码、参考解法验证记录。题面要使用小学高年级和初中学生能理解的中文，不引入第三方 Python 库，不设计歧义输出。

## 明确禁止

- 不把刷题作为第四类课程成绩。
- 不修改现有课程推进和课程总分规则。
- 不复制 Judge0 服务或 Python 编辑器。
- 不一开始实现排行榜、竞赛房间、复杂闯关、教师训练单、截止时间和社交功能。
- 不直接批量写正式库题目或成绩；题库导入和迁移必须有幂等 SQL、备份和后检。
- 不把密码、Token、Cookie 写入代码、上下文或测试产物。

## 验收标准

- 教师登录后只看到一个 `Python 刷题` 一级入口，页面内能切换三个功能区。
- 教师可以复制默认题单、选择基础题、保存草稿、发布和撤回，并可以对一个或多个班级发布追加题目的加练包。
- 学生登录后从顶部 `Python 练习` 进入，只看到自己年级的当前基础题和本人班级的加练包。
- 学生能保存草稿、运行公开样例、提交隐藏测试并看到通过状态。
- 刷题提交不改变课程成绩和课程推进。
- 教师能查看年级、班级、学生、题目四个层面的统计。
- 题单权限、学生隔离、隐藏测试数据脱敏和跨年级访问拒绝均有接口证据。
- 桌面和移动端无横向溢出；编辑器聚焦样式只有一层清晰蓝色边框。

开始实施前，必须先输出：现状核对、数据模型方案、接口清单、权限矩阵、页面线框、迁移风险和分阶段任务；得到确认后再改代码。
