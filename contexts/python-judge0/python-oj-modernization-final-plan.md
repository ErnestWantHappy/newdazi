# Python 刷题 OJ 化改造最终方案

> 状态：2026-08-22 用户已确认全部推荐项；P0～P3 已在本机实现并通过编译、351 项后端测试、接口与 Vue3 生产构建，P4 题库内容和 P5 正式发布尚未完成。
> 范围：统一 Python 编程题库、教师出题与导入、学生独立刷题工作台、判题结果、120 道系统题库 V2、旧 80 题治理。

## 1. 最终目标与边界

把现有独立 Python 刷题升级为适合中小学生的简化 OJ：题面明确、教师容易出题、学生可自测调试、判题反馈清楚、系统题经过真实验证。

- Python 编程题继续使用统一题库中的 `question_type=practical`、`practical_mode=PYTHON`，不新增第四类课程题型。
- 不新增“课程/刷题/通用”适用场景字段；题目用途由课程关联或刷题题单关联决定，同一题可同时复用。
- 独立刷题继续不写 `biz_student_answer`，不改变课程成绩或课程推进。
- 第一阶段只支持 Python 3 的 ACM 标准输入输出模式，不做核心函数模式、交互题、多语言、比赛和排行榜。
- 教师端不接在线 AI 出题；系统题库采用离线 AI 起草、自动校验、人工复核和正式导入。

## 2. 已确认的产品决策

| 决策 | 最终结论 |
| --- | --- |
| 题库边界 | 统一题库，不增加适用场景字段；管理端单独提供 Python 编程题视图 |
| 学生端 | 左题面、右上代码、右下控制台的三窗格沉浸式工作台，区域可拖动 |
| 系统题规模 | 首版 120 道高质量题，后续扩充至 200 道 |
| 判题模式 | 仅 ACM 输入输出模式 |
| 输出比较 | 统一换行、忽略行尾空白和文末空行，其他内容严格比较 |
| 教师出题 | 三步极简向导，不要求年级、学期、第几课 |
| 教师导入 | 双 Sheet Excel；JSON 仅作为系统题库建设通道 |
| AI 生产 | Codex 提供提示词和格式，用户网页端分批生成，Codex 校验修订后导入 |
| 旧 80 题 | 有价值的重写升级，无价值的删除；用户明确不保留 V1 历史 |

## 3. Python 编程题数据规范

### 3.1 题目字段

Python 编程配置补充以下专用元数据，避免污染选择题、判断题和文件作品：

- `title`：独立标题，列表不再截取整段题面。
- `knowledge_points`：知识点编码列表，使用受控字典，不允许随意造同义词。
- `validation_status`：`DRAFT / VALID / INVALID`。
- `validated_at`、`validated_by`：最近一次全用例验证信息。
- `content_version`：题目内容版本，用于判断修改后是否需要重新验证。

继续复用已有字段：`biz_question.difficulty`、`question_content`、`answer`（教师参考代码）、起始代码、输入/输出说明、样例解释、约束、时间/内存限制和测试点。

Python 编程题不显示、不校验 `grade`、`semester`、`lesson_num`；系统 V2 题将这些字段置空。年级适配发生在题单层，不写回题目本体。

### 3.2 公开状态

- `biz_question.is_public` 统一使用现有字典值 `Y/N`，页面显示“是/否”，不得裸显 `1/0`。
- 测试点的 `is_public` 可继续保持既有 `1/0` 内部值，教师页面显示“公开样例/隐藏测试点”；不为表面一致而扩大迁移范围。
- 公开题可被本校教师选用；私有题只允许创建者和有权限的管理员查看和使用，最终以服务端校验为准。

### 3.3 发布门禁

Python 题只有满足以下条件才可进入题单或课程：

1. 标题、题面、输入格式、输出格式和数据范围完整；无输入题必须显式标记。
2. 至少 2 个公开样例、4 个隐藏测试点；复杂题可增加到 8 个以上。
3. 参考代码必填，并在 Judge0 上通过全部测试点。
4. 测试点总权重为 100，输入输出无乱码、无非法占位符、无重复。
5. 题目内容或测试点修改后，验证状态自动回退为 `DRAFT`，重新验证前不可发布。

通用的空白起始代码允许相同；不强行为每题制造无意义差异。必须逐题真实不同的是题意、输入输出、约束、样例、边界测试和参考解法。

## 4. 学生端三窗格 OJ 工作台

### 4.1 桌面布局

```text
┌──────────────────────┬─────────────────────────────────┐
│ 题号、标题、难度、状态 │ Python 3 代码编辑器              │
│ 时间/内存限制          │ 保存状态、主题、字号、全屏、重置   │
│ 题目描述               │                                 │
│ 输入格式/输出格式       ├─────────────────────────────────┤
│ 数据范围/提示           │ 自定义输入 | 程序输出 | 判题结果   │
│ 公开样例与样例解释      │ 提交记录                         │
└──────────────────────┴─────────────────────────────────┘
```

- 主分栏和右侧上下分栏均可拖动，保存本机布局偏好。
- 题单收进可展开侧栏，提供基础题/班级加练、状态筛选、上一题/下一题和题号跳转。
- 小屏幕按题面、编辑器、控制台上下排列，不强求拖动。

### 4.2 题面

- 标题和正文分离；展示难度、知识点、通过状态、时间限制和内存限制。
- 按“题目描述—输入格式—输出格式—数据范围—提示—公开样例—样例解释”渲染。
- 样例输入和输出左右排列、等宽字体、一键复制；空输入显示“本题无需输入”。
- 不显示“输入按题面给出”“按样例格式输出”等兜底废话。

### 4.3 编辑器与防丢

- 保留 CodeMirror 6，不引入 Monaco。
- 补齐查找替换、代码折叠、亮暗主题、字号、全屏、恢复初始代码。
- 编辑即进入未保存状态；防抖保存失败可重试，切题前提示；轮询判题不得重建编辑器或覆盖新输入。

### 4.4 自测与提交

- “运行公开样例”：逐个运行公开样例，展示期望输出与实际输出。
- “自定义运行”：学生输入任意 stdin，只展示 stdout、stderr、耗时和内存，不判断对错、不计入进度。
- “提交判题”：运行全部公开和隐藏测试点，更新正式刷题进度。
- 判题中禁用重复提交；允许安全取消尚未开始的任务，已执行任务只停止前端等待，不假装远端已取消。

### 4.5 判题结果

- 状态包括 `WAITING / JUDGING / ACCEPTED / PARTIAL / WRONG_ANSWER / SYNTAX_ERROR / RUNTIME_ERROR / TIME_LIMIT / MEMORY_LIMIT / OUTPUT_LIMIT / SERVICE_BUSY / SERVICE_ERROR / CANCELLED`。
- 公开用例可显示输入、期望、实际、错误摘要、耗时和内存。
- 隐藏测试点只显示序号、状态、耗时和内存，不返回输入、期望输出或程序输出。
- 提交记录默认显示正式提交；可切换查看样例运行和自定义运行。

## 5. 判题与接口改造

### 5.1 统一输出比较器

平台后端不再完全依赖 Judge0 的 `expected_output` 精确判定。Judge0 负责编译和执行，平台取得 stdout 后按以下顺序比较：

1. `CRLF`、`CR` 统一为 `LF`。
2. 删除每一行末尾的空格和制表符。
3. 删除文本末尾多余空行。
4. 保留内部空行、词间空格、大小写、数字格式和输出顺序并严格比较。

该比较器由课程 Python 判题和独立刷题共同复用，避免同一题在两个入口判定不一致。

### 5.2 自定义运行

新增自定义运行请求，参数只包含题目范围、源代码和自定义输入。它继续走登录、学生范围、代码长度、输入长度、频率和并发限制；不运行隐藏测试点，不更新成绩或刷题进度。

### 5.3 逐测试点结果

独立刷题增加提交测试点结果表，保存用例序号、公开标记、状态、耗时、内存和脱敏错误摘要。公开用例可保存实际输出；隐藏用例不保存或不下发可反推答案的内容。学生 DTO 根据公开标记二次脱敏。

### 5.4 主要接口

- 题目详情：增加标题、知识点、限制、结构化题面和公开样例。
- 公开样例运行：返回逐公开用例结果。
- 自定义运行：返回运行任务和最终 stdout/stderr。
- 正式提交：返回汇总和脱敏后的逐用例结果。
- 提交历史：按正式提交、样例运行、自定义运行过滤。
- 教师验证：用参考代码运行全部测试点，全部通过才把题目标记为 `VALID`。
- 教师导入预检/确认：先生成报告，确认后事务落库。

## 6. 教师端 Python 编程题库

### 6.1 独立管理视图

题库管理顶部增加“Python 编程题”入口或 Tab，但后端仍使用统一题库。列表展示：题号、标题、难度、知识点、公开状态、测试点数、验证状态、创建人、更新时间和操作。

不展示年级、学期、第几课、打字时长、字数、文件扩展名等无关字段。

### 6.2 三步极简出题

1. **题目信息**：标题、难度、知识点、是否公开。
2. **题面与用例**：题目描述、输入格式、输出格式、数据范围；表格添加公开/隐藏测试点，支持批量粘贴。
3. **代码与验证**：起始代码、参考代码、默认资源限制；点击“一键验证全部测试点”，通过后保存发布。

普通值使用默认值，教师不必理解进程数、文件大小等 Judge0 底层参数；高级设置折叠显示。

### 6.3 双 Sheet Excel 导入

- `题目` Sheet：外部题号、标题、难度、知识点、题面、输入格式、输出格式、数据范围、起始代码、参考代码、是否公开、时间和内存限制。
- `测试点` Sheet：外部题号、用例名称、输入、期望输出、是否公开、权重、顺序。
- 上传后只做预检，不立即入库；报告逐题显示缺字段、重复编号、权重、乱码、参考代码执行失败和失败用例。
- 一批全部通过后事务写入；失败批次不留下半成品。

### 6.4 题单与学情

- 系统推荐题单按知识点和难度一键生成，教师可预览、调整后发布。
- 班级学情增加完成率、通过率、平均提交次数、薄弱题 Top N，并可下钻到学生明细。

## 7. 系统题库 V2：120 道

### 7.1 数量结构

| 知识点 | 数量 |
| --- | ---: |
| 输出、变量与基本类型 | 12 |
| 标准输入、类型转换与格式化 | 12 |
| 运算符与数学应用 | 14 |
| 分支结构 | 16 |
| 循环与枚举 | 20 |
| 字符串 | 14 |
| 列表与二维数据 | 14 |
| 字典与集合 | 8 |
| 函数与问题分解 | 6 |
| 综合应用 | 4 |
| 合计 | 120 |

难度建议：简单 60、中等 45、困难 15。题目不绑定年级、学期和课次，由教师按实际教学进度选用。

### 7.2 单题质量标准

- 用简体中文，任务唯一明确，不依赖学生猜测输入方式。
- 输入格式明确行数、数据类型、分隔符和范围；无输入题明确标记。
- 输出格式明确空格、换行、小数位和固定文本。
- 至少 2 个公开样例、4～8 个隐藏测试点，覆盖常规、边界、零值、负数、重复值、最小值和最大值中的适用项。
- 参考代码只使用 Python 标准库，符合题目所处学习阶段，不用晦涩技巧掩盖知识点。
- 不复制牛客、洛谷等网站的受版权保护题面；只借鉴 OJ 结构，自行创作题目。

### 7.3 生产管线

1. Codex 维护知识点清单、批次编号、提示词和 JSON Schema。
2. 用户在网页端 AI 每批生成 10～20 道 JSON 题包。
3. Codex 执行 Schema、UTF-8、重复度、题面完整性、权重和危险代码静态检查。
4. 本机 Python 先跑参考代码；再用正式 Judge0 跑全部用例。
5. 失败题自动形成驳回报告，修订后重新验证。
6. 合格题生成幂等 SQL 和导入清单；正式库完整备份后分批导入。
7. 后检题数、知识点分布、乱码、重复、验证状态和随机抽样提交。

## 8. 旧 80 题治理

### 8.1 评审标准

每题按教学价值、题意可重写性、参考解法正确性、边界可测试性和非重复性评分：

- 70 分及以上：保留核心，完整重写为 V2。
- 50～69 分：与相近题合并或重新设计。
- 50 分以下：删除。

明显时间敏感、名不副实、重复运算、无法稳定判定或伪装成高级知识点的题优先删除。

### 8.2 清理策略

用户已确认不保留 V1 历史。正式执行前必须统计 V1 题与课程、题单、快照、草稿、提交、进度和课程答案的全部依赖；生成替换映射后，按依赖顺序清理，仅处理 `create_by=python-system-v1` 的精确范围，不触碰教师自建题和课程题 1754 等非 V1 数据。

清理前做整库备份并计算 SHA-256；SQL 提供前检、执行、后检和回滚说明。若发现仍在使用的正式课程或当前发布题单，先替换为对应 V2 题，再删除 V1。

## 10. 测试与验收

### 后端

- 输出比较器覆盖 CRLF、行尾空格、末尾空行、内部空行、大小写和数字格式。
- 自定义运行不更新进度、不访问隐藏测试点。
- 教师修改题面或用例后验证状态失效。
- 私有题、跨校题、跨班记录和隐藏用例 DTO 均不可越权读取。
- 队列满、Judge0 关闭、超时、编译错、运行错、超时和输出超限状态准确。

### 前端

- 1366×768 和 1920×1080 下三窗格可用；390px 宽度上下布局无横向溢出。
- 拖动、全屏、主题、字号和题目切换不丢代码。
- 公开/隐藏、是/否、难度和验证状态不显示原始码值。
- 教师三步可完成一题；Excel 错误报告可定位到 Sheet、行和外部题号。

### 题库与生产

- 系统题正好 120 道，知识点和难度分布符合清单。
- 每题至少 2 公开、4 隐藏；参考代码在 Judge0 全部通过。
- `?` 乱码、空题面、万能输入输出文案、重复题和权重异常均为 0。
- V1 清理后不存在孤儿配置、测试点、快照或进度；非 V1 数据数量保持不变。

## 11. 发布与回滚

- 本机按“单测/编译 → 接口 → 浏览器”验收；生产不以浏览器冒烟替代单测。
- 正式库先全量备份，SQL 用 MySQL `source` 直读 UTF-8 文件，禁止 PowerShell 管道传中文。
- 后端和前端发布到新 release，不覆盖旧 release；切换 NSSM/Nginx 后探活。
- 回滚优先切回上一 release 并恢复数据库备份；若只回滚代码，必须确认新字段和旧代码兼容。

## 12. 明确不做

- 不增加适用场景字段，不拆第二套 Python 题库。
- 不在教师端接 AI 出题。
- 不照搬牛客或洛谷题面，不引入 Monaco。
- 不做多语言、核心函数模式、交互题、排行榜和比赛系统。
- 不把独立刷题写入课程成绩。
