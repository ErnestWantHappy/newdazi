# Python 刷题功能优化方案 v1（已被最终方案取代）

> 状态：已完成讨论，最终结论见 `python-oj-modernization-final-plan.md`。
> 适用模块：教师端 `business/pythonPractice/index.vue`、学生端 `views/student/pythonPractice.vue`、
> 后端 `PythonPracticeTeacherController` / `PythonPracticeStudentController` / `PythonPracticeService`、
> 题库管理 `views/business/question/index.vue`、系统题数据 `sql/python_system_questions_*.sql`。
> 参考基准：牛客网在线编程题（nowcoder 语法篇）以及 OJ 通用题面结构。

---

## 0. 先给结论（一页看懂）

1. **当前最大问题不是"判题"本身**（Judge0 已跑通），而是**题目内容和元数据不对**：
   - 80 道内置 Python 题被当成"课程操作题"塞进了 `biz_question`，硬填了 `grade=7 / semester=0 / lesson_num=序号`，并带 `第几课` 列，语义完全错误。
   - 题面只有"标题 + 请根据输入说明编写程序并输出结果"，没有题目描述、输入格式、数据范围，学生看不懂。
   - 80 道题的说明字段、起始代码几乎完全相同（各只有 1 个不同值），毫无区分度。
   - 期望输出存在被字符集替换成 `?` 的**隐患**（历史修复脚本从未覆盖 `expected_output` 字段），一旦是 `?` 学生永远无法通过。

2. **两条腿分开**：把"课程操作题（Python 在线编程）"和"独立刷题练习"从**管理视角**彻底分开，但**不破坏现有数据库模型与成绩体系**。

3. **学生端改成标准 OJ 题面布局**（题目描述 / 输入格式 / 输出格式 / 样例输入 / 样例输出 / 样例解释 / 数据范围 / 提示），参考你发的 P11135 和牛客 OJ。

4. **教师端出题要简单**：内置/系统题库 + 一键发布；教师自建练习题走"极简向导"，不再强制填年级/学期/第几课。

## 2. 已确认边界：统一题库，不增加“适用场景”字段

现状：Python = 操作题的一种作答方式（`question_type=practical`、`practical_mode=PYTHON`）。**这个设定对"课程操作题 + 成绩合计为 100 分"是正确且必须保留的**，不要动。

独立刷题与课程 Python 题共用同一套 Python 题目是有意设计：一题可以被课程选用，也可以被题单选用，具体用途由课程关联或刷题题单关联决定，不是题目自身属性。因此不新增 `COURSE / PRACTICE / BOTH` 之类需要教师维护的字段。

管理端按 `question_type=practical + practical_mode=PYTHON` 提供独立的“Python 编程题库”视图；这是展示和编辑方式分流，不是拆表或新增题型。Python 编程题页面不显示、不校验年级、学期、第几课，改为显示题号、标题、知识点、难度、测试点数、公开状态和验证状态。课程选题和独立刷题选题均可复用这些题目。

## 3. 学生端优化（UI + 功能逻辑）

参考 OJ 标准题面（牛客 / P11135）与学生端当前实现，改造如下。

### 3.1 题面结构（核心）
把当前"一段文字"改成结构化题面卡片，从上到下：

```
┌──────────────────────────────────────────────┐
│  题目标题        [难度] [知识点] [通过率] [已通过√] │
│  时间限制: 1s   内存限制: 128MB                  │
├──────────────────────────────────────────────┤
│  题目描述                                      │
│  （完整的题意说明，用什么、算什么、要求什么）         │
├──────────────────────────────────────────────┤
│  输入格式                                      │
│  输出格式                                      │
│  数据范围 / 约束                                │
│  提示（可选）                                   │
├──────────────────────────────────────────────┤
│  样例输入    样例输出                            │
│  ┌────────┐  ┌────────┐                       │
│  │ ...    │  │ ...    │                       │
│  └────────┘  └────────┘                       │
│  样例解释（可选）                                │
└──────────────────────────────────────────────┘
   [ 编辑器 main.py ]  [ 运行示例 ] [ 提交判题 ] [ 保存草稿 ]
   判题结果区（AC/WA/TLE/CE/RE/部分通过，展示用时/内存/错误信息，隐藏样例只给汇总）
   历史提交表（时间/类型/状态/分数/样例数）
```

- **题目描述、输入格式、输出格式、数据范围**：从后端 DTO 逐字段下发（当前已有 `input_description/output_description/sample_explanation/constraints_text/notes_text` 字段，前端**没有完整渲染**，是本轮重点）。
- **样例输入/样例输出**：改为左右分栏、等宽字体、可复制，符合 OJ 直觉，替代现在的"输入：… 期望输出：…"扁平串。
- **头部标签**：难度（简单/中等/困难）、知识点、该题通过率、我的状态（未开始/待改进/已通过）。
- **时间/内存限制**：显示 `time_limit_seconds` / `memory_limit_kb`（D 上已有，前端补齐）。
- **移动端**：题面与编辑器折叠为上下布局优化（当前已有基础媒体查询，需重排题面区）。

### 3.2 编辑器能力补齐（对照需求第 19、20 条）
当前已具备：Python 高亮、行号、自动缩进、括号匹配、撤销重做、关键词补全、焦点边框样式。
建议补齐：**代码折叠**、**主题切换**、**全屏编辑**、**查找替换**，并保证**轮询刷新不丢编辑内容**（当前实现可能因 `selectQuestion` 重建编辑器导致输入丢失，需用草稿/本地强制保留或在重建前比对）。

### 3.3 提交与判题结果
- 新增状态细分：`等待判题 / 判题中 / 通过 / 部分通过 / 答案错误 / 语法错误 / 运行错误 / 超时 / 内存超限 / 服务异常 / 已取消`（后端已有枚举，前端结果区样式补齐，`AC` 绿色、`WA/TLE/RE/CE` 红色、`部分通过` 黄、`等待/判题中` 转圈）。
- 失败结果展示：**语法/运行错误要展示**错误摘要，**隐藏样例**只返回通过数/总数汇总，不返回隐藏输入输出（后端已脱敏，前端不要透传）。
- "运行示例"跑**公开样例**自测，不写历史；"提交判题"跑**全部样例**（公开+隐藏）作为正式成绩。
- 结果区加"耗时 / 内存"，便于学生判断性能（可选）。

### 3.4 题单列表
- 左侧题单区分"基础题 / 班级加练"，保留筛选（全部/未完成/已完成/错题）。
- 列表项增加**难度标签**、**通过状态圆点**，题面超长省略。
- 支持题单内"跳到指定题号"（当前只有上一题/下一题）。

## 4. 教师端优化（UI + 功能逻辑）

目标：**让新手教师不进入复杂题库就能发布一套练习**，同时**自建题目也不复杂**。

### 4.1 一键发布系统题库
- 首页/工作台提供"发布系统推荐题单"入口：选年级 → 选难度/知识点 → 一键生成题单（从内置题库挑选），无需进题库选。
- 已发布题单可"一键更新"（当内置题库内容更新后，用新版快照替换）。

### 4.2 极简"新建练习题"向导（替代去题库管理建题）
教师自建题只需三步：
1. **题目**：标题 + 题目描述（文本框，可粘贴 Markdown）+ 知识点 + 难度。
2. **样例**：添加 1 个公开样例（输入/输出）+ 若干隐藏样例（可批量粘贴）。
3. **判题**：起始代码（可选）、时间/内存限制（用默认值即可）、是否公开。
- **不再强制填年级/学期/第几课**（练习域不需要）；`is_public` 改为单选题"是否公开练习题"，默认"是"，不再展示原始 `1/0`。
- 教师端不提供 AI 出题按钮。AI 批量生产系统题属于平台建设流程，不把生成复杂度转嫁给普通教师。

### 4.3 从题库选题
- 题库选择器默认只查"练习题域"的 PYTHON 题，按 **难度 / 知识点 / 题面关键词** 筛选，不再混入无年级的困惑。
- 预览弹窗按学生端题面结构展示（含输入/输出/样例/数据范围/起始代码），题目先预览再选。

### 4.4 班级学情
- 按基础题 / 班级加练分开统计；补**薄弱题排名**（正确率最低的前 N 题）、**完成率**、**平均提交次数**，并把每题点击到该题在班级的正确/错误明细。

## 5. 题库与数据层调整

### 5.1 字段语义
- 练习域名题目：`grade`、`semester`、`lesson_num` 设为可空/不再强制，DTO 不下发；`is_public` 语义明确为"是否公开练习题"，默认"是"。
- Python 编程题不再强制使用课程元数据；补充或规范 `knowledge_point`（知识点）、`tags`（标签）、`difficulty`（难度，已存在，需真实标注）和验证状态。参考解法继续使用现有受保护字段，不向学生下发。

### 5.2 内置题库内容重做（AI 出题质量）
用户反馈"当前 AI 内置题目很多问题、内容完全一样、题面不清楚"，核心是**生成提示词太弱 + 缺少校验**。已确认不在教师端接 AI，采用离线生产：由 Codex 提供严格提示词和结构化题包模板，用户在网页端 AI 分批生成后交回，Codex 负责校验、修订和导入。流程如下：

1. **重写生成提示词**，单题必须产出：
   - 题目描述：清楚说明输入是什么、做什么运算、输出什么。
   - 输入格式 / 输出格式：逐字段说明（含空格/换行分隔、整数/浮点、多行输入的读取方式）。
   - 数据范围：输入数值边界，避免学生猜。
   - 至少 1 个公开样例 + 2 个隐藏样例。
   - 参考解法（必须与测试点一致）。
   - 起始代码：`# 请根据题目要求编写程序` 这种通用头即可（这些练习不需要复杂模板，保持简单）。
2. 每批建议 10～20 题，AI 必须按约定 JSON Schema 输出，避免网页长回复截断、转义错误和题号错位。
3. **每道题**：写入前先做结构、字段、编码、重复度和边界测试静态校验，再用本机 Python 与正式 Judge0 跑全部测试点，**全对才入库**；否则生成逐题驳回报告并修订。
4. **去重**：题名、题面语义、参考解法结构、公开/隐藏测试点组合均检查重复，避免只换故事外壳。
5. **避免 `?`**：所有中文/特殊字符以 `utf8mb4` 正确写入；导入必须 `source` 直读 UTF-8 文件，不能用 PowerShell 管道（会转 `?`）。
6. **定位分层**：简单（输入输出/四则/字符串基础）、中等（分支/循环/列表/字典）、困难（算法/嵌套/二维/数学），覆盖中小学 Python 教学核心知识点。
7. **知识点体系**：建一份知识点字典（如"变量与类型 / 输入输出 / 分支 / 循环 / 列表 / 字典 / 函数 / 字符串 / 数学"），题目打标签，便于筛选与生成。

### 5.3 数据修复
- 新增一个**全字段质量校验脚本**：扫描 `biz_question`、`biz_programming_question_config`、`biz_programming_test_case`、`biz_python_practice_question_snapshot`、`snapshot_case`（以及可能的 `submission` / `progress` 冗余），凡含 `?`、空题面、缺测试点、无参考解法的都列出。
- 对存量 80 题逐题评分，不机械全部保留：核心练习目标清楚、参考解法正确且有教学价值的题，重写完整题面、补齐测试点并升级为 V2；题意重复、价值低、边界无法说清或解法本身不规范的题直接删除。用户已明确不保留 V1 历史，实施时可在精确依赖前检和整库备份后清理其题单快照、草稿、提交与进度，再删除 V1 题目、配置和测试点。

## 6. 分阶段实施计划

| 阶段 | 内容 | 验证方式 | 预计工作量 |
| --- | --- | --- | --- |
| **P0 数据治理** | 全字段质量校验；统一公开值域；Python 管理视图移除课程元数据；准备 V1 依赖审计与清理脚本 | 前检/后检 SQL；抽查 `expected_output` 无 `?` | 小 |
| **P1 学生端 UI** | 题面结构化成 OJ 布局；样例左右分栏；头部标签/限制；结果区状态补齐；编辑器折叠/主题/全屏/防丢 | 本机后端 + 前端；学生号冒烟截图 | 中 |
| **P2 教师端 UI** | 一键发布系统题库；极简建题向导；教师友好的批量导入；题库选择器按难度/知识点；学情补薄弱题 | 教师号冒烟；自建题跑判题 | 中 |
| **P3 内置题库重做** | Codex 提供提示词与 JSON Schema；用户网页端分批生成；Codex 自动校验、修订、去重并部署系统题库 | 参考解法全对入库；题面/测试点去重 | 大（分批执行） |
| **P4 接口/后端** | 练习域 DTO 精简字段；判题结果状态映射；通过率统计；知识点/难度下发 | Java 单测 + 接口探活 | 中 |

> 优先级建议：**P0 → P1 → P2 → P3/P4**。P0 能立刻解决"`?` 无法提交 + 年级学期第几课 + 内容相同"这三个用户最痛的点；P1/P2 提升体验；P3 解决"题面不清、题库太薄"的长期问题。

## 8. 风险与边界

- **不动课程成绩**：Python 在线编程作为"操作题作答方式"、课程满分合计 100、`biz_student_answer` 写回逻辑**保持不动**。
- **数据迁移需备份**：任何改 `biz_question` / 题库 / 快照 / 测试点的 SQL，发布前必须对目标库备份、前检、执行、后检；不能把本机迁移成功等同正式库已迁移。
- **`is_public` 改名影响面**：若把"是否公开"从课程题语义改为练习语义，需同步 `views/business/question/index.vue`、`ProgrammingQuestionController`、DTO 及字典，避免误伤课程操作题。
- **AI 生成**：必须加**自动校验 + 人工可改**，防止新库继续出现同质/错题；AI 仅作为"建议"，不直接写库。
- **字符集**：所有含中文 SQL 必须 `source` 直读 UTF-8 文件执行；禁止 PowerShell 管道，否则变 `?`。
- **编辑器防丢**：轮询刷新后重建编辑器必须保留已输入内容，用草稿兜底。
