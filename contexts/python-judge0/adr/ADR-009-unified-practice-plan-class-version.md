# ADR-009：练习题单通过版本关联多个目标班级

状态：已接受并已正式发布（2026-08-22）。

> 2026-08-22 补充：本 ADR 的“有记录则归档并可恢复”已被 [ADR-010](ADR-010-hard-delete-and-natural-class-label.md) 取代；统一题单、版本关联班级和发布版本不可变等其余决策继续有效。

## 决策

独立 Python 刷题只保留一种产品对象“练习题单”，不再向教师展示“年级基础题单”和“班级加练包”。一个题单版本通过 `biz_python_practice_plan_class` 关联一个或多个教师可管理班级；“全年级”只是前端一次选中该年级全部班级。同一班级可以收到多个普通题单。

题单发布后继续使用不可变版本和题目快照。教师修改已发布题单时，后端复制目标班级、题目快照、快照测试点和题目顺序到新草稿版本，学生继续使用旧发布版本，直至新版本再次发布。没有练习记录的题单物理删除；存在草稿、提交或进度时只归档并停止投放，可从已删除题单恢复。

## 数据与迁移

- 新增 `biz_python_practice_plan_class(plan_version_id, dept_id, entry_year, class_code)` 唯一关联。
- 移除 `biz_python_practice_plan` 的学校/届别唯一约束，允许同一范围创建多份题单，保留普通查询索引。
- V1 题单版本迁移到该校该届实际存在学生的全部班级；无学生的草稿退而使用创建教师负责班级。
- 旧 `biz_python_practice_extension*` 三表不再参与业务查询。正式迁移前它们均为 0 行，因此本轮保留物理表作为回滚兼容，不做破坏性删除。

## 后果

教师端只需“题单名称 → 目标班级 → 选题并发布”，学情统一按题单、班级、学生和题目统计。学生题目范围必须由已发布版本与本人学校/届别/班级在服务端重新计算，不能信任前端传入班级。回滚到 V1 唯一范围约束只允许在尚未产生同范围多题单时执行。
