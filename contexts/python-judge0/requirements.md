# Python 在线编程与 Judge0 CE 需求

## 目标

在既有题库、课程、学生答题和成绩体系中增加 Python 在线编程与自动判题。Python 是“操作题”的作答方式，不是第四类题型或成绩；浏览器不得直连 Judge0，第一阶段只支持 Python。

## 验收要求

- 教师在“操作题”中选择“Python 在线编程”，配置初始代码、公开/隐藏测试点、分值权重与资源限制。
- 学生可保存草稿、运行公开示例、正式提交、查看本人与本题的历史。
- 后端鉴权后调用 Judge0，异步轮询并将正式终态写回既有 `biz_student_answer`。
- 状态必须包含等待、判题中、通过、部分通过、答案错误、语法错误、运行错误、超时、内存超限、服务异常和取消。
- Judge0 故障不丢失代码或提交，不写零分。
- Judge0 仅允许主平台后端访问；学生代码无网络、CPU/内存/进程/输出/文件均受限。
- 同一门课程可同时配置文件作品操作题和 Python 在线编程题；两者均属于操作题，课程总分仍由全部题目分值合计为 100 分。
- 成绩查询默认保留“操作题”合计，并在课程详情显示文件作品与 Python 编程两个小计，不新增第四类成绩。
- 学生课程题目 DTO 缺失作答方式时，页面只能向平台后端核验该题是否为已启用的 Python 题；核验失败必须继续按文件作品处理，绝不由浏览器直连 Judge0 或猜测为编程题。
- 学生 Python 题应清晰展示输入说明、输出说明、公开样例输入、期望输出、运行实际输出、错误信息、状态与历史提交；隐藏测试点只能返回汇总结果，不返回隐藏输入和答案。
- 学生编辑器至少支持 Python 高亮、行号、自动缩进、括号匹配、撤销重做、查找替换、折叠、关键词补全、主题切换、全屏和移动端布局；编辑内容不得因轮询刷新丢失。
- 草稿保存必须防抖，保存期间的新输入必须补发最新版本；判题轮询达到上限后显示可恢复状态，不得永久停留在“判题中”。

## 不做

- 第一阶段不支持 Python 以外语言、交互式输入、多人协作代码编辑或公开 Judge0 API。
- 不新建用户、课程、班级、总成绩或替代现有权限模型。

## 待开发：独立 Python 刷题

### 产品目标

在既有课程 Python 操作题之外，提供面向日常练习的简化 OJ。它使用已有题库、CodeMirror 和 Judge0，但练习记录、提交记录和统计与课程作答、课程推进、课程总分完全隔离。

### 教师配置规则

- 教师端只有一个一级菜单“Python 刷题”，首屏沿用教师首页的“年级分组 -> 练习卡 -> 配置或查看班级情况”操作路径。
- 每个学校、学期、年级只有一套当前发布的“年级基础题单”；基础题对该年级全部可见班级生效，是横向比较和基础教学的共同尺度。
- 教师可创建一个或多个“班级加练包”，每个加练包可选一个或多个班级并追加题目。不同班级可以收到不同加练包。
- 加练包只能追加题目，不能删除、替换或隐藏年级基础题；学生始终先看到基础题，再看到自己班级获得的加练题。
- 教师可保存草稿、发布、撤回基础题单或加练包；撤回后不再向学生显示，已产生的提交和统计历史必须保留。

### 刷题验收要求

- 新手教师可直接发布系统推荐题单，不需要先进入复杂题库或设置班级。
- 教师可为选定班级创建加练包，并能在班级页分别查看基础题和加练题的完成情况。
- 学生只可访问本人年级的已发布基础题，以及本人班级命中的已发布加练包；不可访问其他班级题目或记录。
- 每题首次或再次判题均复用既有 Judge0 能力；刷题提交不写入 `biz_student_answer`，不改变课程成绩。
