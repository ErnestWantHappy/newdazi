# 题库画流程图题：拍照 + AI 生成标准答案（需求）

> 状态：**方案已确认（用户选定方案 A），待实施**。上下文日期 2026-10-23。
> 上游基线：本功能完全建立在 [画程流程图操作题专题](../flowchart-tool/requirements.md) 与 [操作题 AI 辅助批改专题](../operation-artifact-ai-grading/requirements.md) 的已有能力之上，不新建第二套流程图或成绩体系。

## 1. 背景与目标

教师在题库新建“操作题 → 画程流程图”时，标准答案目前只能在 LogicFlow 画布逐个手画，耗时。

目标：老师**拍一张流程图照片上传**，系统结合本题已填的**名称、年级、学期、第几课**，用已在批改侧接入的**视觉大模型**识别照片，**自动生成流程图标准答案草稿并直接填进画布**，老师**核对微调后保存**，以此节省出题时间。

## 2. 首期范围

- 仅“画程流程图”作答方式（`question_type=practical` + `practical_mode=FLOWCHART`）的题目配置阶段。
- 照片来源：老师用设备拍好后**从相册/文件选一张上传**（复用现有 `ImageUpload`）；**不做网页实时摄像头**。
- 一次只生成**标准答案**；学生基础图、结构检查规则继续用设计器现有“从标准答案复制”“生成检查规则”一键得到。
- AI 结果**直接回填画布**供老师编辑，老师点保存才写入 `answer_json`；**不建独立建议表**。
- 复用教师已配置的多厂商视觉 Key（通义/DeepSeek/豆包），端点走服务端白名单。

## 3. 非目标

- 不生成题干文字、评分项与分值。
- 不接入区域抽测；不改学生作答、批改与成绩链路。
- 不做自动判分；不改 `biz_student_answer`。
- 不承诺照片 100% 还原，定位为“AI 草稿 + 老师核对”。

## 4. 需求

### REQ-01 触发与信息来源
- 入口在题库画流程图题的“标准答案”页签，新增“AI 生成标准答案”按钮。
- AI 依据的元数据**全部取自本题已填字段**：`title`（操作题名称）、`grade`、`semester`、`lessonNum`（`RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/domain/BizQuestion.java`）。**不依赖该题是否已排进某节课**，题库题目独立可用。

### REQ-02 照片上传
- 支持 jpg/png 单张，沿用 `PracticalFilePolicyService` 的类型与大小校验。
- 上传走现有 `/common/upload`，服务端生成存储键，不信任原始文件名。

### REQ-03 生成与回填
- 后端把“题目信息 + 照片”送视觉模型，模型返回节点与连线（不含坐标）。
- 平台自动排版坐标，产出合法的 `answer_json` 文档结构。
- 结果直接载入 LogicFlow 标准答案画布；顶部横幅标注“AI 生成，请核对后保存”。
- 载入若将覆盖老师未保存的手工内容，先二次确认；最终正式写入仅在老师点保存时发生（沿用 `saveTeacherConfig` + `config_revision` 乐观锁）。

### REQ-04 输出安全与校验
- 节点类型仅 `terminal`/`process`/`decision`/`inputOutput`，连线仅 `polyline`。
- 文字经现有纯文本、HTML、脚本注入白名单（`FlowchartDocumentService.normalizeDocument`）。
- 越界坐标、超数量、含环或孤立节点等非法输出必须兜底，不得产生损坏文档。

### REQ-05 成本与前置
- 默认在建题处展示一行轻提示：“本次将调用视觉模型，需已配置 AI Key 且可能产生费用”。
- 教师未配置对应厂商 Key 时给出明确中文错误，不静默失败。

## 5. 验收标准

1. 一张清晰打印体流程图照片，能生成结构正确、可编辑的标准答案，保存后重进内容一致。
2. 手写或复杂照片识别不全时，老师仍能在画布手动补正，不影响保存。
3. AI 非法或越界输出被拒绝并提示，不写入损坏 JSON。
4. 未配 Key 时给出可读错误；已配 Key 时走白名单端点。
5. 不修改任何数据库表结构；不改学生作答、批改与成绩链路。
6. 后端定向单测、`clean package`、前端构建通过；教师角色浏览器冒烟通过。
