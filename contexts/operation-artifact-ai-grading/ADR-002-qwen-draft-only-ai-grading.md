# ADR-002：百炼千问单供应商与 AI 草稿确认制

- 状态：已接受，代码已实现；真实调用待隐私与盲测门禁
- 日期：2026-08-04

## 背景

操作题需要识别 Word、PPT、Excel、PDF 与图片统一生成的页面图，并按课程发布时的评分项逐项给分。国内网络稳定性、教师个人计费 Key、学生作品隐私和模型偶发格式错误共同决定：首期不能同时维护多个生产厂商，也不能让模型直接覆盖正式成绩。

## 决策

1. 首期生产适配器只接阿里云百炼。依据百炼当前官方模型文档，默认 `qwen3.7-plus`（质量优先），可切换 `qwen3.6-flash`（速度/成本优先）；旧通用域名仍可用，后续获得教师 Workspace ID 后再迁移专属域名。
2. 豆包只参加上线前匿名同样本盲测，不在首期代码里形成双厂商配置和失败分支。
3. 本地规范化 JPEG 使用 Base64 直接传入 HTTPS 接口，不把学生页图变成公网 URL；模型输入不含姓名、学号和班级。
4. 每位教师保存自己的 Key；后端以部署环境 `PRACTICAL_AI_MASTER_KEY` 派生 AES-256-GCM 密钥并使用随机 IV 加密，前端只显示末四位。未配置部署主密钥时拒绝保存 Key。
5. 任务、结果分别绑定教师、课程班级、提交版本和评分快照。模型必须返回 `operation-rubric-v1` JSON；服务端重新校验评分项集合、逐项上限、合计和题目总分。
6. AI 结果永远是建议。教师点击“采用到评分框”后仍需人工复核并调用现有人工评分接口；AI 工作器没有写 `biz_student_answer.score` 的路径。

## 结果

- 教师工作流保持原有连续批改和回车提交，不新增独立复杂审核系统。
- 补交或评分快照变化不会让旧 AI 建议误用于新版本。
- 单厂商适配降低首期维护成本，同时保留以后增加 `PracticalVisionGradingProvider` 实现的扩展点。
- 真实调用必须额外配置部署主密钥、教师 Key，并完成学校授权、供应商数据策略审查和千问/豆包匿名盲测；代码完成不等于生产门禁通过。
- 本机已用一次性主密钥和假 Key 验证 AES-GCM 密文、末四位掩码与删除闭环；未进行任何真实厂商请求。
