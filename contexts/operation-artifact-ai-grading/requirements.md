## 2026-09-17 纸质逐空证据要求

纸质作品先独立识别学生作答，再对照参考答案评分。逐空记录 written/blank/uncertain、原文与学生页码；空白或不确定不能满分，全空不能得分。按用户后续要求，待核对标记不得禁用批量采用，教师在原确认框知晓待核对份数后可采用。默认及价格按上方最新追加执行。识别仍可能误读，不能承诺杜绝视觉幻觉。

## 1. 产品目标

在不破坏现有教师出题、学生提交、教师连续批改和区域抽测流程的前提下，将操作题从“单个 DOCX”升级为“一个逻辑作品”，并在作品闭环稳定后增加国内视觉大模型辅助批改。AI 只生成可追溯草稿，最终成绩必须由教师确认。

## 2. 已确认范围

### REQ-01 逻辑作品

- 一次操作题提交对应一个逻辑作品，可包含一个或多个文件。
- Office/PDF 主作品采用单文件；图片作品允许 1～10 张并保留顺序。
- 单个文件上限 50 MiB；服务端必须同时校验扩展名、MIME、文件头和实际大小。
- 学生作品一期支持 DOC/DOCX、PPT/PPTX、XLS/XLSX、PDF、JPG/JPEG、PNG。
- ZIP/RAR 等压缩包一期只用于教师资源附件，不作为学生可自动预览、可 AI 批改的作品。

### REQ-02 教师出题材料分工

- “学生起始文件”“补充资源”“参考答案/评分依据”分开保存和展示。
- 起始文件最多一个；补充资源可多个；参考材料只对有权限教师和后续 AI 任务可见。
- 题目必须声明允许的提交类型，学生端只展示本题允许类型。

### REQ-03 提交版本

- 每次提交/补交生成不可变版本；教师默认只批最新版本，可查看历史版本。
- 新版本提交后，旧人工成绩、分项明细和 AI 草稿失效但不物理删除。
- 保存成绩时必须校验提交版本与预期旧成绩，冲突时拒绝覆盖并提示刷新。

### REQ-04 统一预览

- DOC/DOCX、PPT/PPTX、XLS/XLSX、PDF 使用 LibreOffice/PDF 静态预览；图片直接预览。
- 预览采用页面/图片条带，不模拟 Office 编辑器；转换失败时允许授权下载且不阻断人工批改。
- 常规课程与区域抽测共用转换、状态、重试、权限与失败降级底座。

> 实施状态：普通课程和区域抽测已复用 Office→PDF→JPEG、PDF→JPEG、图片→JPEG、状态/重试和连续页图底座；普通课程缓存只复用计算结果，页图落到当前附件独立目录。PPTX/XLSX 本机真实生成样本已通过转换、页数和目视验收；区域抽测既有物理样本缺失，仍需实体环境补验。

### REQ-05 评分标准

- 评分项权重合计必须为 100%，服务端按最大余数法折算为题目绝对分值，所有分项上限之和必须精确等于题目满分。
- 分项评分必须完整、无重复、属于当前题目且不超过各项上限；总分必须等于分项合计且不得超过题目满分。
- 发布/开课时形成评分标准快照，后续修改题库不得改变已发布课程或抽测的评分口径。

### REQ-06 教师连续批改

- 保留回车提交并跳到下一位、PageUp/PageDown 切换、全屏预览等高频操作。
- 保存中锁定重复提交与换人；异步响应只允许更新它发起时对应的学生。
- 保存失败、版本冲突或逾期时不得自动跳到下一位。

### REQ-07 AI 辅助批改

- 一期只用于常规课程操作题；区域抽测待普通课程稳定后再评估接入。
- 主供应商采用阿里云百炼通义千问视觉模型；豆包作为上线前同样本盲测候选，不在首期同时接入生产。
- 输入包括题干、题目满分、评分项快照、参考材料、学生最新作品的规范化页面图及必要的受控文本提取。
- 输出必须为严格结构化 JSON，包含逐项得分、证据页/图、理由、置信度、总分和风险标记。
- AI 分数只能保存为草稿；教师可以修改后确认，确认动作才写正式成绩与分项明细。
- 班级批改采用后台任务，支持进度、逐份失败、重试、暂停/取消和模型调用审计。

> 实施状态：默认使用百炼 `qwen3.7-plus`，可切换 `qwen3.6-flash`；严格 JSON、服务端重算、暂停/继续/取消/失败重试和教师采用后人工提交均已实现。正式服务器已用真实教师 Key 和无学生信息测试图完成视觉连通，并在服务重启后用原密文复测通过；真实学生作品批量任务仍保持门禁关闭。

### REQ-08 教师 API Key

- 每位教师维护自己的 API Key，只能新增、替换、测试和删除，保存后只显示掩码。
- Key 必须后端加密存储，密文、明文和请求 Authorization 不得进入日志、前端缓存、业务上下文或 Git。
- 数据库与附件备份、日志留存、供应商数据策略未通过隐私门禁前，不启用真实学生作品批量 AI 批改。

> 实施状态：教师设置弹窗已提供“前往阿里云百炼申请 API Key”入口，直达官方 API Key 控制台并在新标签页打开。正式库仅保存 `v1:` AES-GCM 密文，页面与接口不返回明文；部署主密钥只存在服务器服务环境及受保护的配置备份中。

### REQ-09 AI 批改范围、依据与批量采用（2026-08-09 方案 A）

- 发起任务前必须先展示本班已提交、已人工批改、未批和页图就绪人数；默认只生成未批学生建议，教师也可选择全班重新生成建议。
- AI 批改必须有教师参考答案。教师可在当前课程批改弹窗直接上传或替换；支持 DOC/DOCX、PDF、PPT/PPTX、XLS/XLSX、JPG/JPEG、PNG，不接受压缩包。
- 每次任务必须冻结教师参考答案和学生空白起始材料，模型先比较空白材料、教师参考答案和学生作品，再按评分项给分；任务创建后替换参考答案不得污染旧任务。
- 刷新或重新进入批改页必须恢复当前范围下最近一次 AI 任务、进度和逐份结果；旧任务数据不能因前端状态丢失而消失。
- AI 建议页面直接展示每个评分项的名称、得分、上限和理由，不再只显示总分。
- “批量采用 AI 建议”提供“仅补未评分”和“覆盖已有评分”两种独立模式；默认推荐仅补未评分。全班重新生成建议本身仍不修改正式成绩。
- 覆盖模式必须展示将覆盖和补齐的人数，并再次高风险确认；只采用成功建议，提交版本变化或期限关闭的答卷仍逐份跳过。
- 两种采用模式都必须复用服务端分项完整性、上限、合计、答卷行锁、版本与期限校验；每份成功写入都记录操作教师、模式以及覆盖前后的总分和分项快照。

### REQ-10 AI 处理可视化与恢复（2026-08-09 方案 A）

- 教师可随时打开“AI 处理详情”，查看已结束、处理中、等待数、当前学生、当前阶段、运行时长、平均单份耗时、预计剩余时间和最近心跳。
- 每份作品必须区分等待、准备学生作品、请求视觉模型、校验保存、成功、失败和取消；失败原因可定位到对应学生，并支持现有失败项重试。
- 任务记录安全事件日志，但不得显示 API Key、Authorization、完整提示词、模型原始输出、学生作品内容或后台异常堆栈。
- 空白起始材料和教师参考答案每个任务只转换一次，页图路径与标签持久化复用；缓存丢失时允许按任务快照重新准备。
- 服务重启时自动扫描 `PENDING/RUNNING/CANCEL_REQUESTED` 任务；只把中断中的单份结果退回等待并接续，`SUCCESS/FAILED` 结果不重复调用模型。
- 运行中超过 6 分钟没有阶段心跳时页面明确提示“疑似等待过久”，但不得自动并发启动第二个工作器。

## 3. 非目标

- 不在一期内实现在线编辑 Office、压缩包在线预览、AI 无确认自动发布正式成绩或区域抽测自动批改。
- 不更换 Vue3、Spring Boot、MySQL、LibreOffice 等现有技术栈。
- 不以多文件字段硬塞进现有 `student_answer` 字符串；新附件和版本必须结构化建模。

## 4. 验收门禁

- 评分边界、重复/越权评分项、舍入、并发保存、补交冲突均有后端验证。
- DOCX/PPTX/XLSX/PDF/图片合法样本与伪装文件、超限文件、转换失败、越权读取均有专项测试。
- AI 阶段必须用同一匿名样本和评分标准对候选模型盲测，记录一致性、证据准确性、失败率、延迟与成本。
- 每个阶段先完成测试与文档，再进入下一阶段；服务器发布单独执行备份、迁移、发布和回滚演练。

## 5. 当前题目答案与 AI 费用可见（2026-08-25）

1. 批改班级状态、学生提交、成绩/排名/错题、操作题统计、截止进度和失败预览恢复，只能读取仍关联当前 `biz_lesson_question` 的答案。
2. 课程保存删除题目关联前，必须把被移除题目的在线答案完整归档并写批次元数据；归档、元数据或删除数量不一致时整次保存回滚。
3. 管理员可维护模型输入/输出单价、状态和说明；教师可查看但不能修改。初始价只作参考，映射未确认的模型必须显示 `TO_CONFIRM`。
4. 新 AI 任务冻结创建时单价；任务详情汇总输入、输出、总 token 和理论费用。旧任务无价格快照时允许引用当前价，但必须说明口径可能漂移。
5. 设置弹窗展示当前模型参考价与单份历史/参考用量估算；任务详情展示本任务实际记录 token 的理论费用。两处都必须显示“估算值，实际以阿里云账单为准”。
6. 百炼 `Arrearage`、`InvalidApiKey` 前缀和限流/配额错误必须转为中文可操作提示；未知错误只能返回 HTTP 状态和截断、脱敏后的供应商摘要。
7. 本轮不查询百炼账户余额，不新增独立价格页面，不改变 AI 建议必须由教师确认后才能进入正式成绩的既有边界。

## 6. 2026-09-02 人工星级批改与实时状态（已确认，尚未开发）

### REQ-11 星级辅助评分

- 数字输入继续作为默认评分方式，五星是教师可选的鼠标快捷辅助，不替代精确数字输入。
- 同时支持“整题评星”和“逐评分项评星”，由教师在批改界面明确切换。
- 五星对应题目或评分项满分的 20%、40%、60%、80%、100%；零星通过独立“0 分/清零”按钮设置。
- 当前成绩域继续保存整数。计算结果出现小数时使用四舍五入，例如 7 分题对应 1、3、4、6、7 分；界面必须在点击前后显示实际折算分，不能只显示星数。
- 整题评星只写总分并标记评分方式，不伪造教师没有逐项判断过的评分明细；逐项评星按每项上限折算，并继续执行分项完整性、上限和合计校验。

### REQ-12 评价标准版本

- 已提交作品永久使用提交时绑定的评价标准快照；修改后的标准只作用于后续提交版本。
- 学生重新提交形成新作品版本时，绑定重新提交当时的最新评价标准；旧作品版本和旧标准仍可追溯。
- 已存在学生提交后，不允许修改课程中该操作题的总分；教师可在总分不变的前提下修改评价文字和权重并生成新标准版本。
- 批改页面同时展示作品版本和评价标准版本，禁止把最新标准误显示给旧作品。

### REQ-13 实时课堂状态

- 学生提交事务成功后通过已认证 WebSocket 推送状态变化，并以周期性全量查询校准漏消息、重连和多标签页状态。
- 新提交只局部更新对应学生及人数，不得自动切走教师当前正在批改的学生。
- 状态模型至少包含未进入、已进入、作答中、已提交待批、已批改、退回重交：打开题目页面后为“已进入”，第一次保存答案/草稿或上传临时作品后为“作答中”，正式提交后为“已提交待批”。
- 统一状态能力应同时接入所有相关教师页面，而不是只改操作题批改页；至少覆盖教师首页/课程入口、成绩或提交列表、操作题批改页和教师端学生桌面。
- 推送频道必须按学校、课程和班级授权隔离；断线后自动重连并全量校准，不得把 WebSocket 消息本身作为成绩事实来源。
- 统一状态首轮同时覆盖教师首页课程卡片、成绩/提交列表、操作题批改页和教师端学生桌面；课程设计器仍只负责备课，不承担课堂实时监管。
