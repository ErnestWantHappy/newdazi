## 已查实的问题

1. **编辑器代理路径断裂。** 正式 `/cryptpad/integration/` 返回的 HTML 请求 `/customize/pre-loading.js`、`/components/requirejs/require.js` 等根路径；这两个根路径实测 HTTP 200 但类型为 `text/html`，内容是平台页面。带 `/cryptpad/` 前缀的 RequireJS 才返回 JavaScript。单个入口脚本可达无法启动编辑器。
2. **两种分组互相污染。** `ClassGroupingService.generateSnapshotAuto → generateScheme → saveScheme` 写通用方案；`ClassGroupingMapper.selectDesktopStudents` 读取班级最新方案，因此协作创建可能改变大屏分组。
3. **页面承诺与后端冲突。** 协作页提示可随时重分组，保存却总传 `regroup=true`，后端发现活动引用就拒绝；当前唯一约束只允许一课一班一个快照，也不支持保留多轮分组。
4. **设计器多选状态无法完整回显。** 前端保存前有 `materialIds`，重载时却只从单个 `materialId` 恢复，页面显示的文件池不是已验证的持久业务事实。修复时将任务分配集中在工作台，避免两处配置互相误导。
5. **初始化成功判断不足。** 编辑页未等待 `CryptPadAPI` 返回的初始化 Promise，且以出现 iframe 判定就绪；还需核对编辑器替换容器的行为，正确报告真实初始化失败。
6. **更新说明与实现不一致。** 已通过教师登录读取正式平台更新共 62 条；1.30.3 的“文档秒级加载”“分组仅保存在当前课”与本轮证据不符，需追加明确更正，保留发布历史。

- CryptPad 对外主/沙箱地址须与上述 123 入口一致；WebSocket 和下载链路不能继续回传 129 地址。实施前形成具体候选配置、备份及回滚材料，保留主域/沙箱隔离，不能禁用安全检查绕过报错。
- 编辑页正确等待初始化完成，统一可读报错、超时和重试；就绪前不得显示已保存成功。
- 优先在隔离验收房间完成打开、两人编辑、保存、刷新和重新进入测试；不向真实学生作品写测试文字。

### 阶段二：分组按课程、班级和轮次隔离

- 协作生成和保存直接管理课程协作快照，禁止通过通用班级方案保存；协作快照的来源方案字段可为空，固定组只服务课堂大屏。
- 推荐兼容扩展现有课程快照的轮次，历史数据归入首轮，按快照 ID 读取历史；替换一课一班唯一约束为包含轮次的唯一约束。具体 SQL 必须先核对正式表结构、引用、重复数据，再备份迁移。
- 协作活动使用自身快照 ID 绑定小组；草稿组员与任务在同一事务中验证和保存，禁止先成功分组、后失败建房留下半成品；重复提交应返回同一结果。
- 学生开始后冻结该轮分组；新轮次生成独立分组和文档副本，旧轮次保留。当前入口只引导到当前轮次的本人小组，历史作品在明确的历史入口查看，不能自动混列全班房间和多轮房间。
- 手动调整必须拒绝外班成员、重复成员和遗漏成员；教师查看范围、学生跨组/跨班拒绝保持服务端校验。
- 审计历史协作自动生成的通用方案；只能依据引用关系和固定方案证据精确恢复大屏来源，不按名称批量删除，不改历史协作文档。

### 阶段三：统一工作台

- 课程卡片的“在线协作”直达工作台；单班自动选中，多班可切换。

- 配置面板统一完成自动分组、手动调人、每组文件选择；显示保存后的真实成员，不仅核对组数。
- 旧全班房间放入历史入口；设计器只保留开关与工作台入口，不保留未完整持久化的文件多选池和第二套分组流程。
- 常规课程一道计分操作题的规则维持原状；非计分协作文件不占用计分题名额。

## 完成标准

1. 教师与两名同组学生实际打开并共同编辑，保存后重新进入内容保留；旧文档也可打开。
2. 不同组使用不同文件或相同模板时，文档副本互不串写；跨组、跨班、跨校访问被拒绝。
3. 修改课程 A 的分组，不影响课程 B 和课堂大屏固定组；切换班级后也无串组。
4. 学生开始前可改组；开始后新建轮次，旧分组和作品可追溯，学生当前入口明确。
5. 重复保存、部分建房失败可恢复；不生成学生答案或协作成绩。
6. 单测/构建、接口及上述专项浏览器闭环通过后才发布，保留上一 release 和配置备份；无关工具回归结果逐项记录。
