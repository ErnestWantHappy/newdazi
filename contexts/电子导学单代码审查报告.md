## 二、严重缺陷（必须修复）

### BUG-01 [严重] 删除导学单时未级联删除答案记录

- **位置**：[GuideSheetServiceImpl.java:130-138](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/service/impl/GuideSheetServiceImpl.java#L130-L138)
- **问题**：`deleteBizGuideSheetBySheetIds` 方法只删除了 `assignment` 和 `progress` 子表，但**未删除 `biz_guide_sheet_answer` 表中的答案记录**。这导致：
  1. 孤儿记录残留在数据库中
  2. 答案表的唯一约束 `uk_student_sheet (student_id, sheet_id)` 会阻止同一学生对重新创建的导学单作答
- **建议修复**：
  ```java
  // 在删除 assignment 和 progress 之前添加：
  for (Long sheetId : sheetIds) {
      guideSheetAnswerMapper.deleteBySheetId(sheetId);  // 需新增此方法
  }
  ```

### BUG-02 [严重] 学生端 formJson 泄露 AI API Key 和评分配置

- **位置**：[GuideSheetController.java:190-206](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/controller/GuideSheetController.java#L190-L206)
- **问题**：`getStudentGuideSheet` 接口直接返回完整的 `formJson` 给前端学生端，其中包含 `_aiApiKey`、`_aiProvider`、`_scoringConfig`（含参考答案）等敏感字段。学生可以通过浏览器开发者工具直接查看所有题目的参考答案和 AI API Key。
- **建议修复**：在返回给学生的 formJson 中过滤掉 `_aiApiKey`、`_aiProvider`、`_aiModel`、`_aiCustomUrl`、`_scoringConfig` 字段。

### BUG-03 [严重] 关闭导学单无状态校验，草稿可直接关闭

- **位置**：[GuideSheetController.java:170-174](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/controller/GuideSheetController.java#L170-L174) 和 [GuideSheetServiceImpl.java:229-235](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/service/impl/GuideSheetServiceImpl.java#L229-L235)
- **问题**：`close` 接口和 `closeGuideSheet` 服务方法**均未校验当前状态是否为 '1'（已发布）**，草稿（status='0'）也能被关闭。对比 `publish` 接口有完整的三重校验。
- **建议修复**：在 Controller 或 Service 层添加 `if (!"1".equals(existing.getStatus())) return error("仅已发布状态的导学单可以关闭")`。

### BUG-04 [高] checkbox 多选"部分给分"计算逻辑错误

- **位置**：[GuideSheetGradingService.java:466-496](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/service/GuideSheetGradingService.java#L466-L496)
- **问题**：`gradePartialCheckbox` 方法中，`correctAnswer` 参数经过上游 `snapshotAnswerToString` 已将 `List` 类型合并为逗号分隔字符串（如 `"A,B,C"`），传入 `gradePartialCheckbox` 后走入 `else` 分支：`correctList.add(normalize(correctAnswer))` → 得到 `["A,B,C"]` 仅一个元素。学生选择 `["A","B"]` 后，`correctList.contains("A")` 返回 `false`，学生得 0 分。
- **建议修复**：在 `gradePartialCheckbox` 中，当 `correctAnswer` 为字符串时，按逗号分割：
  ```java
  } else {
      String normalized = normalize(correctAnswer);
      if (normalized.contains(",")) {
          for (String part : normalized.split(",")) {
              correctList.add(part.trim());
          }
      } else {
          correctList.add(normalized);
      }
  }
  ```

### BUG-05 [高] 导学单详情接口无访问控制

- **位置**：[GuideSheetController.java:99-104](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/controller/GuideSheetController.java#L99-L104)
- **问题**：`GET /{sheetId}` 接口**无任何权限注解**，任何登录用户可直接通过 ID 访问任意导学单详情（包括私有导学单）。列表接口有 `is_public = 'Y' or creator_id = currentUserId` 过滤，但详情接口完全没有。
- **建议修复**：在 `getInfo` 方法中校验可见性——若不是公开且非创建者本人，返回错误。

## 三、中等缺陷（应尽快修复）

### BUG-06 [中] 心跳接口缺少学生-导学单归属校验

- **位置**：[GuideSheetController.java:294-326](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/controller/GuideSheetController.java#L294-L326)
- **问题**：`heartbeat` 接口不校验学生是否属于该导学单的指派班级。恶意学生可以为任意导学单发送心跳，污染进度数据。
- **建议修复**：查询 `biz_guide_sheet_assignment` 确认该学生的 entryYear 和 classCode 是否被指派到该导学单。

### BUG-07 [中] 导出功能 N+1 查询问题

- **位置**：[GuideSheetController.java:370-383](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/controller/GuideSheetController.java#L370-L383)
- **问题**：`export` 方法对每个 answer 循环调用 `bizStudentMapper.selectBizStudentByStudentId()`，100 个答案 = 101 次数据库查询。
- **建议修复**：批量查询学生信息——先收集所有 studentId，一次查询所有学生，再用 Map 做匹配。

### BUG-08 [中] 学生端缺少评分结果查看功能

- **位置**：[student/guideSheet/index.vue:170-188](RuoYi-Vue3/src/views/student/guideSheet/index.vue#L170-L188)
- **问题**：后端已实现 `GET /student/grading/{sheetId}` 接口返回评分详情，但**前端学生端完全没有"查看评分详情"的 UI 入口**。学生提交后只看到"已提交"标签，无法查看各题得分和 AI 评语。
- **建议修复**：在学生端添加"查看评分结果"按钮，展示总分和各题得分详情。

### BUG-09 [中] 前端发布错误提示被静默吞掉

- **位置**：[index.vue:231-235](RuoYi-Vue3/src/views/business/guideSheet/index.vue#L231-L235)
- **问题**：`handlePublish` 的 `.catch(() => {})` 空回调导致发布失败时**不显示任何错误信息**（如"表单内容为空"、"未指派班级"等）。用户只能看到发布按钮没反应。
- **建议修复**：在 catch 中提取后端返回的错误消息并 show：
  ```javascript
  .catch((err) => { ElMessage.error(err?.msg || err?.message || '发布失败') })
  ```

### BUG-10 [中] 看板 `classCode` 格式兼容性脆弱

- **位置**：[dashboard.vue:718-735](RuoYi-Vue3/src/views/business/guideSheet/dashboard.vue#L718-L735)
- **问题**：`assignedClassCodes` 可能是数组也可能是逗号分隔字符串，但设计器保存时存储的是 `List<String>`（序列化为 JSON 数组），看板按字符串 split 只是为了兼容历史数据。这种双格式兼容容易在边界情况下出错。
- **建议修复**：统一数据源——通过运行数据修复脚本将旧数据统一为 JSON 数组格式，前端仅处理数组格式。

### BUG-11 [中] 已关闭导学单的前端操作逻辑不一致

- **位置**：[index.vue:76-84](RuoYi-Vue3/src/views/business/guideSheet/index.vue#L76-L84)
- **问题**：
  - 已关闭（status='2'）导学单的操作列中，只有非本人创建的导学单隐藏"设计"按钮
  - 已关闭导学单仍显示"预览"、"看板"、"引用"按钮（这些对于已关闭导学单意义不大）
  - 文档规定"已关闭不显示发布"，但关闭按钮在已关闭状态下也不应显示
- **建议修复**：为 status='2' 的导学单仅保留"预览"和"引用"按钮，隐藏"发布"和"关闭"。

### BUG-12 [中] 你设计器 `bannedWidgets` 与评分字段类型矛盾

- **位置**：[designer.vue:670-682](RuoYi-Vue3/src/views/business/guideSheet/designer.vue#L670-L682)
- **问题**：`bannedWidgets` 包含 `'color'`（颜色选择器），意味着设计器侧边栏不显示该组件。但 `scoreableTypes` 中也包含 `'color'`（可评分字段）。这意味着颜色选择器被禁用（设计器不展示），却在评分配置中是"可评分"的——逻辑矛盾。
- **建议修复**：要么从 `bannedWidgets` 中移除 `'color'`，要么从 `scoreableTypes` 中移除 `'color'`。

## 四、轻微问题（优化建议）

### OPT-01 [低] 建表 SQL 缺少评分字段定义

- **位置**：[biz_guide_sheet.sql:42-60](RuoYi-Vue/sql/biz_guide_sheet.sql#L42-L60)
- **问题**：`biz_guide_sheet_answer` 的 CREATE TABLE 语句缺少 `total_score`、`grading_status`、`grading_detail` 三个字段。这些字段是通过后期手动执行 ALTER TABLE 添加的。新人部署时如果只执行此 SQL，会导致代码报错。
- **建议修复**：将三个评分字段加入 CREATE TABLE 语句中。

### OPT-02 [低] 班级指派表字段类型过大

- **位置**：[biz_guide_sheet.sql:32-33](RuoYi-Vue/sql/biz_guide_sheet.sql#L32-L33)
- **问题**：`entry_year` 和 `class_code` 使用 `varchar(255)`，但实际值仅为 4 位年份和 1-2 位数字，严重浪费索引空间。
- **建议修复**：改为 `varchar(20)`。

### OPT-03 [低] 看板 ECharts 实例未响应窗口 resize

- **位置**：[dashboard.vue:571-711](RuoYi-Vue3/src/views/business/guideSheet/dashboard.vue#L571-L711)
- **问题**：`barChart`、`completionPie`、`accuracyPie` 三个 ECharts 实例未绑定 `window.resize` 事件，窗口缩放时图表不变形，造成布局异常。
- **建议修复**：在 `onMounted` 中添加 `window.addEventListener('resize', handleResize)` 并在 `onBeforeUnmount` 中移除。

### OPT-04 [低] 学生端页面关闭时 sendBeacon Content-Type 问题

- **位置**：[student/guideSheet/index.vue:255-258](RuoYi-Vue3/src/views/student/guideSheet/index.vue#L255-L258)
- **问题**：`navigator.sendBeacon` 使用 `Blob` 发送时需手动指定 Content-Type 为 `application/json`，否则后端 `@RequestBody` 可能解析失败。当前 `Blob` 构造函数只传了 `type: 'application/json'` 作为第二个参数，这个是正确的。但需要确认后端是否有相应的 CORS/CSRF 配置处理 `sendBeacon` 请求。
- **建议修复**：服务端确认 `/dev-api/business/guide-sheet/student/submit` 已放开 CSRF 保护。

### OPT-05 [低] 设计器组件轮询间隔过短

- **位置**：[designer.vue:1718-1721](RuoYi-Vue3/src/views/business/guideSheet/designer.vue#L1718-L1721)
- **问题**：每 2 秒轮询调用 `refreshScoredFields()` 和 `ensureTabWidget()`，在高频拖拽操作时可能造成不必要的计算开销。
- **建议修复**：改为 5 秒轮询，或在 form-json-change 事件中延迟触发。

### OPT-06 [低] 看板全部班级模式默认隐藏所有班级数据

- **位置**：[dashboard.vue:289-298](RuoYi-Vue3/src/views/business/guideSheet/dashboard.vue#L289-L298)
- **问题**：`activeClassSet` 计算属性仅统计"有至少1人提交"的班级，且 `activeList` 在全部班级模式下只显示活跃班级的学生。对于刚发布但无人提交的新导学单，看板完全空白。
- **建议修复**：全部班级模式下显示所有班级的所有学生（含未开始）。

### OPT-07 [低] 预览页无权限控制

- **位置**：[preview.vue](RuoYi-Vue3/src/views/business/guideSheet/preview.vue)
- **问题**：预览页路由设置了 `roles: ['teacher', 'researcher', 'admin']`（仅教师等角色），但没有后端数据层校验——任何人猜中 sheetId 都能调用 `/business/guide-sheet/{sheetId}` 接口获取内容。
- **建议修复**：详见 BUG-05。

### OPT-08 [低] 进度查询无分页

- **位置**：[GuideSheetProgressMapper.xml:54-92](RuoYi-Vue/ruoyi-business/src/main/resources/mapper/business/GuideSheetProgressMapper.xml#L54-L92)
- **问题**：`selectFullProgressBySheetAndClass` 和 `selectFullProgressBySheetId` 无分页限制。对于大班级（如全校统考），可能返回数千行数据。
- **建议修复**：添加分页参数或在 Service 层分页。

### OPT-09 [低] AI 评分线程池使用守护线程

- **位置**：[AiGradingService.java:48-51](RuoYi-Vue/ruoyi-business/src/main/java/com/ruoyi/business/service/AiGradingService.java#L48-L51)
- **问题**：线程工厂设置 `t.setDaemon(true)`，这意味着 JVM 关闭时排队中的 AI 评分任务会被静默丢弃。
- **建议修复**：使用非守护线程，或在 Spring `@PreDestroy` 中优雅关闭线程池（`executor.shutdown(); executor.awaitTermination(30, SECONDS)`）。

### OPT-10 [低] 进度查询 SQL 复杂度高

- **位置**：[GuideSheetProgressMapper.xml:54-72](RuoYi-Vue/ruoyi-business/src/main/resources/mapper/business/GuideSheetProgressMapper.xml#L54-L72)
- **问题**：`selectFullProgressBySheetAndClass` 使用 `INNER JOIN` 两个表的 COLLATE 强制转换 + 三表 LEFT JOIN + SQL `CASE WHEN` 拼接 JSON。查询复杂度较高，耗时随数据量线性增长。
- **建议修复**：考虑将 COLLATE 问题在数据层面统一（统一所有表的字符集排序规则），或在应用层拼接 JSON。

## 五、代码质量与架构优化

### ARCH-01 [建议] 后端缺少全局异常处理

- **问题**：Controller 中多处手动 try-catch 并返回 `error("...")`，Service 层异常直接抛出。缺少统一的 `@ControllerAdvice` 全局异常处理器。
- **建议**：添加全局异常处理，统一错误响应格式，减少重复代码。

### ARCH-02 [建议] 评分配置存储策略可简化

- **问题**：当前评分既存 `widget.scoring` 又存 `_scoringConfig` 快照（文档中 6.1 节描述的策略）。这种双写模式增加了维护复杂度。既然快照以 label 为 key 更稳定，可以考虑**仅使用 `_scoringConfig` 快照**作为唯一数据源，不再维护 `widget.scoring`。
- **影响**：可简化 `getFormJsonString()`、`extractScoredFields()`、`extractScoredFieldsPreserveConfig()` 三个函数的逻辑。

### ARCH-03 [建议] 前端状态管理混乱

- **问题**：`designer.vue` 中 `scoringConfig` 使用 `reactive({})` 管理，`keywordInput` 也用 `reactive({})`，`scoredFields` 用 `ref([])`。三种响应式方式混合使用，导致 `forceUpdate` 类操作（如 `sheetList.value = [...sheetList.value]`）频繁出现。
- **建议**：统一使用 Pinia store 管理评分配置状态，减少 reactive/ref 混合使用。

### ARCH-04 [建议] 缺少 API 请求去重/防抖

- **问题**：学生端每 30 秒自动保存 + 心跳上报，看板每 5 秒刷新数据。在弱网环境下，多个请求可能同时排队，造成不必要的服务端压力。
- **建议**：使用 `AbortController` 在发起新请求前取消上一个未完成的同类型请求。
