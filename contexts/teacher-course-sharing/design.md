# 教师首页共享课程与学生导航设计

## 服务端

- 教师首页 DTO 增加 `creatorName`、`canDesign`、`canDelete`、`deleteBlockReason`，能力随课程列表一次返回。
- 本人创建课程允许设计；是否允许删除由学生答案和导学单绑定历史决定。
- 共享课程固定不可设计、不可删除，班级列表在服务层与教师负责班级求交集。
- 删除流程先执行课程管理权校验，再执行答案/导学单历史门禁。

## 前端

- 教师首页只按服务端能力渲染操作。共享课程显示类型和创建教师；本人不可删除课程显示禁用按钮与原因。
- 学生布局把 `AppMain` 的溢出恢复为 `visible`，解除对页面内 sticky 顶栏的限制。保留页面现有 `position: sticky; top: 0`，不改为 fixed，避免新增遮挡和补偿间距。

## 兼容性

- 不改数据库结构，不引入依赖。
- 后端与前端应配套发布；若只发布前端，旧接口没有能力字段会使本人课程操作入口缺失。

## 2026-09-02 第二阶段只读课程内容设计（已确认）

- 新增独立的共享课程只读详情 DTO/接口，不复用课程设计器的可编辑详情接口，避免因前端按钮遗漏而越权修改。
- 服务端授权条件为：同校、当前教师负责至少一个课程指派班级、课程未被权限规则排除；返回的班级范围仍只包含负责班级与指派班级的交集。
- 课程一旦通过上述规则共享，课程内已引用题目全部可见，不再按题目的公有/私有属性二次过滤；未被课程引用的私人题目不随课程开放。
- DTO 明确返回 `canViewContent=true`、`canDesign=false`、`canDelete=false`，前端进入专用只读页，只提供查看课程结构、题目与成绩的入口。
- 题目答案、评分标准和起始材料的展示范围应以“完成代课、查看学生任务所必需”为原则；下载能力、教师参考答案等敏感字段在接口级使用白名单 DTO，后续实现前再逐项复核。
