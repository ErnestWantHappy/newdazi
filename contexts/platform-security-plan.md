# 平台账号与安全规划（简版）

> 版本：v1.1　日期：2026-08-17　状态：规划稿，尚未修改代码、数据库或生产配置。

## 一、统一密码标准

- 普通用户至少 **12 位**；管理员、教研员至少 **14 位**；最长 64 位。
- 至少包含大写字母、小写字母、数字、特殊字符中的三类。
- 禁止使用姓名、手机号、学号、学校名、平台名、连续字符、键盘序列和常见泄露密码。
- 新建、导入、改密、重置全部使用同一套后端校验；不能只靠前端提示。
- 密码只能使用 BCrypt/Argon2id 哈希保存，禁止明文、可逆加密和写入日志。
- 学生使用一次性临时激活码，首次登录必须改成个人强密码。
- 改密、重置、角色变化、禁用后，立即注销该账号全部旧会话。

## 二、账号分类

| 账号 | 要求 |
|---|---|
| 管理员 | 强密码 + 强制 MFA + 仅管理网访问 |
| 教研员 | 强密码，建议 MFA，按授权学校/区域访问 |
| 教师 | 强密码，只能访问本人学校和任教班级 |
| 学生 | 临时激活码 + 首次改密，只能访问本人和当前课程 |
| 服务账号 | 不允许网页登录，单服务单账号，独立密钥 |
| 运维账号 | 与业务账号分离，操作留痕，按需授权 |

禁止共用管理员、教师、数据库和运维账号。

## 三、登录与会话

- 登录失败按账号、IP、设备组合限流，并逐步增加验证码和等待时间。
- 错误提示统一，不泄露“账号不存在”还是“密码错误”。
- 禁止前端保存可还原密码；“记住我”最多保存账号名。
- 过渡期缩短 Token 有效期；目标是 HttpOnly、Secure、SameSite Cookie + CSRF 防护。
- 管理员、教研员强制 MFA；教师在高风险操作时进行二次验证。
- 登录、改密、重置、锁定、解锁、MFA 和异常访问必须审计，日志不得记录密码、Token、Cookie。

## 四、权限与网络边界

- 后端权限是唯一依据，前端菜单不能代替鉴权。
- 数据按“学校 → 课程 → 活动 → 班级 → 小组 → 设备”逐级隔离。
- 学生网络不能访问数据库、Redis、Druid、Swagger、Nginx 管理入口和 Broker 管理接口。
- MQTT 设备只使用按学校/课程/实验/小组/设备生成的短期凭据和 Topic ACL。

## 五、密钥和配置

- JWT、数据库、Redis、MQTT、AI、SSH 等密钥不得进入 Git、前端包、日志或普通配置文件。
- 生产密钥从服务器受控环境注入；本地、测试、生产不得复用。
- 密钥泄露后必须立即吊销并更换，不能只删除文件。
- 发布采用新版本目录，保留上一版和备份，支持快速回滚。

## 六、实施顺序

1. **先做密码基线**：统一 `PasswordPolicy`，清理默认密码、明文凭据、前端 RSA 私钥和记住密码。
2. **再做边界防护**：外置生产密钥，增加限流、审计、安全响应头和管理网限制。
3. **最后做增强认证**：迁移 HttpOnly 会话、启用 MFA，并评估接入教育局 OIDC/LDAP/AD。

## 七、上线验收

- 所有创建、导入、改密、重置路径都拒绝弱密码。
- 源码、JAR、前端构建包、日志和配置中无密码、Token、私钥。
- 跨学校、跨班级、跨学生访问得到 403；匿名访问得到 401。
- 密码或角色变化后旧会话立即失效。
- 学生网无法访问管理入口，MQTT TLS 和 Topic 权限可验证。
