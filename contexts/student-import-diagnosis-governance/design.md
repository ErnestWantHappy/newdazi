# 学生导入与诊断治理设计

## 导入链路

`Excel 解析 → 全量字段规范化/文件内去重 → 批量查询有效账号 → 计算一次初始密码哈希 → 每 200 条批量写用户 → 回查用户 ID → 批量写角色与学生档案 → 去重补教师班级 → 事务提交`

- 锁键为学校部门 ID，值为随机 UUID，TTL 10 分钟；释放使用 Lua 比较值后删除。
- 格式错误和已存在账号在事务写入前形成失败明细；进入写库的合法行必须全部成功或全部回滚。
- 返回 DTO 包含总数、成功数、失败数以及解析、校验、密码、数据库、总耗时。成功/失败明细各最多展示 20 条，学生姓名按 HTML 转义。
- `sys_user(user_name, del_flag)` 普通索引服务批量 `IN` 查重，同时兼容软删除同名账号；并发收敛依赖同校锁和写后回查，不改变现有软删除语义。

## 诊断分级

- 学生导入慢接口：小于 10 秒为提示，10～30 秒为关注，30 秒及以上为严重。
- 阈值未达、必选项未选、课程资源已被删除等已知预期结果为 `business/info`。
- 未识别异常默认为 `system/critical`；不能按整个学生管理 URL 统一降级。
- `sys_perf_event` 保留原表结构，读取历史记录时动态重算分类、等级和建议。

## 幂等与回滚

- 删除不存在课程返回 0，由控制器转换为“课程已删除或不存在”；现存课程继续执行管理权、答题和导学单保护。
- 手动推进逐班收集 `ServiceException` 为失败清单；未知异常停止处理并上抛。
- 应用回滚切回旧 JAR/前端；数据库索引用独立 rollback SQL 删除，不修改业务数据。
