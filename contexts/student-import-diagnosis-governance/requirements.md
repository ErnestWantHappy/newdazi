# 学生导入与诊断治理需求

## 背景

2026-09-01 正式环境出现多条学生导入严重慢接口，最大 37.316 秒；同时课程重复删除和手动推进阈值未达被误标为严重故障。用户选择方案 B：完整治理，初始要求先修改本地代码；本地验收完成后又明确授权部署正式服务器。

## 验收需求

1. 学生导入不再逐行计算密码、逐行查重和逐行写库；50、200、420 行均能返回结构化数量与分阶段耗时。
2. 同校并发导入只允许一个执行；用户、角色、学生档案、教师班级关系任一写入失败时整批回滚。
3. Excel 内重复、已有账号和格式错误在写库前识别；结果明细有上限，避免大弹窗卡顿。
4. `sys_user` 查重有可回滚联合索引，迁移包含前检、后检和 `EXPLAIN`。
5. 已知业务条件未满足不计为严重系统故障；未知数据库或系统错误仍保持严重。
6. 课程重复删除幂等；手动推进未达条件返回正常业务结果。
7. 正式发布必须先整库备份并核对哈希，再执行索引迁移、切换新 release、探活、浏览器冒烟和发布登记；后续用户已明确授权并完成该流程。

## 非目标

- 不更换技术栈、不引入消息队列或新依赖。
- 不修改默认初始密码规则、用户软删除模型或核心权限模型。
- 不清理历史操作日志或性能事件；历史事件按新规则动态回显。
