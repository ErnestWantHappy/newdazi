# 小学实验板物联网一页操作单

## 上课前

1. 教师进入课程的“物联网”页面，确认课程已开启并选择对应实验。
2. 按小组复制“**小学 Python 代码**”，投屏或发给对应小组。代码中的 WiFi 名称和密码只在实验板本地填写，平台不会保存。
3. 学生运行代码后，看到“连接成功/发送成功”再开始实验。

代码已包含平台 Broker、端口、班级账号、课堂口令、ClientID 和本组 Topic。不要手工改动账号、口令或 Topic；需要换组时重新复制对应小组代码。

## 课堂中

- 教师物联网页面查看小组数据和最近消息；学生页面只显示本人小组数据。
- 初中掌控板继续使用“Mind+ 参数”页签，小学实验板使用“Python 代码”页签。
- 需要重新生成口令时，教师执行“重试/轮换口令”，旧连接会被断开，学生重新复制代码后运行。

## 故障判断

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| 代码提示 WiFi 失败 | 实验板未连上无线网络 | 检查本地 WiFi 名称、密码和信号，平台不接收 WiFi 凭据 |
| WiFi 成功但 MQTT 连接失败 | Broker 地址或课堂配置不可用 | 回到平台重新复制本组代码；教师检查班级卡片是否为“已同步” |
| 连接成功但发布被拒绝 | 账号、Topic 与班级/小组不匹配 | 不要改 Topic，重新复制当前小组代码；跨班 Topic 会被 Broker 拒绝 |
| 教师页面暂时无数据 | 尚未发布、网络延迟或页面未刷新 | 让学生再次运行发布；刷新页面并查看最近消息时间 |
| 口令轮换后旧代码失效 | 旧连接已按安全策略踢下线 | 复制新代码并重新运行实验板 |

仍无法恢复时，记录小组、时间、页面提示和实验板串口日志，交由平台管理员检查；不要在聊天或截图中发送课堂口令。

## 安全边界

- 每个班级账号只能访问本班 Topic 前缀，跨班发布和订阅会被 Broker 拒绝。
- 不使用临时探针账号，不把 Broker 管理地址、密钥或课堂口令写入公共文档。
