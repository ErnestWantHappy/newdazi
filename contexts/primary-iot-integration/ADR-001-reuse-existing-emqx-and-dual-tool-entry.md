# ADR-001：小学实验板复用现有EMQX与班级物联模型

## 状态

拟采纳，待用户确认开发（2026-08-31）

## 背景

小学信息科技实验板外形和编程工具均不同于初中掌控板。省平台示例通过 `mqtt.config(server, projectId, userId)` 封装连接，其后端认证和项目运行机制闭源，无法可靠本地部署。

现场真板已经证明：实验板固件可直接使用标准 `umqtt.simple.MQTTClient`，显式设置自定义账号、密码、ClientID和完整Topic；并已完成正式129 EMQX到123平台数据库闭环。因此硬件差异只影响“如何生成和展示连接代码”，不要求建立新的消息平台。

## 决策

1. 小学实验板复用现有EMQX、班级账号、课堂口令、小组Topic、平台接收器、数据库和实时页面。
2. 初中继续使用Mind+，小学新增N17 Python代码生成；同一页面使用明确页签，不依赖自动猜测学段。
3. 不部署省平台，不使用其 `userId/projectId` 认证模型，不新增Broker或端口。
4. 正式推广前先补齐EMQX内置数据库授权源，回填每班精确ACL，并移除现有 `class_* → county/#` 宽规则。
5. 引入Broker同步状态，只有账号和ACL均同步成功后才向教师和学生下发可运行配置。
6. 本期默认一组一块板，ClientID使用全局唯一groupId生成；多板同组后续走设备登记模式。

## 备选方案

### 方案B：小学独立Broker和业务模块

拒绝。会复制账号、Topic、入库、实时推送和页面，形成两套运维与数据孤岛。

### 方案C：桥接或仿制省平台

拒绝。省平台后端认证和项目激活机制闭源，依赖外网，无法形成可维护、可审计的县级正式系统。

### 方案D：只在前端增加Python复制按钮，不修Broker授权

拒绝作为正式方案。虽然功能最少，但当前生产文件ACL仍给 `class_*` 整个 `county/#` 权限，扩到更多学校前必须先关闭跨班数据污染风险。

## 后果

### 正面

- 不新增基础设施、端口和消息表，开发与运维成本最低。
- 小学和初中数据在同一课程/班级/小组模型中统一展示。
- 现有真板和平台闭环证据可直接作为技术基线。
- 精确ACL修复同时提升现有初中链路安全性。

### 代价

- 上线前必须完成存量账号ACL回填和初中回归，不能只改页面。
- 需要处理数据库与EMQX之间的同步状态，避免半成功。
- 课堂口令轮换后必须主动断开旧客户端，增加一个管理API动作。

## 验证门禁

- 所有存量班级配置达到 `SYNCED`；
- 文件宽ACL已移除；
- 跨班/跨校发布与订阅被Broker拒绝；
- 小学真板连续运行与断网恢复通过；
- 初中Mind+回归通过；
- 临时测试账号删除。
