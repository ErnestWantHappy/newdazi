## 1. 退回重交：先修真正的状态链

1. 先以本地隔离课程分别复现文件作品和画程：教师退回后记录状态、旧分、学生按钮与上传/保存/提交响应；同时检查 Python 操作题是否已有独立重交逻辑。
2. 后端在 `ClassroomTaskStateController` 的退回入口核对当前作品与目标学生，避免对未提交题目写退回；将退回授权与该题的后续提交校验关联。普通作品入口在 `StudentHomeController` 的上传和正式提交两处使用相同授权判断，仍校验本人、当前课和题目归属。
3. 画程复用现有 `reopen` 建立新草稿；学生看到 `RETURNED` 时提供明确“修改并重新提交”入口，旧图直接带入新草稿。保持原提交版本、结构检查和成绩审计，不覆盖历史；并发窗口仍按修订号拒绝旧页面提交。
4. 新提交后更新 `biz_student_answer` 的当前作品和待批状态；教师批改页重新读取新版本。旧 AI 建议必须因版本变化失效，不能被批量采用。
5. 验收覆盖：普通文件、画程、课程补交窗口已过但教师明确退回、重复点击退回、跨班越权、双标签页冲突、旧分与新待批分离。若 Python 题实际受同一退回按钮覆盖，也补独立用例。

预计文件：`ClassroomTaskStateController.java`、`StudentHomeController.java`、`FlowchartService.java`、`StudentFlowchartDialog.vue`、`student/index.vue` 及相关定向测试。是否需要 SQL 以最终实现为准，优先复用现有 `RETURNED` 状态和作品版本表。

## 2. 画程：保持旧 JSON 可读的最小方案

1. 先固定旧图夹具：四种节点、旧左右锚点、折线拐点、文字位置、教师标准答案、学生草稿/提交，并记录当前结构判题结果。
2. 将默认画布高度调到适合课堂屏幕的范围；`fitView` 继续防止小图被过度放大，缩放按钮改为明确步长并设置上下限。缩放只是视图状态，不写入作品 JSON。
3. `terminal`、`process`、`inputOutput` 只提供上、下锚点，且 `x` 均等于节点中心。`decision` 保留四点。加载旧图时，把指向已删除左右锚点的连线映射到最近的上/下点，并重新计算端点与折线，避免旧作品断线。
4. 启用 LogicFlow 已有的节点缩放能力，不加新依赖；限制最小宽高和锁定/只读权限。平行四边形按实际宽高重新生成四角，斜边余量受限，允许横纵独立缩放。
5. 在现有 JSON 节点 `properties` 中加入可选宽高，前端 `schema.js` 与后端 `FlowchartDocumentService` 同步规范化。旧图缺尺寸时沿用文字布局；文字变化只扩大不足的尺寸，不覆盖手动缩放值。渲染器与结构判题继续使用相同坐标语义。
6. 用旧图与新图逐一验证添加、拖拽、连线、改字、缩放、撤销、保存、刷新、导出、学生提交、教师预览和判题；尤其检查旧左右连线与平行四边形缩放后端点是否贴边。

预计文件：`FlowchartEditor.vue`、`schema.js`、`layout.js`、`FlowchartDocumentService.java`、`FlowchartImageRenderer.java` 和相应前后端测试。推荐不升级表结构、不迁移旧作品；可选宽高方案需用户按 `AGENTS.md` 确认。

## 4. 打字统计：按查询学年的年级口径筛选

- 本轮已给打字统计页增加 1–12 年级下拉；学校汇总和班级明细共用 `grade` 参数。后端据查询学年换算 `entry_year`，并同时限定学校学段，避免不同学段的“一年级”混算。
- 清除年级时两个 SQL 均不增加条件，保持原汇总口径。学校分组切换只筛当前服务端结果，年级切换会自动定位相应学段；点击“查询”才刷新数据。
- 已完成 Mapper 定向测试和前端生产构建；仍需本地可用数据库和研究员页面检查具体学校的图表、班级明细及分页。不得把编译通过称为统计数值已核验。
- 本项不需要 SQL 迁移；本地后端重新编译并重启后接口新参数才生效，前端需重新启动或加载新构建。

## 5. 多模型视觉批改：先验证能力，再扩服务商

### 方案评选（需确认）

| 方案 | 核心思想 | 优点 | 代价与风险 |
| --- | --- | --- | --- |
| A 推荐：固定服务商与视觉模型白名单，分批接入 | 保留百炼，再选一家拥有图片输入和结构化 JSON 输出能力的服务商；每家固定端点、模型白名单和请求适配 | 能保留现有密钥加密、教师确认、费用快照与 SSRF 边界；容易逐家验收 | 每家需要适配和匿名样本测试；首轮不能覆盖“所有模型” |
| B 通用兼容地址 | 教师输入任意兼容接口地址、模型和 Key | 扩展速度快 | 服务端外连、提示词/学生图发送范围、模型能力与计费不可控，必须额外做地址白名单、DNS/重定向约束和能力探测 |
| C 仅扩百炼模型 | 沿用固定百炼端点，只扩视觉模型列表 | 改动与测试最少 | 不能满足其他服务商接入 |

推荐 A。第一批候选须以**视觉图片输入、JSON 输出稳定性、教师可取得 API Key**为门槛，不能因为某模型有文本免费额度就列入操作题视觉批改。新增模型前先用官方文档和教师账户控制台核实实际可用额度、地域、到期日、用完即停设置和费用；系统只展示理论估价，不自行声称“本次免费”。百炼官方说明新人额度按模型独立，额度到期/耗尽可能转按量付费，且免费额度需要符合地域与 Key 类型条件：<https://help.aliyun.com/zh/model-studio/new-free-quota>。火山方舟官方也提供免费体验/安心体验说明，但适用资格与模型仍须以账户当前控制台为准：<https://docs.volcengine.com/docs/undefined/1465347?lang=zh>。

### 首个新服务商的开发顺序

1. 固定 `providerCode/modelName/endpointUrl` 的可信组合。教师 Key 继续服务端加密、仅回显掩码；切换服务商不复用不相干的 Key。检查现有配置表能否按教师和服务商保存多组密文；若不能，形成增量 SQL 与可回退方案后再实施。
2. 从 `QwenPracticalVisionGradingProvider` 抽出少量共用的图片准备、输出契约校验与安全错误映射；保留各服务商自己的请求参数、响应读取和 host 白名单，避免一次大重构。
3. 教师设置弹窗按服务商显示可用视觉模型、Key 测试与费用口径。价格表维护服务商和模型对应关系，任务创建冻结选择，任务恢复继续用原任务的模型与价格，不因教师后来切换而漂移。
4. 取相同匿名作品及评分项跑盲测，记录 JSON 完整率、评分项缺失率、证据准确性、延迟和理论成本。单个模型失败保留逐份错误，不自动改用另一个模型，更不自动写正式成绩。
5. 后端定向测试覆盖 Key 加密、模型与端点白名单、图片限制、超时/限流/额度耗尽、结构化输出、任务恢复、旧任务兼容、价格快照；前端构建和教师模拟页面冒烟通过后才标记本机完成。

预计文件：`TeacherAiConfigService.java`、`PracticalVisionGradingProvider.java`、`QwenPracticalVisionGradingProvider.java`、`PracticalAiJobService.java`、`PracticalAiJobWorker.java`、价格/配置 Mapper 和 `teacher/grading.vue`。可能需要增量 SQL、服务商私密配置和后端重启；本轮不在服务器执行。
