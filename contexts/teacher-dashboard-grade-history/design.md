# 教师首页课程年级分栏与加载提速设计

## 1. 数据语义

- `biz_lesson.entry_year` 继续作为稳定届别锚点。
- `biz_lesson.grade` 明确作为课程开设年级，创建后不可修改。
- 当前年级仍由入学年份、学校学段和7月20日学年边界动态计算。
- 不新增课程年级字段，不复制已有事实。

## 2. 首页返回模型

首页核心接口继续返回届别分组，每门课程补充 `grade`。前端在每个届别内部按 `grade` 生成课程开设年级分栏，并始终补出当前年级空分栏。

批改状态从核心接口拆出为独立接口，按课程ID返回班级状态。核心课程到达后立即结束全页加载；批改状态和区域抽测入口并行补充。

课程指派班级由后端批量读取，避免每门课程单独查询。

## 3. 页面交互

- 届别标题显示“2024级（当前九年级）”。
- 当前年级分栏默认展开，包含“添加九年级课程”。
- 历史分栏显示课程数量并默认折叠；展开后展示全部卡片和“添加八年级历史课程”。
- 当前年级课程仍保留既有最新5门加“还有N节”的视觉收口；历史分栏点击展开后直接展示全部。
- 历史新增入口在跳转前提示目标为历史年级，设计器继续只读显示课次。

## 4. 课次与不可变边界

- 首页建议课次按目标开设年级筛选后取最大值加一。
- 服务端在新建且未提供有效课次时，按 `dept_id + creator + entry_year + grade` 取最大值加一。
- 保存已有课程时同时保留原 `entry_year` 和原 `grade`，请求尝试改变任一字段均拒绝。
- 推进候选在既有同校、同教师、同届别基础上再要求 `grade` 相同。

## 5. 性能与失败降级

- 首页核心数据、区域抽测入口、批改状态使用独立请求。
- 核心请求成功后立即渲染；辅助请求失败只影响对应入口或红点。
- 用首次激活门禁消除初次 `onMounted + onActivated` 双请求，后续重新激活正常刷新。
- 批改状态接口一期保留现有期限补偿语义，先从首屏阻塞链路移除；后续如仍慢，再将状态指标改为批量聚合。

## 6. 数据修正

增量 SQL 采用“前检断言—精确更新—后检断言”的幂等结构。只修正课程263～267，任何课程的学校、创建教师、届别、开设年级或原课次不符合预期时中止，避免根据标题或时间猜测2024级复杂历史顺序。
