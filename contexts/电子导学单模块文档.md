## 一、模块概述

电子导学单是面向课堂教学的交互式表单系统，支持教师通过可视化表单设计器创建导学单，配置自动评分规则，发布给学生填写并自动批改，并通过看板实时监控课堂进度。

### 模块定位

- **设计**：教师拖拽式组装表单（VForm3），配置评分规则
- **发布**：将导学单指派到指定班级
- **填写**：学生在线填写，支持断点续填、文件上传
- **评分**：自动评分（精确/包含/AI）+ 人工批改
- **监控**：看板展示班级进度与答题详情，支持数据导出

## 二、角色与核心流程

### 角色功能矩阵

| 角色 | 功能 |
|------|------|
| 教师 | 创建/编辑/删除导学单、表单设计器拖拽设计、评分配置、发布/关闭、教师看板（进度监控）、数据导出、评分管理 |
| 学生 | 查看当前导学单、表单填写（断点续填）、文件上传、提交答案、查看评分结果 |

### 核心流程

```
教师创建导学单 → 设计表单 → 配置评分规则 → 发布到班级 → 学生填写提交 → 自动评分 → 教师查看看板
```

### 导学单生命周期

```
新建（草稿 status=0）
  → 设计表单（VForm3 拖拽设计）
  → 配置评分（可选）
  → 发布（status=1）
  → 学生填写提交
  → 自动评分（可选）
  → 关闭（status=2）
```

## 四、数据库设计

### 4.1 核心表

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| biz_guide_sheet | 导学单主表 | sheet_id, sheet_title, form_json, status, creator_id, dept_id, is_public |
| biz_guide_sheet_assignment | 班级指派表 | assignment_id, sheet_id, entry_year, class_code, dept_id |
| biz_guide_sheet_answer | 学生填写记录表 | answer_id, sheet_id, student_id, answer_json, total_score, grading_status, grading_detail, status |
| biz_guide_sheet_upload | 多媒体上传记录表 | upload_id, answer_id, sheet_id, student_id, item_id, file_name, file_url, access_url |
| biz_guide_sheet_progress | 课堂实时状态表 | id, sheet_id, student_id, current_page, progress_detail, is_submitted, last_heartbeat |

### 4.2 状态字段约定

**导学单状态（status）**：`0` = 草稿，`1` = 已发布，`2` = 已关闭

**学生答案状态（answer.status）**：`1` = 填写中（草稿），`2` = 已提交

**评分状态（grading_status）**：

| 状态 | 含义 |
|------|------|
| auto | 全部自动评分完成 |
| partial | 部分自动 + 部分人工 |
| manual | 全部需要人工批改 |
| pending | 待评分 |

### 4.3 依赖表

| 表名 | 用途 |
|------|------|
| sys_user | 教师用户信息 |
| sys_dept | 学校/部门信息 |
| sys_role / sys_menu / sys_role_menu | 角色与菜单权限 |
| biz_lesson | 课程表（可选外键） |
| biz_student | 学生表（必须存在） |

### 5.4 自动评分引擎（GuideSheetGradingService）

评分流程：

```
1. 解析 formJson → 读取 _scoringConfig 快照
2. 解析 answerJson → 学生答案
3. flattenWidgets → 递归展平所有控件（跳过非真实控件）
4. 遍历每个控件 → 匹配评分配置 → 比对答案 → 计算得分
5. 去重 → 重新计算总分 → 返回 GradingResult
```

三种评分方式：

| 方式 | 标识 | 计分规则 |
|------|------|----------|
| 精确匹配 | exact | 与参考答案完全一致得满分 |
| 包含匹配 | contains | 按匹配关键词数量比例计分：(匹配数/总数)×分值 |
| AI 评分 | ai | 参考答案 + 学生答案发送大模型，AI 判断得分 |

> 注：正则匹配已完全移除，评分仅保留精确匹配、包含匹配、AI 评分三种方式。

### 5.5 AI 评分服务（AiGradingService）

- 多供应商适配：DeepSeek / 豆包 / 千问 / 智谱清言
- 线程池：核心 3 线程、最大 8 线程、队列 200、CallerRunsPolicy 背压策略
- 频率限制：同一学生 5 分钟内对同一导学单最多调用 3 次，超限转人工批改
- 评分提示词采用关键词分层评分：涵盖主要关键词→满分；部分关键词且意思基本正确→60%~80%；少量关键词且偏差较大→20%~50%；完全不相关→0 分

### 5.6 进度计算与看板

- 学生保存草稿时自动计算当前页填写进度（filled/total/fields）
- 看板通过 `assignment + student LEFT JOIN progress` 获取完整班级学生列表（含未开始学生），**不能仅查 progress 表**
- 已提交学生的评分详情通过 SQL `CASE` 拼接 JSON 返回

## 六、前端实现

### 6.1 路由配置

| 路由路径 | 组件名 | 说明 | 缓存 |
|----------|--------|------|------|
| /business/guide-sheet-list | GuideSheet | 列表页 | 是 |
| /business/guide-sheet/designer/:sheetId? | GuideSheetDesigner | 设计器 | 否(noCache) |
| /business/guide-sheet-dashboard/:sheetId? | GuideSheetDashboard | 看板 | 是 |
| /business/guide-sheet-preview/:sheetId? | GuideSheetPreview | 预览 | 否 |
| /student/guide-sheet | StudentGuideSheet | 学生端 | 否 |

> 路由 name 必须与组件 name 一致，确保 keep-alive 正常缓存。

### 6.2 导学单列表页（index.vue）

- 可见性过滤：仅显示公开（is_public='Y'）或当前用户创建
- 创建人信息直接用后端返回的 creatorName
- 已关闭状态不显示「发布」按钮
- onActivated 钩子触发刷新（配合 keep-alive）

### 6.3 导学单设计器（designer.vue）——核心

#### 标签页约束（HomeTab）

- 新建时默认包含唯一名称 HomeTab 的标签页，internal: true（不可删除/移动/拖拽）
- 所有组件自动嵌入 HomeTab 的活跃 tab-pane
- enforceHomeTabConstraints() 轮询兜底，防止序列化丢失 internal 标记

#### 表单初始化策略

- designerConfig 设置 resetFormJson: true，禁止 VForm3 从 localStorage 恢复旧内容，避免与业务侧异步 setFormJson 产生竞态导致空白页
- 使用 100ms 间隔轮询（最多 30 次）等待 designerRef 就绪，替代固定 setTimeout

#### 变更检测（替代失效事件）

- vform3-builds@3.0.10 的 @form-json-change 事件不触发（死代码，已移除）
- 改用 processFormState() + 1 秒轮询 getFormJson()，用 lastFormJsonStr 快照比较识别 widgetList 变化
- lastFormJsonStr 为空时不标记 dirty，避免首次加载误判

#### 评分配置

- 可评分字段类型：radio、checkbox、select、cascader、input、textarea、color
- 总分必须为 100，每个字段分值不能为 0
- AI 评分必须输入参考答案
- 评分配置通过 _scoringConfig 快照存储（以 label 为 key），因 VForm3 会丢弃自定义 scoring 属性

#### 图片上传 URL 修复

- fixUploadURLs() 自动修复 picture-upload 的 uploadURL 空值导致的 404

### 6.4 教师看板（dashboard.vue）

- 左侧班级选择 + 学生完成列表（带评分标签），右侧各页进度详情
- 每个学生一行，详情弹窗展示逐题批改（AI 题显示参考答案和评语）
- parseGradingDetail() 按 fieldKey 去重后累加总分

### 6.5 学生端（student/guideSheet/index.vue）

- 自动获取当前班级已发布导学单
- VForm3 渲染，多页 tab 切换
- 保存草稿（save，不触发评分）/ 提交（submit，触发评分）
- 实时心跳上报当前页，断点续填

## 七、关键设计决策

### 7.1 评分配置快照（_scoringConfig）

**问题**：VForm3 序列化/反序列化会丢弃自定义 scoring 属性。
**方案**：formJson 顶层维护 _scoringConfig（label → 配置），保存写入、加载评分优先读取；以 label 为 key 不受 VForm3 重分配 id/guid 影响。

### 7.2 控件展平去重

**问题**：flattenWidgets 递归时误将 options 配置对象当作控件，导致重复评分。
**方案**：isRealWidget() 检查（须含 formItemFlag/key/widgetList/tabs/category 之一）+ deduplicateDetailList() 按 fieldKey 兜底去重。

### 7.3 包含匹配比例计分

得分 = (匹配关键词数 / 总关键词数) × 该题分值，标签化关键词输入界面，逗号分隔存储。

### 7.4 AI 评分限流

5 分钟内同一学生同一导学单最多 3 次，超限转人工，用 ConcurrentHashMap + ConcurrentLinkedDeque 记录时间戳。

### 7.5 看板数据完整性

仅查 progress 表会缺未开始学生，须 assignment + student LEFT JOIN progress。

### 7.6 classCode 与字符集

前端传「1班」（带班后缀），DB 存纯数字，Controller 层 strip 后缀；JOIN 的 VARCHAR 字段 collation 不匹配时 SQL 显式指定 COLLATE。

### 7.7 路由与 keep-alive

路由 name 与组件 name 一致；设计页 noCache: true；移除导致卡死的 transition 包装。

## 八、数据流

### 8.1 学生提交流程

```
学生填写表单
  ↓ POST /student/submit { sheetId, answerJson, currentPage, action }
GuideSheetAnswerServiceImpl.submitAnswer()
  ├─ saveAnswer() → 保存答案 + 更新进度
  └─ gradingService.grade() → 自动评分
       ├─ 解析 formJson._scoringConfig
       ├─ flattenWidgets() → 展平控件
       ├─ 遍历控件匹配配置比对标答
       │    ├─ exact / contains / ai
       ├─ deduplicateDetailList() → 去重
       └─ 返回 GradingResult { totalScore, gradingDetail }
  ↓
更新 answer.gradingDetail + answer.totalScore
```

### 8.2 看板数据流

```
教师打开看板 → GET /progress?sheetId&classCode
  ↓ GuideSheetProgressMapper.selectFullProgressBySheetAndClass
assignment + student LEFT JOIN progress (+ answer 评分数据)
  ↓ 返回 List<GuideSheetProgressVo>
前端 dashboard.vue → parseGradingDetail() 去重累加 → 渲染
```

## 九、边界条件与约束

| 约束 | 说明 |
|------|------|
| 总分必须为 100 | 每字段分值不能为 0 |

## 十、迁移指南与注意事项

### 10.1 数据库迁移

按顺序执行 SQL：

| 序号 | 文件 | 说明 |
|------|------|------|

| 4 | sql/collation_fix.sql | 字符集统一（可选） |

依赖表：biz_student（必须）、biz_lesson（可选）需已存在。

### 10.2 后端迁移

- 复制 Controller / Service / Mapper / Domain 文件到 ruoyi-business 对应包
- 复制 5 个 Mapper XML 到 resources/mapper/business/
- 确认 BizStudentMapper、SysDeptMapper 存在

### 10.3 前端迁移

- 安装 `vform3-builds@^3.0.0`、`pinyin-pro` 依赖
- main.js 全局注册 VForm3 + image-add-widget 组件
- 复制页面组件、API 文件、自定义组件
- router/index.js 添加路由
- vite.config.js 确认 /dev-api 代理到 8080

### 10.4 菜单与权限

权限标识：business:guideSheet:list / add / edit / remove / design / dashboard / export

### 10.5 常见坑与注意事项

1. **设计器空白页**：VForm3 初始化异步，须轮询等待 designerRef 就绪；设置 resetFormJson: true 禁用 localStorage 恢复。
2. **HomeTab 约束**：internal: true，序列化可能丢失，需 enforceHomeTabConstraints 兜底。
3. **classCode 前后端不一致**：前端带「班」后缀，Controller strip。
4. **评分快照**：用 _scoringConfig + `id || name || guid` 查找逻辑。
5. **进度 JOIN**：assignment + student LEFT JOIN progress。
6. **AI 限流**：超限转人工。
7. **学生端安全**：返回前过滤 _scoringConfig、_aiApiKey 等敏感字段，递归移除 scoring 属性。
8. **路由 keep-alive**：设计页 noCache，路由 name 与组件 name 一致。
9. **字符集**：JOIN 字段 collation 不一致需显式 COLLATE。
10. **自定义组件**：需全局注册 + 注入 FieldPanel customFields（详见《自定义组件实现文档》）。
