## 二、P0 严重缺陷（必须立即修复）

| 编号 | 问题 | 严重度 | 影响 | 位置 |
|------|------|--------|------|------|
| BUG-01 | 删除导学单时未级联删除答案记录 | 严重 | 孤儿数据 + 唯一约束阻止新作答 | `GuideSheetServiceImpl.java` |
| BUG-02 | 学生端 formJson 泄露 AI API Key 和参考答案 | **严重安全漏洞** | 学生可查看所有题目的正确答案和创建者的 API Key | `GuideSheetController.java` |
| BUG-03 | 关闭导学单无状态校验，草稿可直接关闭 | 严重业务逻辑错误 | 状态流转不合法 | `GuideSheetController.java` + `GuideSheetServiceImpl.java` |
| BUG-13 | 列表接口也泄露 formJson 敏感信息 | 严重安全漏洞 | 任何能访问列表的用户都能看到 API Key 和参考答案 | `GuideSheetMapper.xml` |
| BUG-14 | 评分去重失败，同一字段多次评分 | 严重数据准确性 | 总分翻倍 | `GuideSheetGradingService.java` |

### 修复方案概要

- **BUG-01**：新增 `deleteBySheetId` 删除所有答案记录，先删子表再删主表
- **BUG-02**：新增 `sanitizeFormJsonForStudent` 过滤敏感字段，删除顶层 `_scoringConfig`、`_aiApiKey` 等，递归移除 widget 树中的 `scoring`
- **BUG-03**：在 Controller 和 Service 层都添加状态校验，仅已发布（status='1'）才能关闭
- **BUG-13**：列表查询 SQL 中移除 `form_json`，不查询敏感数据
- **BUG-14**：`walkFlatten` 中按 fieldKey 去重，避免同一 widget 被重复添加

## 三、P1 高优先级缺陷（应尽快修复）

| 编号 | 问题 | 影响 | 位置 |
|------|------|------|------|
| BUG-04 | checkbox 多选"部分给分"计算逻辑错误 | 正确答案多选，学生得 0 分 | `GuideSheetGradingService.java` |
| BUG-05 | 导学单详情接口无访问控制 | 私有导学单任何人都能查看 | `GuideSheetController.java` |
| BUG-06 | 心跳接口缺少学生-导学单归属校验 | 恶意学生可污染任意导学单进度 | `GuideSheetController.java` |
| BUG-07 | 导出功能 N+1 查询 | 100 学生需要 101 次查询，性能差 | `GuideSheetController.java` + `BizStudentMapper` |
| BUG-08 | 学生端缺少评分结果查看功能 | 学生提交后看不到各题得分和 AI 评语 | `student/guideSheet/index.vue` + `guideSheet.js` |

### 修复要点

- **BUG-04**：`gradePartialCheckbox` 中，当 `correctAnswer` 为字符串且含逗号时，按逗号拆分
- **BUG-05**：详情接口添加访问控制：公开导学单任何人可看，私有导学单仅创建者可看
- **BUG-06**：心跳接口检查该学生的班级是否被指派到该导学单
- **BUG-07**：批量查询学生 ID，一次查询所有学生，Map 匹配，修复为 2 次查询
- **BUG-08**：学生端添加评分结果展示区域，提交成功后自动拉取并展示

## 五、P3 优化建议

| 编号 | 问题 | 修复方向 |
|------|------|----------|
| OPT-01 | 建表 SQL 缺少评分字段定义 | 将 `total_score`、`grading_status`、`grading_detail` 加入 CREATE TABLE |
| OPT-02 | 班级指派表字段过大 | `entry_year` 和 `class_code` 从 `varchar(255)` 改为 `varchar(20)` |
| OPT-03 | 看板 ECharts 不响应窗口 resize | 添加 `window.resize` 事件监听，调用 `chart.resize()` |
| OPT-04 | 学生端 `sendBeacon` CSRF 确认 | 确保 `student/**` 路径在 CSRF 白名单中 |
| OPT-05 | 设计器轮询间隔过短（2秒） | 改为 5 秒轮询，降低计算开销 |
| OPT-06 | 看板全部班级模式只显示活跃班级 | 全部班级模式显示所有学生（含未开始） |
| OPT-07 | 预览页后端无权限校验 | 与 BUG-05 一并修复（详情接口已加可见性校验） |
| OPT-08 | 进度查询无分页 | 添加分页参数支持，最大 500 行 |
| OPT-09 | AI 评分线程池使用守护线程 | 改为非守护线程，添加 `@PreDestroy` 优雅关闭 |
| OPT-10 | 进度查询 SQL 复杂度高 | 统一数据库 COLLATE，移除 SQL 中强制 COLLATE 子句 |

## 十、修复后验证要点

修复完成后需验证以下场景：

1. **安全验证**：学生登录后，`GET /student/current` 返回的 `formJson` 中不含 `_scoringConfig`、`_aiApiKey` 等敏感字段
2. **列表验证**：列表接口返回的每条记录 `formJson` 为 `null`，不泄露敏感信息
3. **删除验证**：删除导学单后，`biz_guide_sheet_answer` 中无对应答案记录
4. **状态流转验证**：草稿无法直接关闭，必须先发布才能关闭
5. **评分验证**：checkbox 多选部分选中能正确给分，同一字段不会重复评分
6. **访问控制验证**：私有导学单非创建者无法通过 `GET /{sheetId}` 访问
7. **学生端验证**：提交后能看到评分结果和各题得分
8. **错误提示验证**：发布失败（无班级指派）能看到具体错误信息
