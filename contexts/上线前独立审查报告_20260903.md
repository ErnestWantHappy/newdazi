### P1（上线前修复）

#### P1-1 状态表迁移脚本未被 Git 跟踪，且 .gitignore 规则误伤整个 sql 目录
- 位置：`.gitignore:24-25`（`/?`、`/???`）；`sql/student_task_state_v1.sql`、`sql/student_task_state_v1_rollback.sql`（磁盘存在，`git check-ignore` 证实被忽略、未跟踪）；对照 `sql/class_grouping_v1.sql`、`sql/group_collaboration_v1.sql`（靠强制 add 才跟踪）。
- 问题：`/???` 通配任意 3 字符根目录名，恰好命中根目录 `sql/`，导致 sql 下所有新文件默认被 Git 静默忽略。两个状态表脚本因此不在提交里；同时发现大量已在生产执行过的历史脚本（如 `lesson_archive_status_v1.sql`、`research_activity_public_share_v1.sql`、`flowchart_operation_v1.sql`）也从未被跟踪。

- 最小修复：① `git add -f` 两个状态表脚本并提交；② 收窄忽略规则（如保留乱码匹配但加 `!sql/`，或改成精确的乱码文件名模式），用 `git status` 验证新 SQL 能正常出现；③ 历史缺跟踪脚本另建补齐任务，不阻塞本轮。

## 4. 教师使用体验（只列课堂高频场景，共 5 条）

1. **亮点（直接减少教学事故）**：新建课程不再默认勾选全部班级（`teacher/index.vue:784` 移除 classes 透传，已确认无其他入口再传），消除"没逐个取消就误布置到同年级所有班"这一最高频事故；课程设计器和题库列表都能直接预览画程题基础图，选题时不用再进编辑页。
2. **亮点（批改减负）**：五星辅助打分、分项清零、Enter 提交并跳下一位、分数全部服务端重算（`PracticalScoringPolicyService`，前端算分只作对照，篡改/陈旧请求会被拒）；"退回重交"有二次确认且原作品、原成绩保留可审计；批改页标注"作品 vN · 评分依据 vM（提交时）"，新旧标准不再混。
3. **会让教师误判课堂的问题**：学生桌面"终端视图"在生产 HTTP 下可能全员离线（P1-3）、"作业状态"恒显未进入（P2-1）。这类投屏到教室大屏的信息一旦错误，教师会错怪学生，上线前必须修复或先隐藏视图切换。
4. **会让教师以为系统坏了的断点**：小组协作向导要求"先冻结课时快照"，但界面上没有任何地方能做分组和冻结（P1-4）。务必本轮藏入口，不要把走不通的流程露给教师。
5. **实时状态总体可靠、一处小别扭**：批改页 WebSocket 增量+10 秒校准+乱序版本丢弃，且不打断教师正在批改的学生，思路稳；小别扭是学生被退回后重新提交，教师要手动再点一次该学生才能看到新作品（P2-7）。

## 6. 不建议做的事（本轮不要借"优化"之名扩张）

1. 不要新增配置页、新角色或新流程来承载分组：一个对话框+一个"冻结快照"按钮足够；本轮更推荐先藏入口。
2. 不要把状态写入并入学生主业务事务：当前 REQUIRES_NEW 独立事务+失败只告警是刻意设计，能保证状态表故障不拖垮交卷。
3. 不要先上新后端再补 SQL（批改页硬依赖状态表）；也不要先上新前端再上后端（预览 404、状态接口报错）。
4. 不要在服务器用 Navicat 等图形客户端执行含 `DELIMITER //` 的状态表脚本。
5. 不要给新表加外键（项目已有 IoT 外键并发教训），不要顺手重构协作/课程大模块，不要动旧 Vue2 目录，不要换技术栈。
6. 不要把 Presence 在线状态写入考勤或签到（在线≠到课，边界已在代码注释和页面文案中明确）。
7. 不要因为本机 localhost 测试通过就认为 Presence 可用——必须用 IP/HTTP 形态复测（P1-3）。
8. 不要删除旧 release、旧备份来腾空间；不要在本轮 git push 之外做任何分支保护/强推操作。
