# ADR-004：课程推进后仅当前课允许提交与退回

日期：2026-09-24。状态：用户已确认，本机候选未发布。

## 决定

班级课程指派一旦推进，旧课立即停止学生作答、上传和正式提交。教师只可对当前课发起退回；学生只可在当前课补交或重交。已保存的旧课答案、作品版本、成绩与退回状态保留供查阅和审计，不因规则切换删除。

## 原因

原15分钟窗口只在普通文件作品入口生效；理论与打字在事务内要求当前课，流程图和 Python 也要求当前课，造成同一课的提交口径不一致。用户明确选择统一拒绝旧课，且退回重交只属于正在上课的课程。

## 实现与边界

- 学生普通答案、文件上传与作品版本提交，画程工作区、草稿和正式提交都以本人学校、班级当前课程为准。教师退回先核对班级与学生，再锁当前指派行。文件版本与画程草稿、重开、正式提交写入也锁同一指派行，与推进操作排序。
- 理论、打字与 Python 原服务层当前课检查继续生效；理论开放开关与打字重做轮次规则不变。历史课程仍可按原权限查看、批改和统计。
- 取消 `student.submission-grace-minutes` 配置和旧课退回入口。课程推进与提交几乎同时到达时，以指派行锁决定先后；先完成的提交属于推进前，推进先完成则拒绝旧课。
- 不修改数据库结构，也不清理历史退回任务。应用回退可能恢复旧窗口行为，需按版本配套回退前后端。

## 验收

本机定向 Java 测试验证旧课拒绝、当前课准入及旧课退回拒绝；真实账号与数据库推进竞态、各题型和前端提示仍需隔离环境核对。
