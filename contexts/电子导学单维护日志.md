### 21:53 — 修复「图片展示」组件不在左侧面板显示（方案 2）

- **类型**：修复
- **问题**：自定义 `image-add`（图片展示）组件虽然被注入到 FieldPanel 的 customFields 数组中，但左侧「自定义扩展字段」标签页始终为空，组件未渲染。
- **根因**：VForm3 的 FieldPanel 在 `created()` 时通过**模块级 customFields 闭包**一次性构建左侧面板列表；`addCustomWidgetSchema` 是 UMD 闭包私有函数、未导出，外部无法再往里 push。此前直接给 `proxy.customFields` 重新赋值不会让 vuedraggable 的 `list` 响应变化。
- **改动**（`designer.vue` 的 `registerCustomImageWidget()`）：
  1. 补丁 FieldPanel 实例的 `loadWidgets()`：先跑原始 `loadWidgets()` 再追加 `image-add`，重建产生新数组引用，触发 vuedraggable 重渲染。
  2. 补丁 `proxy.i18n2t`：使渲染期生成的 item 文字显示「图片展示」。
  3. 补丁 `designer.getFieldWidgetByType`：使组件可被选中并渲染属性编辑器。
  4. 仅在 `image-add` 尚未进入列表时触发一次重建 + `$forceUpdate()`，避免每秒轮询重复刷新。
- **结果**：vite 转换文件返回 200 无编译错误，待浏览器硬刷新验证。

### 21:18 — 对比分析两种修复方案

- **类型**：方案决策
- **内容**：对比「方案 1（创建期注入，FieldPanel 渲染前写入模块级 customFields 闭包）」与「方案 2（运行时注入 FieldPanel 实例的局部响应式数组 + 触发 vuedraggable 重建）」。
- **结论**：推荐方案 2；方案 1 的障碍是 customFields 及 addCustomWidgetSchema 为 UMD 闭包私有、无外部访问入口；方案 2 需解决「定位当前可见 FieldPanel 实例」和「确保 vuedraggable 响应数组变化」两个问题，且符合工程既有多处 VForm3 内部 hack 的风格。

### 21:17 — 测试确认组件未渲染并定位根因

- **类型**：问题定位
- **现象**：进入导学单设计页，点击「自定义扩展字段」标签页，标签页为空；FieldPanel 实例的 `proxy.customFields` 含 2 个 `image-add` 条目，但实际渲染 0 个 `.field-widget-item`。
- **根因**：vuedraggable 的 list 绑定未响应挂载后的数组变化，且可能存在 HMR/keep-alive 产生的旧 FieldPanel 实例干扰。

### 20:13 — 确认「图片展示」组件版本与来源

- **类型**：调研

### 20:02 — 首次实现「图片展示」组件注册

- **类型**：功能修复

### 18:40 — 清理事件死代码，重建变更检测机制

- **类型**：重构
- **问题**：`@form-json-change="onFormJsonChange"` 是死代码，VForm3 v3.0.10 的 designer.umd.js 无 `$emit('form-json-change')`，导致 dirty 标记、maxPages 更新失效。
- **改动**：
  1. 移除死绑定，将 onFormJsonChange 替换为 processFormState()。
  2. 用 1 秒轮询 getFormJson() + lastFormJsonStr 快照比较实现变更检测。
  3. resetToNewForm / loadSheet / loadSheetAsTemplate 中重置 lastFormJsonStr 为空串，防止首次加载误判 dirty。
  4. 清理 formJsonVersion、autoRenameWidgets、pinyinCounters 等死代码，轮询间隔 5 秒→1 秒。

### 10:30 — 定位设计页空白根因（localStorage 竞态）

- **类型**：问题定位
- **问题**：项目重启后进入设计页面经常空白。
- **根因**：VForm3 的 localStorage 自动恢复机制与业务侧异步轮询加载的表单内容产生竞态，陈旧结构先渲染后被覆盖，中间状态渲染失败。
- **改动**（`designer.vue`）：设计器配置添加 `resetFormJson: true`，禁止 VForm3 从 localStorage 恢复旧内容，使表单内容完全由业务侧 setFormJson 控制。
