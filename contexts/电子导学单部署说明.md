# 电子导学单 v2 部署说明

电子导学单 v2 采用“模板—课程绑定快照—学生答卷”三层模型。模板库不再负责班级指派和发布；课程保存后，导学单直接继承课程的学校、入学年份和班级编号范围。

## 重要变更

- `biz_guide_sheet` 是纯模板表，保存标题、年级、学期、课次、县域公开范围、版本、归档状态和 VForm3 内容。
- `biz_lesson_guide_sheet_binding` 保存课程与模板之间的不可变快照。一门课程最多一条当前绑定，关闭开关只停用，不删除绑定和历史成绩。
- 答卷、进度和上传全部按 `binding_id` 隔离。同一模板被多门课程使用时，同一学生会形成互不影响的答卷。
- 导学单成绩保持独立，不计入普通课程总分、平均分、排名或现有成绩比例。
- 学生存在未完成区域抽测时，区域抽测仍优先于日常课程和电子导学单。
- 默认创作入口为三步快速向导，生成结果仍是完整兼容的 VForm3 `formJson`；高级模式和旧模板继续使用同一数据结构。
- `biz_guide_sheet_draft` 只保存教师创作草稿，不参与课程发布、学生访问或课程快照。

## 数据清理范围

开发者已确认无需迁移旧电子导学单业务数据。`sql/guide_sheet_v2_template_binding.sql` 首次执行时只会删除并重建以下旧表：

- `biz_guide_sheet`
- `biz_guide_sheet_assignment`
- `biz_guide_sheet_answer`
- `biz_guide_sheet_progress`
- `biz_guide_sheet_upload`

`sql/guide_sheet_beginner_mode.sql` 不删除或重建任何 v2 业务表，只新增教师草稿表、学生草稿版本字段和上传幂等键，并对历史导学单操作日志中的正文、答卷和旧 AI 密钥痕迹做不可逆脱敏。

两段脚本都不会修改普通课程、课程题目、课程班级指派、普通学生答卷、普通课程成绩或区域抽测表。旧导学单上传文件可能成为磁盘孤儿，本迁移不会删除文件，需由运维人员在确认备份后另行清理。

## 部署顺序

1. 安排维护窗口并停止旧版后端，确保迁移期间没有导学单写入。
2. 完成全库备份，并单独备份上述五张旧导学单表。
3. 记录受保护表的 `COUNT(*)`、最小 ID 和最大 ID，至少包含：
   - `biz_lesson`
   - `biz_lesson_assignment`
   - `biz_lesson_question`
   - `biz_student_answer`
   - `biz_county_exam`
   - `biz_county_exam_answer`
4. 在目标 MySQL 8 数据库执行 `sql/guide_sheet_v2_template_binding.sql`。
5. 检查 `biz_guide_sheet_migration` 中 `guide_sheet_v2_template_binding` 的状态为 `DONE`，并核对五张 v2 表及课程绑定表。
6. 紧接着执行 `sql/guide_sheet_beginner_mode.sql`。该脚本会输出受保护表的 `BEFORE` / `AFTER` 基线；任一数量或 ID 边界变化都会以 `SIGNAL SQLSTATE '45000'` 中止部署。
7. 核对新手模式字段、默认值和索引，确认受保护表的 `count_delta` 全为 `0`、孤儿绑定数为 `0`，并确认外键 `fk_lesson_guide_sheet_binding_lesson` 已建立。
8. 在 `RuoYi-Vue` 目录执行 `mvn -pl ruoyi-admin -am -DskipTests clean package`，必须保留 `clean`，避免已删除的旧 Mapper 资源残留在产物中。
9. 部署并启动新版 Java 后端。
10. 构建、部署 `RuoYi-Vue3`，清理浏览器旧缓存后验收教师端和学生端。

两个迁移脚本缺一不可，顺序固定为 `guide_sheet_v2_template_binding.sql` → `guide_sheet_beginner_mode.sql`。不要在 v2 表结构上启动旧后端，也不要在执行迁移前启动新后端。MySQL DDL 会隐式提交，不能把本迁移理解为单事务原子操作。

## 全新数据库

全新数据库先导入项目选定并完成凭据检查的基础库脚本，再执行仍适用的非导学单增量脚本，最后按固定顺序执行：

1. `sql/guide_sheet_v2_template_binding.sql`
2. `sql/guide_sheet_beginner_mode.sql`

不要把旧 `sql/guide_sheet_v1.sql` 作为新库最终导学单结构，也不要在 v2 脚本之后再次执行 v1。若基础库已包含旧导学单表，v2 首次迁移会按既定范围重建；若不包含，脚本也会直接创建 v2 表。

## 重复执行与失败恢复

迁移脚本使用 `biz_guide_sheet_migration` 完成标记保护新数据：

- 未完成时重跑，会再次清理可能残留的导学单 v2 半成品表并重新建表。
- 已标记 `DONE` 后重跑，只执行 `CREATE TABLE IF NOT EXISTS`，不会再次删除 v2 业务数据。
- 如果执行中断，保持服务停止，查明错误后重跑脚本；不要先开放写入。
- v2 成功后再重跑新手模式脚本是安全的；草稿表、字段和索引均幂等，历史日志脱敏也只会处理仍命中敏感特征的记录。

## 新手模式数据结构

| 对象 | 默认值或索引 | 业务语义 |
| --- | --- | --- |
| `biz_guide_sheet_draft.revision` | `DEFAULT 1` | 教师创作草稿的单调版本号 |
| `biz_guide_sheet_draft.draft_status` | `DEFAULT 'D'` | `D` 编辑中，`C` 已完成 |
| `uk_guide_sheet_draft_owner_key` | `(owner_id, client_draft_key)` 唯一 | 同一教师的同一客户端草稿键只对应一份草稿 |
| `idx_guide_sheet_draft_owner_status` | `(owner_id, draft_status, update_time)` | 支持按当前教师恢复最近草稿 |
| `idx_guide_sheet_draft_sheet` | `(sheet_id)` | 支持模板保存后关联、完成或清理对应创作草稿 |
| `biz_guide_sheet_answer.draft_revision` | `DEFAULT 0` | 学生端自动保存的单调版本号 |
| `biz_guide_sheet_upload.client_upload_id` | `DEFAULT NULL` | 兼容迁移前记录；新上传必须传非空幂等键 |
| `uk_guide_sheet_upload_idempotent` | `(binding_id, student_id, client_upload_id)` 唯一 | 同一课程快照、学生和客户端上传请求不会重复落库；MySQL 允许历史 `NULL` 值共存 |
| `fk_lesson_guide_sheet_binding_lesson` | `lesson_id` → `biz_lesson.lesson_id`，更新和删除均 `RESTRICT` | 有当前或历史导学单绑定的课程不能被物理删除 |

教师草稿的 `owner_id` 必须由登录态取得，读取、保存和完成都同时使用 `owner_id + client_draft_key`。更新必须携带服务端最近返回的 `revision` 并通过 CAS；版本冲突时提示刷新或合并，不能用旧页面覆盖新内容。

课程删除前的 Service 历史检查用于返回教师可理解的提示，数据库外键则封住“历史检查刚完成、另一请求并发创建绑定、随后课程被物理删除”的竞争窗口。迁移会先检查孤儿绑定，存在 `lesson_id` 找不到课程的记录时以 `SIGNAL` 中止，禁止为通过迁移而直接删除历史绑定。

## 县域公开权限

- 县域边界由后端从 `sys_dept.ancestors` 解析首个非零组织根节点，禁止硬编码县域、学校或部门 ID。
- 公开模板只对同一县域教师可见；私有模板只对创建者可见。
- 公开仅表示可筛选、预览和选择，不授予编辑、归档或成绩查看权限。
- 公共模板作者不能查看其他教师课程的学生答卷或成绩。

## 课程绑定与快照

- 课程首次选择模板时，后端复制标题、年级、学期、课次、`formJson`、页数、评分配置和预览所需信息。
- 普通课程保存不会刷新已有快照；模板后续修改或归档不影响已绑定课程。
- 更换模板时，旧绑定转为历史记录，新绑定保存最新模板快照；旧答卷继续归属旧 `binding_id`。
- 关闭电子导学单只设置当前绑定为停用；重新开启时恢复原绑定和学生进度。

## 学生访问顺序

后端按以下顺序裁决访问：

1. 校验登录学生身份和所属学校。
2. 检查是否存在未完成区域抽测；存在时阻断日常课程及导学单写入。
3. 按学校、入学年份和班级编号查询当前课程指派。
4. 校验课程当前绑定且开关已开启。
5. 仅返回绑定快照的学生脱敏版本，移除参考答案、评分配置和 AI 敏感字段。

学生端默认显示日常课程题目；有有效绑定时显示“日常课程题目 / 电子导学单”切换，两部分可自由切换且不要求先后提交。

学生表单响应采用服务端白名单重建，只保留学生渲染所需的组件、选项和表单配置。参考答案、分值规则、AI 提示词、自定义事件、JavaScript、数据源表达式和内部字段不得依赖前端隐藏；富文本必须经过 HTML 清洗，未知或危险组件降级为不可执行的说明组件，损坏 JSON 返回安全空结构并记录不含正文的告警。

## 上传与文件访问

- 上传前同时校验登录学生、当前 `binding_id`、课程班级范围、区域抽测阻断状态以及字段确为当前快照中的上传组件。
- 服务端校验文件大小、扩展名、MIME 类型和文件头；原始文件名只作展示，存储路径由服务端生成并规范化。
- 客户端必须提交 `clientUploadId`，后端按唯一索引处理重试，禁止因自动保存或网络重试产生重复上传记录。
- 新文件保存在 `${ruoyi.profile}-private/guide-sheet`。这是 `ruoyi.profile` 的同级私有目录，例如配置为 `D:/ruoyi/uploadPath` 时实际根目录为 `D:/ruoyi/uploadPath-private/guide-sheet`，不在静态 `/profile/**` 映射内。数据库只存相对路径，访问 URL 由服务端生成，不得信任客户端提供的教师机 IP、Host 或 URL。
- 部署前创建私有目录并授予 Java 服务账号读、写和创建子目录权限；禁止将该目录额外配置为 Nginx、IIS 或 Spring 静态资源目录。数据库备份必须与此目录及仍需保留的历史 `ruoyi.profile/upload/guide-sheet` 文件在同一维护窗口备份，恢复时保持记录与文件版本一致。
- 学生文件只允许通过 `/business/guide-sheet/student/uploads/{bindingId}/{clientUploadId}` 读取本人记录；教师只允许通过 `/business/guide-sheet/uploads/{uploadId}/content` 并携带入学年份、班级参数读取精确管班范围内的记录。
- 历史 `/profile/upload/guide-sheet/**` 静态直链由安全配置拒绝，通用资源下载和预览接口也拒绝导学单历史路径。历史文件若仍存在，只能由上述专用接口完成身份、`binding_id` 和数据范围校验后读取。

## 成绩查询

教师从课程成绩页进入“电子导学单成绩”看板。入口只在后端确认当前课程已开启绑定且教师有权管理所选班级时显示，并锁定：

- 课程 ID
- 绑定 ID
- 入学年份
- 班级编号

课程创建者只能查看该课程实际指派的班级；管班教师必须拥有精确的学校、入学年份和班级授权。模板作者身份不产生任何成绩权限。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `GUIDE_SHEET_AI_PROVIDER` | `deepseek` | `deepseek`、`doubao`、`qwen`、`zhipu` 或 `custom` |
| `GUIDE_SHEET_AI_API_KEY` | 空 | 为空时 AI 题自动降级为人工处理 |
| `GUIDE_SHEET_AI_MODEL` | 供应商默认值 | 可选模型覆盖 |
| `GUIDE_SHEET_AI_BASE_URL` | 供应商默认值 | 自定义供应商必须配置 |
| `GUIDE_SHEET_WS_ALLOWED_ORIGINS` | 仅本机开发地址 | 课堂 WebSocket 允许的精确 Origin，多个值用英文逗号分隔 |
| `GUIDE_SHEET_HELPER_ENABLED` | `false` | 是否启用教师机文件服务 |
| `GUIDE_SHEET_HELPER_PORT` | `5000` | 教师机文件服务端口 |

生产环境必须把 `GUIDE_SHEET_WS_ALLOWED_ORIGINS` 配置为实际教师端和学生端站点的精确 `http://` 或 `https://` Origin，禁止使用 `*`，也不要填写 URL 路径。反向代理同时需要透传 WebSocket Upgrade 请求。

AI 密钥只允许从服务端环境注入，不得写入数据库、前端存储、接口响应或日志。新手向导的 AI 内容只返回待教师审阅的草稿，不直接保存、不自动发布，也不覆盖教师已有内容；教师确认后才进入普通草稿保存流程。AI 未配置、超时或调用失败时只提示“AI 服务暂不可用”，普通编辑、自动保存、模板保存和课程使用必须保持可用，不能把 AI 错误显示成保存失败。教师机服务不可达时，普通表单填写和保存仍应可用，相关文件能力按配置降级。

单个后端实例对 AI 创作请求执行“每名教师 10 秒一次、全局最多 4 个并发”的快速保护。多实例生产部署还必须在 API 网关或 Redis 增加共享限流，不能把进程内限制当作县域总额度；外部供应商侧同时配置预算、配额和超时告警。

## 操作日志脱敏

新手模式迁移会把历史导学单操作日志中含 `formJson`、`answerJson` 或旧 `_aiApiKey` 特征的请求参数和响应正文替换为固定脱敏内容。该处理不可逆，执行前如有合规留存要求，应将数据库备份存入受控审计介质；禁止为了恢复调试正文而把备份重新导入生产库。上线后的日志切面也不得再记录完整表单、完整答卷、教师机地址、AI 密钥或供应商响应正文。

## 回滚注意事项

v2 迁移删除旧导学单数据且表结构不兼容旧代码。回滚必须同时：

1. 停止新服务。
2. 恢复迁移前备份的五张旧导学单表；新手草稿、v2 期间新增答卷、绑定和私有上传文件如需留档，应先连同 `${ruoyi.profile}-private/guide-sheet` 另行导出，不能混入旧表。
3. 回退 Java 后端和 Vue 前端到旧版本。
4. 处理 v2 专用绑定表和迁移标记：恢复整库备份时沿用备份中的状态；仅恢复五张旧表时，必须先备份并隔离或移除 `biz_lesson_guide_sheet_binding`，解除其课程外键，再在确认旧表恢复完成后删除 `guide_sheet_v2_template_binding = DONE` 这一条标记。不能只删标记而不恢复旧表。
5. 核对普通课程、普通成绩和区域抽测数据未发生变化后再开放服务。

再次前滚时重新停止旧服务并备份，确认旧表已恢复且上述 `DONE` 标记不存在，再依次执行 v2 主迁移和新手模式迁移，然后部署同版本前后端。若保留错误的 `DONE` 标记，v2 脚本会跳过旧表重建；若只删除标记却仍运行 v2 服务，下一次执行会删除现有 v2 数据。不能只回退代码，也不能只操作迁移标记。
