# 电子导学单功能文档

> 最后更新：2026-07-08

---

## 一、功能概述

电子导学单是面向教师和学生的教学辅助工具，支持教师通过可视化表单设计器创建导学单，配置自动评分规则，发布给学生填写并自动批改。

### 核心流程

```
教师创建导学单 → 设计表单 → 配置评分规则 → 发布到班级 → 学生填写提交 → 自动评分 → 教师查看看板
```

### 主要角色

| 角色 | 功能 |
|------|------|
| 教师 | 创建、设计、编辑、发布、关闭导学单；查看看板/统计 |
| 学生 | 查看已发布的导学单、填写、保存草稿、提交 |

| 状态 | 含义 |

### 4.4 自动评分引擎 (`GuideSheetGradingService`)

#### 评分流程

```
1. 解析 formJson → 读取 _scoringConfig 快照
2. 解析 answerJson → 学生答案
3. flattenWidgets → 递归展平所有控件（跳过非真实控件）
4. 遍历每个控件 → 匹配评分配置 → 比对答案 → 计算得分
5. 去重 → 重新计算总分 → 返回 GradingResult
```

#### 评分方式

| 方式 | 常量 | 计分规则 |
|------|------|----------|
| 精确匹配 | `exact` | 学生答案与参考答案完全一致得满分 |
| 包含匹配 | `contains` | 按匹配关键词数量比例计分：(匹配数/总数)×分值 |
| AI 评分 | `ai` | 将参考答案和学生答案发送至大模型，AI 判断得分 |

#### 控件展平 (`flattenWidgets`)

`flattenWidgets` 方法递归遍历 `formJson.widgetList` 树，提取所有真正的控件对象：

- 递归遍历所有嵌套的 Map 和 List
- 使用 `IdentityHashMap` 防止循环引用
- `isRealWidget()` 检查：必须包含 `formItemFlag`、`key`、`widgetList`、`tabs` 或 `category` 之一，防止误将 `options` 配置对象当作控件
- 评分完成后 `deduplicateDetailList()` 按 `fieldKey` 去重，重新计算总分

#### 评分配置快照 (`_scoringConfig`)

由于 VForm3 设计器在序列化/反序列化过程中会丢弃自定义的 `scoring` 属性，后端采用**快照机制**：

- 保存时：前端在 `formJson` 顶层写入 `_scoringConfig` 对象，以控件 `label` 为 key 存储评分配置
- 评分时：优先从 `_scoringConfig` 快照读取（按 label 匹配），回退到 `widgetList[].scoring`（按 id 匹配）

### 4.5 AI 评分服务 (`AiGradingService`)

#### 多供应商适配

支持以下 AI 供应商：

| 供应商 | 配置项 |
|--------|--------|
| DeepSeek | API Key + 模型名称 |
| 豆包 (Doubao) | API Key + 模型名称 |
| 千问 (Qwen) | API Key + 模型名称 |
| 智谱清言 (GLM) | API Key + 模型名称 |

#### 线程池配置

- 核心线程数：3
- 最大线程数：8
- 队列容量：200
- 拒绝策略：`CallerRunsPolicy`（背压策略，调用线程执行任务）

#### 频率限制

同一学生在 5 分钟内对同一导学单最多调用 AI 评分 3 次，超限后转为人工批改。

#### 评分提示词

采用关键词匹配分层评分策略：
- 涵盖主要关键词、意思正确 → 满分（100%）
- 匹配部分关键词、意思基本正确 → 60%-80%
- 匹配少量关键词、意思偏差较大 → 20%-50%
- 完全不相关 → 0 分

### 4.6 进度计算 (`GuideSheetAnswerServiceImpl`)

学生填写/保存草稿时，后端自动计算当前页面的填写进度：

```json
{
  "filled": 3,
  "total": 5,
  "fields": {
    "field1": true,
    "field2": false,
    "field3": true
  }
}
```

- 递归遍历 `formJson.widgetList` 找到对应 tab-pane 页
- 收集该页所有字段名（name 属性）
- 跳过纯容器类型（tab、tab-pane、grid、card 等）
- 比对 `answerJson` 中对应字段是否有值

### 4.7 看板数据查询

看板通过 `GuideSheetProgressMapper.selectFullProgressBySheetAndClass` 查询：

- 使用 `biz_guide_sheet_assignment` + `biz_student` LEFT JOIN `biz_guide_sheet_progress` 获取完整班级学生列表
- 包含未开始的学生（progress 表中无记录也显示）
- 已提交学生的 `progressDetail` 通过 SQL `CASE` 拼接评分详情 JSON：
  ```sql
  CONCAT('{"type":"grading","totalScore":', COALESCE(ans.total_score, 0),
         ',"details":', COALESCE(ans.grading_detail, '[]'), '}')
  ```

### 5.3 导学单设计器 (`designer.vue`)

核心功能最复杂的页面，集成了 VForm3 可视化表单设计器。

#### 标签页约束（HomeTab）

- 新建表单时默认包含唯一名称为 `HomeTab` 的标签页组件
- `HomeTab` 设置 `internal: true`，确保不可删除、不可移动、不可拖拽
- 所有其他组件必须自动嵌入 `HomeTab` 的第一个 `tab-pane` 内
- `enforceHomeTabConstraints()` 轮询兜底，防止 VForm3 序列化/反序列化时剥离 `internal` 标记
- 每次新建表单时，设计器重置为仅含 `HomeTab` 标签页的空白状态

#### 新增字段自动命名

- `autoRenameWidgets()`：为新增字段设置中文标签（如"单选1"、"多选2"）和拼音唯一名称
- 使用 `pinyin` 库生成拼音名称，防止重复

#### 评分配置

- 可评分字段类型：`radio`、`checkbox`、`select`、`cascader`、`input`、`textarea`、`color`
- 评分方式：精确匹配、包含匹配、AI 评分
- 精确匹配：学生答案与参考答案完全一致才得分
- 包含匹配：关键词标签输入界面，支持逐个添加/删除关键词，按匹配比例计分
- AI 评分：需输入参考答案，支持多供应商配置（DeepSeek/豆包/千问/智谱清言）
- 总分必须为 100，每个字段分值不能为 0
- 启用评分时，AI 评分方式必须输入参考答案
- 评分开关启用后，AI API Key 配置区显示

#### 评分配置快照 (`_scoringConfig`)

- 保存时：`getFormJsonString()` 递归遍历所有控件，嵌入 `scoring` 属性，并在顶层写入 `_scoringConfig` 快照（以 `label` 为 key）
- 加载时：`extractScoredFieldsPreserveConfig()` 优先从 `_scoringConfig` 快照恢复（label 匹配），回退到 `w.scoring`
- 快照使用 label 作为 key，不受 VForm3 重分配 id/guid 影响

#### 图片上传 URL 修复

- VForm3 默认 `uploadURL` 为空字符串导致上传请求 404
- `fixUploadURLs()` / `fixUploadURLsInPlace()` 自动修复为 `/dev-api/common/upload`

#### 保存逻辑

- 保存草稿（`handleSave`）：调用 `addGuideSheet` 或 `updateGuideSheet`，状态为 `0`
- 保存并发布（`handleSaveAndPublish`）：先保存为草稿，再调用 `publishGuideSheet`
- 返回（`goBack`）：有未保存修改时自动保存后返回，无修改直接返回
- 保存前校验：`validateScoringTotal()` 检查总分是否为 100、每个字段分值不为 0

### 5.4 教师看板 (`dashboard.vue`)

#### 布局

- 左侧：班级选择器 + 学生完成情况列表（带评分标签）

## 六、关键技术决策

### 6.1 评分配置快照策略

**问题**：VForm3 设计器在序列化/反序列化过程中会丢弃自定义的 `scoring` 属性。

**方案**：在 `formJson` 顶层维护 `_scoringConfig` 快照（label → 配置），保存时写入，加载和评分时优先读取。label 作为 key 不受 VForm3 重分配 id/guid 影响，保证了评分配置的稳定性。

### 6.2 控件展平去重

**问题**：`flattenWidgets` 递归遍历时，控件的 `options` 配置对象（包含 `name` 和 `type` 字段）会被误判为独立控件，导致同一字段评分两次。

**方案**：
1. 添加 `isRealWidget()` 检查——必须包含 `formItemFlag`、`key`、`widgetList`、`tabs` 或 `category` 之一
2. 添加 `deduplicateDetailList()` 兜底去重——按 `fieldKey` 去重并重新计算总分

### 6.3 包含匹配计分

**问题**：简单的包含匹配过于粗糙，无法反映学生掌握程度。

**方案**：按关键词数量比例计分——
- 教师以逗号分隔输入关键词列表
- 提供标签化关键词输入界面，支持逐个添加/删除
- 得分 = (学生答案匹配的关键词数 / 总关键词数) × 该题分值

### 6.4 AI 评分频率限制

**问题**：学生可能频繁提交触发 AI 评分，造成 API 费用和服务器压力。

**方案**：同一学生在 5 分钟内对同一导学单最多调用 AI 评分 3 次，超限后转为人工批改。使用 `ConcurrentHashMap<String, ConcurrentLinkedDeque<Long>>` 记录调用时间戳。

### 6.5 看板数据完整性

**问题**：仅查询 `progress` 表无法获取未开始的学生。

**方案**：使用 `biz_guide_sheet_assignment` + `biz_student` LEFT JOIN `biz_guide_sheet_progress`，确保所有被指派班级的学生都出现在列表中（含未开始的学生）。

### 6.6 年级计算逻辑

**问题**：不同入学年份的学生属于不同年级。

**方案**：`calculateEntryYear()` 根据当前日期计算入学年份（7 月 20 日后为当前年份，之前为去年），用于年级匹配。

### 6.7 classCode 统一处理

**问题**：前端传"1班"（带"班"后缀），数据库存储纯数字，不同表 JOIN 时 VARCHAR 字段 collation 不匹配。

**方案**：
- 后端 Controller 层统一 strip "班" 后缀
- SQL 中显式指定 `COLLATE` 解决 `utf8mb4_general_ci` vs `utf8mb4_0900_ai_ci` 不匹配

### 6.8 路由名称与组件名一致性

**问题**：路由名称与组件 name 不一致导致 `<keep-alive>` 无法正确缓存，`onActivated` 不触发。

**方案**：路由 `name` 必须与组件 `name` 属性保持一致（如 `GuideSheet`、`GuideSheetDashboard`）。

### 6.9 过渡动画移除

**问题**：`<transition mode="out-in">` 因看板组件根节点非单一元素导致过渡卡死，返回列表页时页面空白。

**方案**：移除 `<transition>` 包装，保留 `<keep-alive>` 缓存机制。

## 七、数据流图

### 7.1 学生提交流程

```
学生填写表单
  ↓
POST /student/submit { sheetId, answerJson, currentPage, action: "submit" }
  ↓
GuideSheetAnswerServiceImpl.submitAnswer()
  ├─ saveAnswer() → 保存答案记录 + 更新进度
  └─ gradingService.grade() → 自动评分
       ├─ 解析 formJson._scoringConfig 快照
       ├─ flattenWidgets() → 展平所有控件
       ├─ 遍历控件 → 匹配评分配置 → 比对答案
       │   ├─ exact: 精确匹配
       │   ├─ contains: 关键词比例计分
       │   └─ ai: 调用 AI 服务评分
       ├─ deduplicateDetailList() → 去重
       └─ 返回 GradingResult { totalScore, gradingDetail }
  ↓
更新 answer.gradingDetail + answer.totalScore
```

### 7.2 看板数据流

```
教师打开看板
  ↓
GET /progress?sheetId={id}&classCode={code}
  ↓
GuideSheetProgressMapper.selectFullProgressBySheetAndClass
  ├─ FROM biz_guide_sheet_assignment a
  ├─ LEFT JOIN biz_student s (学生信息)
  └─ LEFT JOIN biz_guide_sheet_progress p (填写进度)
       LEFT JOIN biz_guide_sheet_answer ans (评分数据)
  ↓
返回 List<GuideSheetProgressVo>
  ├─ isSubmitted = 'Y' → progressDetail = 评分详情 JSON
  └─ isSubmitted = 'N' → progressDetail = 填写进度 JSON
  ↓
前端 dashboard.vue
  ├─ parseGradingDetail() → 解析评分详情，去重，计算总分
  └─ 渲染学生列表 + 评分标签 + 详情弹窗
```

## 八、边界条件与约束

| 约束 | 说明 |
|------|------|
| 总分必须为 100 | 评分配置总分校验，每个字段分值不能为 0 |
| HomeTab 不可删除 | `internal: true` 标记 + 轮询兜底检查 |
| 新建表单重置 | 每次新建时设计器重置为仅含 HomeTab 的空白状态 |
| 端口固定 8082 | Vite 开发服务器端口配置在 `vite.config.js` |
| 已关闭不显示发布 | 状态为"已关闭"的导学单操作列不显示"发布"按钮 |
| 新建时"是否公开"必填 | 默认值为"公开"（Y） |
| 列表可见性 | 仅显示公开（`is_public = 'Y'`）或当前用户创建的导学单 |
| AI 评分必须输入参考答案 | 评分模式选择为"AI评分"时校验 |
| AI 评分频率限制 | 5 分钟内同一学生同一导学单最多 3 次 |
| 非管理员权限 | 无权访问 `/system/user/list` 接口 |
| 控件命名 | 新增字段自动生成中文标签 + 拼音唯一名称 |
| 图片上传 | 自动修复 `picture-upload` 的 `uploadURL` 为空问题 |

## 九、已解决的问题记录

| 问题 | 根因 | 解决方案 |
|------|------|----------|
| 看板返回列表页空白 | `<transition mode="out-in">` 过渡动画卡死 | 移除 `<transition>` 包装 |
| 评分配置重复导致总分翻倍 | `flattenWidgets` 误将 `options` 配置对象当作控件 | 添加 `isRealWidget()` 检查 + `deduplicateDetailList()` 去重 |
| 路由缓存失效 | 路由名称与组件 name 不一致 | 统一路由名称与组件 name |
| Watcher 泄漏 | watcher 在 `onMounted` 内部定义 | 移至 `<script setup>` 顶层 |
| 进度表不完整 | 仅查 progress 表缺少未开始学生 | LEFT JOIN assignment + student 表 |
| classCode collation 不匹配 | 不同表 VARCHAR 字段 collation 差异 | SQL 显式指定 COLLATE |
| AI 评分 API 调用失败 | Key 与 API 端点不匹配 | 按供应商配置匹配的 API 地址 |
| VForm3 初始化时序 | 初始化完成前调用内部 API 失败 | 使用 `getFormJson()` + `setFormJson()` 替代 |
