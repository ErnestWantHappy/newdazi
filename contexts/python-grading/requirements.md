# Python 操作题批改稳定化需求

状态：**1.30.88～1.30.92 均已上线**（2026-11-10）

## 背景

教师批改页原先把 `biz_student_answer` 当成学生 Python 作品的唯一来源，同时从 `biz_programming_submission` 取最高分判题结果。两套读取口径在以下场景会分叉：

- 学生在课后或非当前课完成正式提交，判题记录已写入，但答题表还没有对应行。
- 学生同分重复提交，答题表保留旧代码，而判题查询选择更新时间更晚的新提交。
- 教师批量采用系统分时，学生并发重交或另一名教师同时改分。
- 个别学生档案缺失、题目满分为空或已过批改期限。

## 用户目标

- 教师看到的代码、分数、判题时间、用时、内存和通过用例必须来自同一条正式判题记录。
- 已正式提交且有判题分的学生，即使答题表缺行，也应能预览和批改。
- 批量采用系统分应一次完成整班，遇到单人异常时跳过并说明，不得整班回滚。
- 并发重交、并发教师改分、退回重交和非法分值不得被静默覆盖。
- 手机窄屏应能完成“选学生 → 看作品 → 打分”的完整流程，不把三栏压成窄条。
- 教师可以运行查看当前最高分 Python 提交，输入自定义数据并查看输出；运行不产生判题记录、不改成绩。
- Python 支持五星辅助打分；系统判题分只作参考，正式成绩由教师五星/数字打分或批量采用系统分确认。

## 验收标准

1. 最高分提交只接受 `submission_kind='SUBMIT'`、`score IS NOT NULL` 和已知成功/失败终态白名单，排除 NULL、未知、等待中、判题中和取消状态。
2. 同分时以 `judged_at`、`submission_id` 较新的提交为准；答题表代码也必须同步为同一版本。
3. 无答题行但有正式提交时，批改列表标记为已提交，预览显示判题代码；人工评分和批量采用可补建答题行。
4. 批量采用在事务内对当前答题行加锁，比对页面快照、当前最高分提交、退回状态和任务状态；页面快照保护自 1.30.90 起生效。
5. 单个学生档案缺失、系统分缺失/越界、课程满分非法、答卷已变化或已退回时跳过并计数；其余学生继续提交。
6. 桌面保持三栏；宽度不超过 900px 时改为纵向布局，学生名单、代码预览和打分区均为整行宽度。
7. 学生正式提交后，系统判题结果和代码保留；`biz_student_answer.score` 保持 NULL，任务状态保持已提交待批。
8. 教师已评分后，后续学生重交不得悄悄替换已评分代码；教师列表仍以最高分判题记录作为系统参考。

## 非目标

- 不改变最高分判题记录的选取规则；正式成绩写入由教师确认触发。
- 不重算历史成绩，不批量补建历史答题行。
- 不在生产验收中写入真实学生成绩。
- 不改变题库、课程、权限或 Judge0 判题服务。
