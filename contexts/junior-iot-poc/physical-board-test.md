# Mind+ + 掌控板实测单

## 1. 先验证教师机到县服务器

浏览器打开：

```text
http://10.52.1.123:18080/
```

登录使用 SIoT 2618 官方默认凭据。注意：你之前截图里的旧版口令不适用于 2618；以 DFRobot 当前官方说明为准，不要在聊天或截图中公开口令。

登录后点击“新建主题(Topic)”，先创建：

```text
poc/dmw/zdx/group01/light
```

网页中的 Topic 与 Mind+ 必须逐字一致，否则 Broker 虽然可能收到发布，数据管理页也无法按目标 Topic 展示。

如果这个页面在学校教师机打不开，先不要接掌控板，问题在学校到县服务器的网络路由或端口，不在 Mind+ 程序。

## 2. Mind+ 参数

| 参数 | 填写值 |
| :--- | :--- |
| 物联网平台 | `SIoT` |
| 服务器地址 | `10.52.1.123` |
| MQTT 端口 | SIoT 积木默认 `1883` |
| 账号/密码 | SIoT 2618 官方默认凭据 |
| Topic | `poc/dmw/zdx/group01/light`（首测可直接用） |

## 3. 程序最低结构

1. ESP32 主程序开始；
2. 屏幕显示“Wi-Fi 连接中”；
3. 连接学校 Wi-Fi，并等待“Wi-Fi 连接成功”；
4. 屏幕显示“MQTT 连接中”；
5. 初始化 SIoT，填写上表参数和 Topic；
6. 等待 MQTT 连接成功，屏幕显示“MQTT 已连接”；
7. 循环读取光线或任一传感器；
8. 每 1 秒向 Topic 发布一次数据；
9. 屏幕同时显示最新值和累计发送次数。

不要只显示“程序运行中”。四个状态必须分开，否则断联时无法判断失败发生在哪一层。

## 4. 成功标准

- 掌控板显示 Wi-Fi 已连接；
- 掌控板显示 MQTT 已连接；
- 发送计数每秒增加；
- SIoT 网页对应 Topic 能看到数据；
- 连续运行 10 分钟；
- 关闭再打开 Wi-Fi 后能恢复发送。

## 5. 当场排错

| 现场 | 优先检查 |
| :--- | :--- |
| 教师机打不开 18080 | 学校到 `10.52.1.123` 的路由、学校出口策略 |
| Wi-Fi 一直失败 | SSID/口令、2.4GHz、信号强度、无线终端隔离 |
| Wi-Fi 成功但 MQTT 失败 | 地址是否只填 IP、账号/密码是否为 2618 当前值、1883 是否可达 |
| MQTT 成功但网页无数据 | Topic 是否完全一致、发布积木是否真的进入循环、发送内容是否为空 |
| 一会成功一会失败 | 屏幕记录重连次数；记下断联时间和发送计数，区分 Wi-Fi 重连与 MQTT 重连 |

完成后保留两张证据：掌控板状态屏幕、SIoT 网页同一 Topic 的消息列表。
