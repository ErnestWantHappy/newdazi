# 初中物联网县级 SIoT PoC 需求

> 状态（2026-08-19）：SIoT P0/P1 已验证；P2 正式安全门禁因 SIoT 2618 无法创建可认证的独立强密码账号而阻断。用户已确认启动标准 MQTT Broker 与 Mind+ 的并行兼容验证；仍不重做 Mind+，不做考试和自动评分。

> 2026-08-20：用户现场确认 Mind+ SIoT 模块连接 `10.52.1.129:1883` 的 EMQX 成功，标准 Broker 兼容门禁关闭。P2 正式架构改为 EMQX 管理的每设备账号与精确 Topic ACL；禁止把共享 SIoT 弱账号用于多校正式课堂。平台 IoT 5 张业务表已在正式 `ry-vue` 建立，MQTT 接收器尚未启用。

## 1. 目标

验证“学生继续在 Mind+ 编程，掌控板经 MQTT 把实验数据发送到县服务器，后续学业测评平台作为订阅端接收”的技术路线，不开发新的 Mind+，也不把物联网做成考试。

## 2. 使用场景

- 初中课堂以 2 人或 4 人小组实验为主。
- 多所学校、多个教师可以同时使用县级服务。
- 教师在平台中为小组登记掌控板，由平台生成并复制一次设备配置；学生不接触平台订阅账号或 EMQX 管理端。
- 掌控板发送光照、温湿度、按钮等实验数据；教师能判断数据是否到达。
- 物联网和在线协作是两个独立功能，是否在同一节课使用由教师决定。

## 3. PoC 范围

本阶段包含：

1. 县服务器部署 SIoT 2618；
2. MQTT 1883 与 SIoT Web 18080 的跨机器访问；
3. MQTT 认证、订阅、发布、异常退出自动恢复；
4. 240 个模拟小组、每组 5 条消息的并发收发；
5. 一块真实掌控板在学校网络中的端到端验证。

本阶段不包含：

- 学业测评平台正式页面、课程/小组/设备数据库；
- 多校租户隔离和教师自助生成凭据；
- 成绩、考试、自动评分；
- 小学省平台接入；
- 用平台取代 Mind+。

## 4. 验收标准

### P0 软件链路

- 县服务器 MQTT 与 Web 可访问；
- 正确凭据能连接、订阅和收发，错误凭据明确返回认证失败；
- SIoT 子进程异常退出后 30 秒内自动恢复；
- 240 个并发客户端共 1200 条消息全部被订阅端收到；
- 现有 80、3005、3009、3010 服务保持 HTTP 200。

以上标准已于 2026-08-11 验证通过。

### P1 真实课堂链路

- 教师机能打开县 SIoT Web；
- 掌控板能连接学校 Wi-Fi；
- 掌控板能连接 `10.52.1.123:1883`；
- 连续发送至少 10 分钟，消息到达率不低于 98%；
- 断开 Wi-Fi 后恢复，设备能重新连接并继续发送；
- 教师能依据屏幕状态和故障判断表定位失败层级。

P1 已通过后，进入 P2 平台接入；P2 完成前不进行多校推广。

## 2026-08-19 进度补充
P2 平台代码、幂等 SQL、模拟器、后端测试和 Vue3 构建已完成；正式上线未完成。正式 SIoT 原始数据库备份已恢复，CountySIoTPoc 保持 Running。新增平台订阅账号的 MQTT 认证实际返回 CONNACK 5，因此未执行正式后端切换、正式库迁移或教师浏览器上线验收；该问题是当前上线阻断，需先按 SIoT 2618 的真实认证/Topic 管理方式解决。

## 标准 Broker 兼容门禁（2026-08-19）

- 已在 `10.52.1.129:1883` 部署独立 EMQX 测试实例；管理端仅本机 `127.0.0.1:18083`，无对外管理接口。
- 仅教育网 `10.52.0.0/16` 可访问 MQTT 1883；TLS 8883 暂不开放，避免在 Mind+ 未证明 TLS 兼容前扩大端口面。
- 强密码认证、单设备 Topic ACL、错误密码拒绝及越权 Topic 拒绝均已由 Broker 实测通过。
- 必须由真实掌控板用 Mind+ 的 SIoT 选项完成一次“连接、发布、可观察消息”的验证；未通过前不得替换 SIoT，不得发布 P2。

## 产品入口补充（2026-08-19）

教师实际使用路径确定为：教师首页 → 对应课程卡片 → 物联 → 新建实验 → 选择课程已指派班级并建立小组 → 登记掌控板 → 复制一次性 Mind+ 参数 → 查看实时消息和中文诊断。课程 ID 由课程卡片自动传入，教师不手填；一个实验不创建新端口，所有设备仍使用县 SIoT `10.52.1.123:1883`。该入口已完成本地代码和 Vue3 构建，尚未随正式发布上线。
