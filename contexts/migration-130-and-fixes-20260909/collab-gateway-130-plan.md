# 协作入口迁到 130：方案（待用户确认后实施）

日期：2026-09-09。方案 A 已于当日 21:05 实施（130 网关 + 129 origin + 130 环境变量）。123 生产后端未改；123:3018/3019 暂留回滚。用户已明确：123 上旧协作文档可以不要；希望师生只访问 130。

## 0. 先说清楚三句话

1. **可以。** 师生浏览器以后只打 130：网站走 `http://10.52.1.130/`（80），协作再走 130 的 **3018 和 3019**。123 的 3018/3019 可以停用。
2. **协作引擎不用搬到 130。** CryptPad 仍在 129 的 Docker 里。130 只做大门（Nginx 反代）。学校电脑永远不直连 129。Python 判题、物联网也不搬，继续 129。
3. **不能只开 80 就完成协作。** CryptPad 强制两个不同来源（主站 + 沙箱）。没有新域名时，必须是两个端口。以前把协作塞进网站 `/cryptpad/` 子路径已经失败过（编辑器内部按根路径拉脚本，拉到的是平台 HTML）。

## 1. 123 的 3018/3019 其实没开放给教育网

现场只读（2026-09-09）：

| 项 | 事实 |
| --- | --- |
| 123 进程 | `UnifiedNginx` 在听 `0.0.0.0:3018` 和 `:3019`，本机 curl 200 |
| Windows 防火墙规则名 | `NewDazi CryptPad gateway 3018-3019` |
| 方向 / 协议 / 端口 | 入站 TCP 3018,3019 |
| **RemoteIP** | **`LocalSubnet`（本网段，通常只有 `10.52.1.0/24`）** |
| 配置文件 | Domain、Private、Public 都启用了这条规则，但来源仍是本网段 |

含义：

- 教科研机房所在的 `10.52.1.0/24` 能打开 3018（所以本机/跳板探测是绿的）。
- **其他学校机房（例如 `10.52.4.x`、各校教育网段）在 123 防火墙上直接被丢弃。** 不是 CryptPad 坏了，是端口从来没对全县教育网放行。
- 这与 2026-09-06 记录一致：当时就写了「防火墙仅 LocalSubnet，跨网段课堂可达性尚未验」。后来没有扩来源。
- 因此「123 上协作有时能开、多数学校不能开」是网络门禁问题，不是 130 迁移漏端口。

旧协作文档：用户确认可以丢弃。改入口 origin 后，绑在 `http://10.52.1.123:3018` 上的 CryptPad 垫内容本来也打不开。平台库里的房间记录还在，但旧垫作废，新开房间用新地址。

## 4. 三个方案（部署路线，需选一个）

### 方案 A（推荐）：130 增加 3018 + 3019 网关，CryptPad 仍在 129

- **核心**：复制现在 123 的做法，大门换到 130；改 129 的主/沙箱 origin 为 `http://10.52.1.130:3018` 和 `:3019`；平台环境变量指向这两个地址；CSP 允许 `http://10.52.1.130` 和将来的 `http://xxkj.xsedu.net.cn` 嵌页面。
- **优点**：与已验证结构相同；不搬 Docker/数据盘；不依赖新域名；教科研只加两个端口；123 旧文档按你的决定丢弃。
- **缺点**：师生打开协作要记/允许两个额外端口；机房若拦截非 80 端口，必须教科研放行。
- **推荐理由**：没有新域名时这是唯一能满足 CryptPad 双来源的办法；工作量小、可回滚（123 网关先留着不删）。

### 方案 B：只开 80，用两个新域名

- **核心**：`xxkj.xsedu.net.cn`、`office.xsedu.net.cn`、`office-sandbox.xsedu.net.cn` 都解析到 130；三个都走 80（或以后 443）。130 Nginx 按 Host 分流：xxkj 去平台，office 两个去 129 CryptPad。
- **优点**：学校只需 80（可能已放行）；地址好看。
- **缺点**：必须教科研改 **DNS**（三个名字）；office 域名以前指向 129，要改干净；比开端口协调面更大。
- **何时选**：教科研明确「非 80 端口一律不放」时再改走这条。

### 方案 C：把 CryptPad 容器整机迁到 130

- **核心**：129 的 `/srv/cryptpad`、镜像、OnlyOffice 补丁、数据卷拷到 130，本机听 3018/3019 或 80。
- **优点**：少一台运行时依赖。
- **缺点**：停机长、要重建容器和补丁挂载、容易丢补丁；129 仍要留 Judge0/EMQX，省不掉 129；对「浏览器只访问 130」没有额外好处。
- **不推荐**：你已允许丢旧文档，更没必要搬引擎。

**默认按方案 A。** 未确认前不改服务器。

## 5. 方案 A 实施步骤（确认后才做）

顺序固定，每步只做一件事并留回滚。

1. **教科研 ACL 先放 130 的 3018/3019**（来源全县网段）。未放行就改 origin，外校仍会超时。
2. 备份 129：`/etc/nginx/sites-available/cryptpad.conf`、`/srv/cryptpad/config/config.js`、compose；备份 130 Nginx 与 `xueyeceping-130.env`。
3. 130 Nginx 增加两个 `listen 3018` / `listen 3019` 的 server，反代 `http://10.52.1.129:80/`，打开 WebSocket、长超时、60m 包体；**不要**再走 `/cryptpad/` 子路径。
4. 130 UFW：对 `10.52.0.0/16` 放行 3018/3019（22 保持原样，3009 继续不对外）。
5. 129 CryptPad：`httpUnsafeOrigin` / `httpSafeOrigin` 改为 130 的 3018/3019；CSP 里所有 123:3018/3019 换成 130 对应地址；`frame-ancestors` 加上 `http://10.52.1.130` 和 `http://xxkj.xsedu.net.cn`。按需重建/重载 CryptPad 与 Nginx。
6. 130 环境变量：`CRYPTPAD_BASE_URL=http://10.52.1.130:3018`，`CRYPTPAD_API_URL=http://10.52.1.130:3018/cryptpad-api.js`，其余密钥不变。重启 130 后端。
7. 从 **非 10.52.1.0/24 的学校网** 或模拟跨网段验收：脚本 200、iframe 出现、两人编辑、保存回平台。本机 123 网段 200 不算全县可用。
8. 验收通过后再停 123 的 3018/3019 监听（先留 1～2 天作回滚）。不删 129 数据卷。

回滚：129 origin 改回 123:3018/3019，130 环境变量改回 123，reload。123 Nginx 未删则可马上恢复旧大门。
