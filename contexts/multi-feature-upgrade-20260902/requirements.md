## 1. 目标

在不更换 Vue3、Spring Boot、MySQL、Redis、CryptPad 的前提下，先修复影响数据正确性和教师批改的线上问题，再完善快捷批改、实时课堂状态、课程只读共享、流程图易用性，最后建设通用班级分组、学生终端桌面和按小组分文档的非计分在线协作。

## 2. 术语

- **共享课程教师**：与课程同校、且至少管理该课程一个已指派班级的非创建教师。
- **学生桌面**：教师查看班级学生终端在线状态的网格页面，不是考勤或远程控制系统。
- **连接 IP**：平台服务端从受信任代理链观察到的客户端来源地址，不保证等于电脑物理网卡 IP。
- **分组方案**：按学校、入学年份、班级保存的可复用成员分组模板。
- **课时分组快照**：某课程协作活动实际使用的冻结分组事实。
- **协作活动**：独立、非计分的课堂共同编辑活动，不属于学生个人操作题答案。
- **任务版本**：同一协作活动可选择的不同起始文件模板。
- **小组房间**：一个课时小组基于一个任务版本创建的独立协作文档。
- **保存触发者**：触发平台保存某个完整协作文档版本的客户端用户，不等同于该版本全部内容的作者。

## 3. 功能需求

### REQ-P0-01 评价标准快照批改修复

**用户故事：** 作为教师，我希望已提交作业始终使用提交时的评价标准，以便修改标准后仍能批改旧作业。

验收标准：

1. 前端请求评分项必须真实传递 `practicalVersionId`。
2. 旧作品显示并保存到其绑定的旧快照，新作品使用新快照。
3. 页面显示“作品 vN · 评分依据 vM（提交时）”。
4. 课程题目已有任何提交后，服务端拒绝修改该题总分。
5. 使用郑琦账号 `696260` 的课程 293、题目 2029 做专项回归：旧版 3 项、新版 2 项互不串用。

### REQ-P0-02 题目更新非空字段修复

1. PYTHON、FLOWCHART 及非图片操作模式更新时不得把 `practical_image_max_count` 写为 NULL。
2. 继续保持生产表的 NOT NULL 约束；非图片模式使用安全默认值但业务上忽略。
3. 题型切换、旧题编辑和重复保存必须有 Mapper/Service 测试。

### REQ-P0-03 题库导入与诊断治理

1. Excel 导入在写库前校验题型、题干等必填字段。
2. 导入采用明确的整批事务：任一行失败时整批不落库，并返回行号和中文错误摘要。
3. 前端只展示受控错误，不返回 SQL、JAR 路径、堆栈或数据库内部信息。
4. 学生删除保护、班级不属于学校等预期拒绝显示为业务提示，不计入系统严重故障。
5. 学生导入耗时按当前动态阈值重新分级；验证线上运行 JAR 与代码规则一致。
6. 后端日志输出改到稳定日志目录或与活动 release 明确一致，避免 NSSM 运行目录和日志目录互相错位。

### REQ-SHARE-01 共享课程内容只读

1. 共享课程教师可查看课程内已引用的全部公有、私有题目。
2. 未加入课程的创建教师私人题目不开放。
3. 共享教师只能查看课程内容和成绩，不能设计、删除、复制或修改原课程与题目。
4. 服务端必须校验同校、负责班级与课程指派交集；跨校或同校无负责关系访问拒绝。

### REQ-GRADE-01 五星辅助批改

1. 数字输入保持默认。
2. 支持整题评星和逐评分项评星切换。
3. 星级折算为 `round(满分 × 星数 / 5)`，按 HALF_UP 四舍五入保存整数。
4. 独立提供“0 分/清零”；每颗星必须提示实际分数。
5. 整题星级不伪造分项明细；逐项星级继续执行完整性、上限与合计校验。

### REQ-FLOW-01 流程图规范与连接易用性

1. 开始/结束使用胶囊形状。
2. 处理框和输入/输出框不使用圆角；输入/输出继续保持标准平行四边形。
3. 连接锚点扩大可见、悬浮和点击热区，仍保持节点布局清晰。
4. 旧流程图 JSON 打开、保存和结构检查结果保持兼容。

### REQ-REALTIME-01 作业状态实时同步

1. 状态包括未进入、已进入、作答中、已提交待批、已批改、退回重交。
2. 打开题目为已进入；首次保存草稿/答案/临时作品为作答中；正式提交为已提交待批。
3. 学生事务提交成功后发布认证 WebSocket 事件；页面定时全量校准。
4. 教师首页、成绩/提交列表、批改页和学生桌面复用同一状态口径。
5. 新提交不打断教师当前批改对象，只更新对应学生、人数和轻提示。

### REQ-ASSIGN-01 指派班级默认状态

1. 普通新建课程默认不选择任何班级。
2. 从具体班级入口新建时只预选该班级。
3. 编辑课程准确回显已经保存的指派班级。
4. 禁止通过年级入口把全年级班级自动塞入设计器选中值。

### REQ-GROUP-01 通用班级分组

1. 一个班级可以保存多套分组方案。
2. 支持按组数平均、按学号区间和手动拖动三种方式。
3. 每名当前班级学生必须且只能属于一个组。
4. 每个非空组一名组长，默认学号最小者，教师可调整；组长只作视觉标记。
5. 课程使用时生成课时分组快照；活动开始后模板变化不自动影响快照。

### REQ-DESKTOP-01 学生终端桌面

1. 主入口位于现有班级管理页面每个已管理班级的操作列；教师首页提供当前课程/班级快捷入口。
2. 页面以卡片网格显示姓名、学号、在线/离线、连接 IP、设备数、最近活动、小组和组长。
3. 任意学生端页面保持受认证连接即可在线；30 秒心跳、60 秒无心跳离线。
4. 同一学生多设备聚合到一张卡片，可展开设备列表。
5. 默认按学号排列；教师可拖动并按教师+班级保存布局。
6. 可以在终端状态视图和作业状态视图之间切换。
7. 点击学生打开设备、会话、小组及协作轨迹抽屉。
8. 不新增点名，不写考勤，不远程控制电脑，不承诺读取 Windows 计算机名。

### REQ-COLLAB-01 分组多文档协作

1. 在线协作改为独立非计分课堂协作活动，不占操作题数量、不设置分数、不写个人答案。
2. 一个活动可上传多个任务版本；系统按小组顺序默认映射，教师可调整。
3. 多个组可以使用相同模板，但必须创建不同文档副本。
4. 学生只能取得本人课时小组的房间；同组、异组、跨班和跨校权限由服务端校验。
5. 首名学生进入后冻结起始文件和小组映射。
6. 课中换组需要教师确认并审计；学生失去旧组入口、获得新组入口，旧文档和轨迹保留。
7. 现有全班共同编辑房间保留为“全班组/历史模式”。

### REQ-TRACE-01 协作操作轨迹与版本差异

1. 保存进入、离开、重连、在线时段、保存触发/成功/失败和换组事件，默认保留一个学年。
2. 每个 revision 保存后异步比较前后完整文件，不阻塞协作保存。
3. DOCX 比较段落和表格文字；XLSX 比较工作表、单元格值和公式；PPTX 比较幻灯片和文字。
4. 旧 DOC/XLS/PPT 尝试转换，失败时降级为“文档已变化”；图片、格式、图表只提供有限摘要。
5. 时间线按约一分钟聚合，允许展开原始版本事件和有限长度文字差异。
6. UI 必须表述为“某学生客户端触发保存，小组文档发生以下变化”，不得把全部差异认定为该学生个人贡献。
7. 精确作者归属作为独立 Provider PoC，不阻塞版本级差异上线。

## 4. 非功能要求

- 权限：所有查询和推送按学校、教师管理班级、课程、课时小组校验。
- 性能：40～60 人班级状态变化在正常内网中 2 秒内可见；断线重连后 5 秒内完成全量校准。
- 在线状态：心跳写 Redis，不按 30 秒频率写 MySQL。
- 协作保存：差异分析失败或排队不能影响文件保存成功。
- 安全：只信任配置内代理写入的客户端地址；不在日志、文档和页面泄露 Token、Cookie 或服务凭据。
- 兼容：历史成绩、评分快照、全班协作房间和 revision 不删除、不覆盖。
- 发布：涉及 SQL 时必须执行前检、整库备份、SHA-256、幂等迁移、后检和回滚准备。

## 5. 明确非目标

- 不开发电脑远程控制、屏幕监控或真实计算机名探针。
- 不把在线状态当作签到或缺席。
- 不把协作文档自动转换为个人作业或成绩。
- 不承诺从多人合并版本中精确判断每个字符的作者。
- 不迁移全平台成绩为小数。
