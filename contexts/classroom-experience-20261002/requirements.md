- 状态：三轮访谈后用户明确全部采用推荐方案，并授权直接开发、自动验证、不再询问；本机代码与隔离验收已完成。
- 交付：配套前后端修改、四份增量 SQL、实际 Windows 客户端与校验清单、自动验收证据及配置/回退说明。正式发布不在本轮范围，机房现场验收另列待办。
- 术语见 [CONTEXT.md](./CONTEXT.md)。当前系统事实仍以 `contexts/PROJECT_CORE.md`、架构资料和实际代码为准；本需求不替代已实现状态。

## 用户已确认

1. 不更换现有技术栈，不重构无关模块，不增加师生使用难度；保留现有 Office、PDF、图片的教师批改预览体验。
2. 教师未批改并产生正式成绩前，学生应可反复更新文件操作题和流程图操作题；已批改有成绩时，教师才出现退回重交按钮。
3. 单文件 HTML 为首期网页作业范围，支持内联 CSS 和 JavaScript；希望平台提供清楚、统一的提交规范。
4. TXT 可能是文字答案，也可能存放 HTML 源代码；必须考虑上传与教师预览的完整链路。
5. 学生可提交 ZIP、RAR、7Z；首期只显示文件名、大小并提供教师授权下载，不解压、不开发包内预览。原有直接上传格式的预览保持，TXT 和单文件 HTML 补齐直接预览。
6. 学生反馈选择分阶段实现：先复用本人答案、正式分数与教师确认反馈，再提供已有 AI 诊断中的个人错误和改进建议，优先复用现有报告证据，不默认逐人另发 AI 请求。
7. 机房功能首期只做可选客户端和教师异常提醒，不直接锁定登录或作答；只在有需要的学校使用。
8. 目标学生机主要是 Windows 10，通常已有极域与还原卡，具体还原产品因学校而异；大部分学校 D 盘不还原，但尚未逐校核实。必要时可由学校管理员统一安装一次，操作成本应尽量低。
9. 最终开发提示词授权范围为自动检查、实现、必要的本地迁移及自动验证，正式服务器部署不在本轮范围。
10. 未批改/已批改按每位学生、每道操作题判断；正式保存 0 分也算已批改，AI 建议未被教师采用不算已批改。保留只允许当前课程写入的规则。
11. 覆盖上传只更新当前有效版本，不物理覆盖历史作品；上传中、草稿修改或提交失败不替换当前作品。教师评分与学生更新并发时必须核对版本，不能将旧作品分数写入新作品。
12. 退回后暂留原成绩并标识待重交；新作品成功提交后才将当前成绩转为待批，历史作品和成绩保留。
13. 新增 AI 个人反馈由教师一次向本班发布，学生自动看到本人内容；保留已有开放成绩和错题功能。无 AI 报告时仍可查看已有成绩和教师反馈。
14. 用户实际使用为一课一道操作题，大屏不新增多题进度交互；未交、已交、已批改、已退回采用明确的颜色及文字。经核对，课程设计器与后端确有限制 FILE/PYTHON/FLOWCHART 共用一个名额，历史多题课程仅兼容保留，不能据此开放新增多题。
15. 机位采用长期方案：按学校、机房、班级记录学生常用电脑，首次全班坐好后由教师确认，以后持续对照；正常调座通过显式确认更新，不自动用每节课首次位置覆盖长期基准。
16. 新增能力先限定普通课堂。区域抽测保持现有规则并做兼容回归；Python 不套用文件/流程图的教师评分锁定规则，继续使用既有判题和最高分规则。
17. TXT、HTML、ZIP、RAR、7Z 首期均可人工评分，不新增这些格式的 AI 批改能力；明确展示不支持原因，不能把不支持的作品当成零分、已分析或导致整个班级任务失败。
18. 学校管理员统一配置客户端和“学业测评平台”桌面快捷方式；学生点击后仍在浏览器使用原平台，自动关联设备，无需另一套客户端登录。普通网页入口保留，关联未知时显示未识别，不阻止学习。
19. 客户端下载按钮仅向启用功能的学校学生展示，作为补装入口；不能承诺网页静默写 D 盘或自动运行，部署目录和开机/登录自启需管理员配置并保留到机房还原基线。
20. 已发布个人反馈在课程推进后可从历史入口查看；重生成分析不会自动替换已发布版本，教师点击更新发布后才替换。反馈记录课程、作品版本及时间；新作品提交后旧反馈只能标识为历史依据，不能冒充当前作品分析。
21. 客户端本轮交付目标为一间机房可试点的实际程序、配置与联调成果，不是只交方案；真实还原卡重启、自启保留、极域分发属于现场验收，未实际完成时必须标记待验。
22. 教师可整班确认长期机位，正常调座或换机器时显式更新；各学校、机房、班级隔离，设备故障或客户端离线不影响登录、答题、交作业和批改。

## 访谈时的原实现（本轮已按实施结果补齐）

- `PracticalFilePolicyService` 的学生作品白名单为 Office、PDF、JPG/JPEG/PNG，没有 TXT、HTML 或普通压缩包。
- 既有预览以 Office/PDF 转静态页图、图片预览为主，继续保留原体验。单文件 HTML 需要额外的隔离预览能力，不能把学生代码直接注入教师页面。
- `FlowchartEditor.vue` 已有默认 480px、0.25 缩放步长、可调整大小节点及上下锚点相关实现；PROJECT_CORE 的 2026-09-23 条目记录本机回归，未代表本轮重新验收或正式已发布。
- `StudentFlowchartDialog.vue` 和 `FlowchartService` 已存在重开提交能力，但目前只读判断基于草稿和提交版本；须按本次新规则核验整个读写与正式评分链路。
- `teacher/grading.vue` 的退回按钮没有依据当前题目正式成绩控制显示，需前后端一致限制，不能只隐藏按钮。
- `PracticalInsightController` 当前限制教师与管理员；其学生详情方法仍是教师查看个人证据，不可直接对学生开放整份报告权限。
- 学生首页已有历史成绩及错题练习入口，优先复用，避免另建平行入口。
- 课堂大屏已有 `connectionIp` 和操作题提交/批改数量；现有 IP 为服务器观察地址，不能当成经过认证的终端内网 IP。

## 已确认的展示与实施默认值

- TXT 始终按纯文本显示，即使含 HTML 标签也不执行；HTML 单文件支持效果预览，可提供源码查看，学生无需按姓名或学号重命名。
- 打字待输入正文和输入文字加深至黑色，保留正确/错误区分，不改变计时、速度、准确率和最高分规则。
- 每个阶段自动完成相应验证再推进；客户端作为独立后置试点，不阻塞核心课堂功能交付。

## 明确暂缓

- 压缩包内部预览与解压执行。
- 多文件网页、外部依赖、联网接口及需要安装项目依赖的网页作品运行环境。
- TXT、HTML、压缩包的新增 AI 批改能力，以及另行逐人付费生成反馈。
- 强制锁座、登录封禁、凭 IP 判定真实身份。
- 自动兼容所有学校还原软件、绕过还原保护或无人确认的远程安装。
- 正式服务器发布、正式库迁移、Git 推送及对真实学生作品和成绩的验收写入。

## 实施结果与产品限制

- 普通课堂 FILE/FLOWCHART 的更新和退回已按上述规则实现；正式保存 0 分也锁定，旧课仍只读。Python、打字和区域抽测不套用本轮新规则，一课一道操作题限制保留。
- 新格式由教师在题目配置中显式选择，既有题目的默认格式不自动扩大。TXT/HTML 最大 2 MiB；网页推荐 `index.html`，不强制姓名/学号文件名。非图片作品一次一个文件，图片仍支持原数量和顺序。
- 个人反馈发布不重新调用模型；无证据时明确显示没有个人诊断。AI 报告内容变化后需要教师再次发布，旧快照保留。
- 机位助手实际实现与本机链路已验，默认关闭；软件关联辅助核对，不承诺识别真实操作者或防止转发短时链接。D 盘持久不能单独保证 Windows 自启项、桌面快捷方式或 DPAPI 密钥经还原后保留。
- Windows 10、极域、还原卡重启与镜像克隆仍须在一间真实机房验证。暂缓项保持，不以本机结果宣布全校部署可用。
