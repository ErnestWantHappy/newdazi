## 1. 结论与比较边界

核验对象是当前工作区（含已有未提交修改），对应 PROJECT_CORE 顶部 v4.00 本机候选。正式版本仍以既有发布证据为准，不能将本报告直接解释为正式环境八项故障均已发生。项目仍是 Vue3 + Spring Boot/MyBatis + MySQL/Redis，本方案不更换架构、不新增依赖。

三份报告的八条核心缺陷均有当前源码依据。按本轮有效发现的覆盖面、业务风险和定位质量，综合倾向 GPT 第一、Gemini 第二、Qwen 第三；不是对模型整体智力的排名。未获得相同提示词、模型版本、检查范围和预算，不能计算公平的检出率或断言谁整体最聪明。

| 报告 | 本轮复核 | 评价 |
| --- | --- | --- |
| GPT | 5 条核心问题成立 | 覆盖草稿身份隔离、正式版本展示、上传组件状态、异步响应归属；跨学生草稿污染价值最高 |
| Gemini | 1 条跨层问题成立 | 找到删除作品后的答案、状态、统计不一致，是主教学链路的重要漏项；提交时间实际上被写为删除时刻，不只是保留旧值 |
| Qwen | 2 条核心问题成立，部分影响表述过宽 | 生命周期到 Redis 过期、客户端启动到异常退出的链路分析细致；“主链路自洽”不能作为无缺陷证明 |

Qwen 的两处范围修正：

- 离开首页后首先失效的是相应学生的机位观测；只有全班都不再续期、没有其他仍可识别学生时，才表现为整班失效和整班确认按钮禁用。时间从最后一次状态请求起算，教师页面还存在刷新周期。
- 客户端快捷方式失败确实不会打开浏览器，但 README 明确保留普通网页入口，不能称其为平台唯一入口。托盘 TryOpen 也只是捕获异常并提示，没有真正兜底打开网页。损坏配置没有界面内恢复入口，不代表管理员通过外部文件操作也永远无法恢复。

## 3. 推荐实施方案

采用原架构内的最小分批修复，每批验收后再推进。没有换栈、表结构调整或引入依赖的必要。

### 第一批：作品归属与事实一致性（R1、R2、R3）

#### R1：草稿必须属于明确的登录用户

- 修改 StudentFlowchartDialog.vue、localDraft.js，按需补齐 store/modules/user.js 的退出身份清理。
- 草稿键增加版本前缀和稳定登录 userId，形成“版本 + 用户 + 课程 + 题目”；读取时再次核验存储的 ownerUserId。用户身份尚未获取时禁止读取/保存草稿，不使用空 ID 或默认 0。
- 旧键没有所有者，禁止自动迁入当前账号。保留但不自动加载，不能用“谁第一个登录就归谁”的迁移方式。
- 工作区加载、延时自动保存、保存成功/失败回调都捕获打开时的用户/课程/题目和请求代次。切题、关闭、退出或换账号后，旧响应不得修改新上下文或把旧内容写入新键。
- 只读展示正式作品时不要顺带把原有未同步草稿标记为已同步或覆盖，避免修 R3 时丢失学生未提交编辑。
- 验收：A 留离线草稿，B 以相同 revision 打开同题，B 不读到 A 内容、无自动保存 A 内容；A 再登录可恢复自己的草稿；覆盖不同 revision、旧键、身份未就绪、关闭/切题后迟到响应。

#### R2：删除作品同时撤销提交事实和课堂状态

- 修改 PracticalArtifactService.java、BizStudentAnswerMapper.java/XML、ClassroomTaskStateService.java/Writer.java，按需增加 BizStudentTaskStateMapper.java/XML 的受限状态更新；复核 ClassGroupingMapper.xml 和教师批改查询的空答案兜底。
- clearPracticalAnswer 显式写 submit_time = NULL，不再把删除时间当提交时间；删除审计仍保留在作品版本记录。
- 同一个删除事务中完成：校验当前课及版本、锁作品与答案、归档/标记删除版本、清答案和当前版本、将本题状态恢复为 WORKING（作答中），提交成功后再广播。历史版本与其他题型保留。
- **不能直接调用现有 markInTransaction(..., WORKING) 就认为修好。**ClassroomTaskStateWriter 当前会拦截 SUBMITTED/GRADED/RETURNED → WORKING。增加仅由删除业务调用的事务内撤销提交入口，沿用原锁顺序、递增 stateVersion、提交后广播；普通“开始作答”上报仍不得降级已提交/已批状态，不开放客户端任意重置。
- 0 分仍是已批；有分退回仍保留原分，禁止靠删除清分。版本冲突、评分先完成或课程已推进时必须拒绝删除。
- 批改列表无状态行时，不能仅凭 answer_id 存在推断 SUBMITTED；结合有效作品/非空答案和提交事实判断。大屏如增加有效提交条件，须兼容 FILE/FLOWCHART/PYTHON，不能机械要求所有操作题都有文件版本 ID。
- 已有残留数据先只读列出：文件作品当前版本为空、答案空、成绩空而时间/状态仍像已提交。确认目标环境确有此类数据后，再准备带前检、备份及精确主键清单的数据修复 SQL；不批量清空所有空答案，不伪造提交/删除时间。
- 验收：隔离 MySQL 中“提交→删除→重交”，同时核对学生页、教师批改列表、普通/分组大屏与 WebSocket；单题删除后未交、非绿色，多题按剩余有效作品汇总。补充删除与评分并发、旧版本删除、0 分、退回留分、失败回滚；状态失败时作品删除也回滚。

#### R3：只读窗口显示正式提交版本

- 主要修改 StudentFlowchartDialog.vue；后端现有 latestSubmission.documentJson 已可用，原则上无需为此增加新接口。
- readOnly=true 时选择正式提交的 documentJson；可编辑时选择本人草稿，缺草稿才使用起始模板。只读缺正式作品时明确提示无法加载，不静默降级展示草稿冒充已批作品。
- 显示对应正式版本号，保留草稿内容及 revision，不通过覆盖数据库草稿来“修复显示”。
- 验收：正式提交 A，继续自动保存 B，但不重交；教师评分 A；学生重开只读仍看 A，教师退回后可继续编辑保留的 B；含 0 分与正常分。确认教师端始终读取正式版本。

### 第二批：页面切换与连续上传（R4、R5）

#### R4：大屏响应按班级、课程和请求代次归属

- 修改 business/classroomDesktop/index.vue。
- 每次请求固定课程、入学年、班级快照与递增请求序号；成功、失败、finally 均只允许当前代次更新页面。
- loading 只负责展示；不能因旧班请求未结束就拒绝新班加载。同班轮询可防重入，跨班必须立即发起新请求。
- 切班立即清旧学生、布局、题型开关、选择项及依附旧班的弹窗状态；同链路 fetchLessonGateState 也使用上下文检查，避免旧响应读取新的全局 lessonId 再触发混合请求。卸载后丢弃迟到响应。
- 验收：模拟 A 慢 B 快、A 失败 B 成功、A→B→A、前进/返回与静默轮询重叠；页面只能呈现当前请求的学生与成绩，旧 finally 不得提前解除新请求的加载态。

#### R5：上传额度只计算当前批次

- 修改 student/index.vue，按课程和题目维护 el-upload 的受控文件列表或组件 ref，并建立文件 uid 与暂存 token 对应关系。
- 一批作品提交成功后清理该批的组件条目与业务暂存列表；失败时保留可重试内容，显式移除同步两套列表。切课清理所属上传任务与回调。
- 提交期间阻止向同题当前批次追加文件，或精确按本批 uid/token 清理；不能无条件清空后来刚选择的新文件，也不能在多图尚有上传回调时 clearFiles。
- 保持图片数量上限与非图片一次一个文件的服务端约束，不以去掉 limit 或无限调大来绕过问题。
- 验收：单图上限 1 连续提交至少 3 版，无需刷新；多图每版达到上限后仍能交下一版；覆盖上传失败、业务返回失败、移除重选、提交失败重试、慢上传和切课后回调。

### 第三批：机位助手启用前修复（R6、R7、R8）

#### R6：注册码结果绑定发起时的学校

- 修改 business/seatHelper/index.vue。
- enroll 捕获 deptId、机房、机位和上下文代次；返回时全部匹配才展示。切学校立即清 code、学校表单/设备旧数据，加载完成前禁用生成/保存，不能继续操作上一学校设置。
- 保存、撤销、错误提示和 busy 清理一并按操作上下文归属，防止旧操作收尾影响新学校。注册码展示附学校、机房、机位以便管理员核对。
- 服务端原有注册码归属校验保留；丢弃迟到结果不等于撤销服务端注册码，可让未展示的短时码按既有 TTL 过期。
- 验收：A 生成慢请求，切 B 或 A→B→A，旧码都不出现；只显示当前新请求的码，注册后学校与界面一致。

#### R7：网页机位续期跟随学生登录布局

- 修改 layout/StudentLayout.vue、StudentSeatHelper.vue、student/index.vue，必要时在现有 seatHelper.js 抽出共享会话状态，不引入新依赖。
- 将关联凭证消费和 30 秒续期提升到学生公共布局生命周期，状态展示与续期职责分开；首页可继续展示原入口，避免挂载两套定时器。
- 覆盖 Python、物联、协作的实际路由；布局重新挂载时能立即续期。退出登录、身份变化或离开学生布局停止旧轮询并丢弃响应。
- 保持 75/90 秒时效和服务端登录会话核验，不能靠把 TTL 改成一天掩盖续期缺失。
- 验收：关联后同标签页分别进入 Python、物联、协作至少 120 秒；本人机位持续可识别，整班全部切走也可确认有效机位。退出后不再续期；设备真实断线、学校关闭仍正确失效。

#### R8：网页入口独立于助手关联成功

- 修改 clients/seat-helper/SeatHelper.cs、README.md；按需修改 SeatHelperService.java 注册响应，返回经验证的普通 platformUrl。
- 冷启动、已有实例再次打开和托盘双击共用安全的打开流程：先尝试带关联凭证的地址，失败则打开预先保存并校验的普通网页地址，明确显示“机位未关联”，助手启动不因 device/open 暂时故障直接退出。
- 正常网页地址与设备密钥分开保存；公开地址可单独保留，以支持 DPAPI 文件损坏时仍能读取。严格校验 HTTPS/本机 HTTP，不复用过期 token、不把 API 前缀直接当网页地址，也不复制设备密钥到明文文件。
- 捕获配置解密/解析失败，提供管理员“重新配置”入口并保留损坏文件供排查；已有有效配置也可从托盘或显式参数进入配置。撤销旧设备后可输入新注册码完成恢复。后台自启失败不循环弹窗。
- 旧安装若尚无可信普通网页地址，必须明确由管理员补填，不能承诺凭空恢复地址或绕过设备认证。
- 验收：学校关闭、设备撤销、业务非 200、网络不可达、损坏 dat、机器标识变化、重复启动、托盘打开。确认可打开普通网页（后端确实停机时不承诺网页能正常服务），不产生伪关联；重新配置可完成。真实 Win10/极域/还原卡继续作为独立现场验收。

## 4. 验收、发布与风险

1. 先补关键状态/隔离/时序回归，再跑相关 Java/Node 测试与双端构建；不写仅搜索源码字符串就算通过的替代测试。Java 定向测试使用本机已有约定：`-Dsurefire.failIfNoSpecifiedTests=false -DforkCount=0`。
2. R2 必须在隔离 MySQL 验真实 Mapper 与事务；模拟 Mapper 不能证明 submit_time 已变 NULL。其他问题通过受控延迟响应与浏览器真实行为核验，客户端另做真实进程故障场景。
3. 浏览器至少覆盖学生/教师核心页与本报告专项链路；教研员做菜单冒烟。重点保证未批可改、0 分锁定、退回留分、重交清分、旧课不可写均不回退。
4. 当前方案预计无需新表或新依赖。R2 修改 Mapper 后需后端 clean package 并重启；前端配套发布。R8 如增加注册响应字段，旧客户端兼容读取，新 EXE 重新编译并更新分发哈希，逐台升级试点。
5. 现有 v4.00 四份 SQL 在目标环境是否执行仍须独立前检；“本修复无新表”不代表可以省略现有候选迁移。存量数据治理 SQL 与代码修复分开验收。
6. 实施完成后更新 PROJECT_CORE、受影响架构资料及本专题 requirements/design/tasks/verification，必要时补充 ADR；只记录实际通过的结果。本轮方案不提升已实现版本、不宣称缺陷已修复，也不生成产品发布更新记录。
